Principles of Natural Language Processing

Lessons

Unit I — Text processing and information retrieval

Session 01 What NLP is, and your first tool Why language is hard for computers — and how to pull facts out of text with a pattern. Session 02 Capturing, choosing, and the greedy trap Regular expressions, part two: extracting the individual pieces of a match, handling more than one input format, and understanding greedy matching. Session 03 Tokenization How a computer splits text into words, and why that turns out to be a difficult problem. Session 04 Cleaning up text Normalization and stop words: deciding which differences in text do not matter and removing them. What counts as irrelevant depends on the task. Session 05 Stemming and lemmatization Reducing a word to a root form by two different methods, and deciding which one a given task requires. Session 06 Part-of-speech tagging Labelling each word with its grammatical job — and why the same word needs a different label depending on the words around it. Session 07 Named entity recognition Finding the names in text — people, places, companies — which is harder than tagging words, because a single name can span several of them. Session 08 Searching a collection The term-document incidence matrix and how Boolean queries are answered with it, together with the reason it does not scale to real collections. Session 09 The inverted index Keep only the ones. For each word, a list of the documents it appears in — and a fast way to answer a query by walking two lists at once. Session 10 Ranking results with TF-IDF Not just which documents match, but which match best — and why the score needs a logarithm in two different places.

Unit II — Language models, sentiment, word vectors

Session 11 Language models and n-grams A model that guesses the next word. It is the same idea ChatGPT runs on — and the simplest version of it is just looking at the last word or two. Session 12 N-gram probabilities and the Markov assumption Where the numbers come from. The exact answer is easy to write down and impossible to use — so we deliberately use the wrong one. Session 13 The zero problem and smoothing Counting says an unseen sentence is impossible. It is not. Fixing that means taking probability away from what we saw and giving it to what we did not. Session 14 Judging a language model: perplexity We have built three models and have no way to say which is best. The measure that settles it is a single number, but it means something only when computed on text the model has never seen. Session 15 Bayes' rule and the Naïve Bayes classifier The question we want to ask cannot be counted. So we turn it into two questions that can — and then tell two deliberate lies to make the second one countable too. Session 16 Naïve Bayes for sentiment, worked through Five short reviews, one new sentence, and every number done by hand. The training is nothing but counting — and the first honest attempt fails completely. Session 17 Bag of Words and the vector space model You built this table in session 8 and used it as a lookup. Change the 0s and 1s to counts, read the columns instead of the rows, and it becomes a map with documents as places on it. Session 18 The TF-IDF vector model Last session's table rewarded the wrong words. Today we re-weight it — and the answer we get back is not the one anybody expects. Session 19 Cosine similarity Last session left a number on the board and refused to explain it. Today we derive it — and then use it to get session 17's clustering back. Session 20 Neural networks in one hour Nothing in this session is usable on its own, which is deliberate. It supplies the machinery session 21 requires: five ideas, each selected because Word2Vec uses it. Session 21 Word2Vec: CBOW and Skip-gram Last session ended with a sentence nobody could have read an hour earlier. Today we build the thing it describes — and find out that the prediction task was never the point. Session 22 GloVe One loss function and one co-occurrence matrix. What makes the session worth an hour is the question it raises about Word2Vec, and the answer, which is not the one GloVe's own paper gives.

Unit III — Deep learning and applications

Session 23 The RNN: hidden state, shared weights A feedforward layer needs an input of one fixed size, and sentences are not all one size. An RNN runs the same small network once per word instead, carrying a running summary — the hidden state — forward from one word to the next. Session 24 Training an RNN: backprop through time, and the vanishing gradient Last session ended on a promise the architecture makes and a question nobody answered. This session answers it, and the answer is no — not by default. That "no" is the entire reason the next session exists. Session 25 The LSTM: two vectors, and three gates that manage them Session 24 found two problems. The first one — one vector asked to do two jobs — is what this architecture is built to fix. The gates are how it does the managing, not what the design is about. Session 26 The GRU: two gates, one vector, and what the simplification cost Session 25 ended by asking whether three gates and eight weight matrices were all necessary. The GRU is one answer. This session works out what it removed, what that removal costs in arithmetic, and what the evidence says about whether the trade was worth making. Session 27 Sequence-to-sequence: the encoder-decoder shape Four sessions built a recurrent unit. This one does not touch it. It is the first session in Unit III about what you build out of two of them, and about a task that no amount of improving the unit could have solved. Session 28 The bottleneck, and attention as the fix Session 27 ended on a problem: one fixed-size vector carrying an entire source sentence. The fix is a single change of subscript, and the three operations it needs are all operations this course already taught. Session 29 Self-attention: query, key, value, and the dk Session 28's three operations, pointed at one sequence instead of two. The arithmetic barely changes. What changes is that the recurrence is left with nothing to do — and that a set of vectors compared pairwise has no notion of word order at all. Session 30 Multi-head attention, and positional embeddings Session 29 removed the recurrence and got parallelism. The bill for that was word order, and this session pays it. Then the same mechanism is run several times side by side — which turns out to cost almost nothing, for a reason that is worth doing the arithmetic on. Session 31 The transformer: encoder blocks, decoder blocks, the whole picture Sessions 29 and 30 built the attention layer. This session builds the box that contains it, stacks the box six times, and then asks what separates an encoder from a decoder. The answer is smaller than it sounds: the same three equations, run three times, differing only in what is querying what. Session 32 BERT and masked language modelling Session 31 left a sentence on the table: an encoder sees the whole sequence, so it is for understanding. This session is that model — and the training objective it is forced to use, because seeing ahead makes the old objective trivial. Along the way it pays a debt from sessions 21 and 22: one word, two meanings, two vectors. Session 33 Fine-tuning, DistilBERT and knowledge distillation Session 32 built BERT and stopped at what it is. This session is what it is for: a small head trained on labelled data, the same head pointed at session 7's tagging scheme, and then a smaller copy of the model trained to behave like the large one. Session 34 Machine translation Session 33 closed by saying the architecture of Unit III is finished. This session is the first application of it: everything a working translation system needs that a transformer diagram does not show. Session 35 Question answering and text summarisation Two syllabus clauses in one hour. The first half points Unit I's retriever at the generator Unit III built. The second is a taxonomy, and one architecture the room already has. Session 36 Chatbots, and the course wrap-up A task-oriented chatbot fills a frame. Then the table session 22 left standing, extended to the rest of the course.

Labs

Unit I — Text processing and information retrieval

Lab 01 · Week 1 Refresher and setup Get Colab working, and refresh the Python this course leans on. Lab 02 · Week 2 Information extraction with regular expressions Pull amounts, dates and accounts out of messy bank SMS — and find where regex stops working. Lab 03 · Week 3 Tokenize, normalize, stem, remove stop words The standard preprocessing steps — and when each one quietly destroys your meaning. Lab 04 · Week 4 Incidence matrix and inverted index Build a tiny search engine two ways, and see why the inverted index is the one that scales.

Unit II — Language models, sentiment, word vectors

Lab 05 · Week 5 N-grams and n-gram probabilities Build a language model by counting, watch one unseen pair score a good sentence at zero, then make it write English. Lab 06 · Week 6 Sentiment analysis with Naïve Bayes Sentiment with Naïve Bayes — from the lecture toy to 2,000 reviews, then measure it honestly. Lab 07 · Week 7 Cosine similarity and TF-IDF Cosine and TF-IDF: finish an exercise the textbook skips, find out why scikit-learn disagrees with the lecture, and build a search engine. Lab 08 · Week 8 Word2Vec, GloVe, and the comparison Train Word2Vec, download GloVe, and measure — for real — whether either beats TF-IDF at sentiment.

Unit III — Deep learning and applications

Lab 09 · Week 9 Sequence models: the RNN and the LSTM Build an RNN and an LSTM in PyTorch, and find out whether reading in order beats the bag of words that threw order away. Lab 10 · Week 10 Attention, and a translation system Build a working English-to-French translation system, then plot what it attends to while it translates. Lab 11 · Week 11 Encoder and decoder transformers Write one transformer block from the equations, then use it twice — as a classifier and as a text generator, one mask apart.

Primers

Short practice notebooks on the three libraries the labs use. They teach the tools rather than the syllabus, so nothing here is assessed and no lab depends on them — but a student who has worked through the relevant one arrives at the lab already knowing where everything is. They open in Colab like the labs.

Primer 1 NLTK The parts of NLTK this course uses: corpora, tokenisers, stemmers, lemmatisers, taggers and frequency counts. Primer 2 spaCy One pipeline, one call: tokens, lemmas, tags, entities and the dependency parse, and the attribute names that carry them. Primer 3 NumPy Arrays, axes, broadcasting and the dot product — the operations every document vector, weight matrix and similarity score in this course is made of. Primer 4 NumPy, Hands On A worked pass through the freeCodeCamp NumPy tutorial: what an array is, how it is indexed and sliced, how it is built, and the arithmetic, statistics, reshaping and masking that come with it.

Classroom demos

The scripts run live in class. Each one prints its way through a single idea, using the same examples as the lesson it belongs to, so what you run matches what you read. They are for following along and experimenting — they are not assessed, and nothing in the labs depends on them.

These run on your own machine rather than in Colab. You need uv. Clone the repository, then once, inside classroom/, run uv sync and uv run bootstrap.py — the second one downloads the spaCy model and the NLTK corpora that pip does not install. The README there has the detail.
