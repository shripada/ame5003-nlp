Multi-head attention, and positional embeddings

Session 29 removed the recurrence and got parallelism. The bill for that was word order, and this session pays it. Then the same mechanism is run several times side by side — which turns out to cost almost nothing.

Self-attention computes each output as a weighted sum over pairs of positions, and nothing in that computation refers to where anything sits. It treats its input as a set.

The recurrence used to handle order for free — an RNN reads the words one after another, so it cannot fail to represent their order. Session 29 threw it away to get parallelism.

Not similar — identical, to every digit. Causal mask dropped so every position may see every other.

A score is qi⋅kj, which depends on the two tokens and nothing else, and a softmax over a set of scores does not care what order they arrived in.

Shuffle the inputs and the same pairs give the same scores, and therefore the same outputs. A model built only of self-attention cannot tell the witch arrived from arrived the witch — so it cannot be the whole model.

A fair objection: ∀j≤i means position 5 can see position 2 and not the reverse, so the model does know something about order.

But the mask knows precedence, not distance. It does not say that j is three words before i rather than thirty. Precedence alone will not distinguish the dog bit the man from the man bit the dog.

SLP3 §8.4 asks where X comes from

"The transformer does this by separately computing two embeddings: an input token embedding, and an input positional embedding."

The token embedding is session 21's — a row of E, shape [|V|×d]. The positional embedding is new.

"Just as we have an embedding for the word fish, we'll have an embedding for the position 3. As with word embeddings, these positional embeddings are learned along with other parameters during training."

A vector for "position 1", one for "position 2", up to the context length N, stored in Epos of shape [N×d]. Nothing tells the model what position 3 means; it works out for itself what is worth storing there.

The two embeddings are added, not concatenated

xi=E[id(i)]+Epos[i]

Position is summed into the same d numbers

  • No dimensions are spent on position. The vector entering the first layer is d wide, exactly as it would be without positions, so every shape downstream is unchanged. Concatenation would have widened X and every matrix that touches it
  • Word and position share the space. That looks destructive — and the answer is that the model is trained with the sum, so it learns representations that survive it. The two embedding matrices are learned together

Before the first attention layer, and once.

Add position later and it is too late: the first layer's attention scores have already been computed from vectors that had no idea where they were.

"There will be plenty of training examples for the initial positions in our inputs and correspondingly fewer at the outer length limits. These latter embeddings may be poorly trained and may not generalize well during testing."

A counting argument. Every sentence has a position 1, so that embedding gets a gradient from every example. Very few sentences are 4,000 tokens long, so position 4,000 stays close to its random initialisation — and no amount of training harder fixes it, because the data is not there.

Compute the positional vectors instead, from a fixed function of the position number — sines and cosines at different frequencies.

A static function has no undertrained region: position 4,000 gets the same quality of vector as position 1, whether or not any training sentence was ever that long. That is the whole argument, and the formula is not on the syllabus.

Relative position methods represent the distance between two positions rather than the absolute index of each.

They are usually implemented inside the attention computation at every layer, instead of being added once at the input. Mentioned here so the name is not new later.

Exercise

The two orderings produce the same outputs

What has to be added to break the tie? And — the part that matters — where in the pipeline does it have to be added, and why would adding it later fail?

What. A vector that depends on the position rather than the token — a row of Epos, added to each token's embedding. After the addition, the vector at position 1 is no longer the same object as the same word at position 3, so the two orderings no longer present the same set of vectors.

Where. At the input, before the first attention layer. The weights are computed from the vectors as they arrive: if xi carries no position when the first layer runs, that layer's whole N×N matrix is already position-free, and its outputs are already a permuted copy of what they would have been. Adding position afterwards labels the result but does not change it.

A useful way to say it: position must be in the vectors that get compared, because the only thing the mechanism ever looks at is dot products between vectors.

Question 1 of 2

Why do transformers need positional embeddings at all?

Correct: self-attention is permutation-invariant — it sees a set of vectors, and a set has no order, which is what the table of identical outputs shows.

The second describes a real problem that really does need solving, which is what makes it tempting: different lengths are handled by padding and masking, a separate mechanism. A model could pad perfectly and still not know which word came first. The fourth has it backwards — Epos adds parameters, fixed by the context length.

Second topic, independent of the first

"Each head might be attending to the context for different purposes: heads might be specialized to represent different linguistic relationships between context elements and the current token, or to look for particular kinds of patterns in the context."

Resolving what it refers to needs one kind of comparison. Deciding which verb a noun is the subject of needs another. Noticing a word is inside a quotation needs a third.

A single scoring function qi⋅kj has to serve all of them at once, so it must compromise — one similarity measure, averaging several purposes together.

Single-head applied WO to one head's output. Multi-head first concatenates the A outputs and then applies WO to the concatenation.

Each head's output is [1×dv], the concatenation is [1×A⋅dv], and WO is [A⋅dv×d] — back to [1×d] so the layer can be stacked.

It is the only part of the layer where the heads meet. Inside a head, nothing knows the other heads exist.

WO is the learned recipe for mixing their answers back into one vector. This is why session 29 said it would start to earn its place here.

The original transformer: d=512, dk=dv=64, A=8

A×dk=8×64=512=d

Exactly the same, not approximately, because 8×64=512. Heads are close to free: they divide the width rather than adding to it.

Eight heads are not eight copies — they are one layer's width cut into strips

Multi-head attention is not "more attention". It is the same parameter budget spent on eight narrow comparisons instead of one wide one.

The argument for spending it that way: eight 64-dimensional similarity functions can each specialise, where one 512-dimensional function has to average its purposes together.

Nothing in the equations tells head 3 to learn coreference. The heads differ only because they start from different random initialisations and are free to diverge.

What they end up doing is an empirical question — in practice some heads do learn recognisable jobs and others are close to redundant.
Question 2 of 2

In the original transformer, do 8 attention heads cost roughly 8 times the parameters of 1 head?

Correct: they partition the width. Each head's WQ is [512×64] rather than [512×512]; eight of those come to 786,432, exactly what one full-width head's three matrices cost. With WO the layer is 1,048,576 — four thirds of single-head, not eight times.

The first is the natural guess and gets the premise right: each head really does have its own three matrices. What it misses is that those matrices are narrower. The fourth is wrong about the mechanism — the heads are independent and computed in parallel, which is much of why the design is attractive on modern hardware.

That completes the attention layer of a transformer: X built from token and positional embeddings, and multi-head scaled dot-product self-attention computed over it.

What is missing is everything around it. §8.2: the transformer block is the attention layer plus "(1) a feedforward layer, (2) residual connections, and (3) normalizing layers". The first is already in hand — session 20's feedforward network, unchanged.

Summary

Self-attention is permutation-invariant, verified to every digit, so order is supplied separately: a token embedding and a positional embedding, added not concatenated, at the input and only there. Learned positions are undertrained at the far end, which is the one reason to prefer sinusoids.

Multi-head runs A heads and concatenates before one WO. Because A×dk=d, eight heads cost the same 786,432 projection parameters as one full-width head — the same budget spent on several narrow specialised comparisons.
