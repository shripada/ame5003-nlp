The transformer: encoder blocks, decoder blocks, the whole picture

Sessions 29 and 30 built the attention layer. This session builds the box that contains it, stacks the box six times, and asks what separates an encoder from a decoder. The answer is smaller than it sounds.

Two sessions have gone into one layer

  • Multi-head scaled dot-product self-attention. Three projections, scores over dk, softmax, weighted sum of values, A heads mixed by WO
  • Positional embeddings. X built by adding a learned positional vector to each token's embedding, before the first layer

§8.2 is precise about what is missing, and it is exactly three items: "(1) a feedforward layer, (2) residual connections, and (3) normalizing layers". Only one of them is genuinely unfamiliar. From here on this session is assembly.

Session 20's two-layer network, unchanged

FFN(xi)=ReLU(xiW1+b1)W2+b2(8.21)

Two things about how it is used

  • Applied to each position independently — the same W1 and W2 at every token, and no position's computation looks at any other's. Whatever mixing between tokens happens, it happens in the attention layer and nowhere else
  • The hidden layer is wider than the model: d=512 and dff=2048 in the original transformer

That factor of four accounts for where the parameters sit, which the session returns to later.

Layer normalisation, in SLP3's words

"A variation of the z-score from statistics, applied to a single vector in a hidden layer."

Not applied to a layer, despite being called layer norm — applied to one token's vector at one position. A d-vector in, a d-vector out.

Over the d components of the vector

μ=1d∑ixi(8.22)
σ=1d∑i(xi−μ)2(8.23)

Mean zero, standard deviation one — then a learned gain and offset

xˆ=(x−μ)/σ(8.24)
LayerNorm(x)=γ(x−μ)/σ+β(8.25)

The purpose is training stability rather than expressiveness: it keeps the values flowing through a deep stack inside a range where gradient-based training works.

Which matters when the stack is six or twelve or ninety-six blocks deep and each block's output is the next one's input. A drift that is harmless at block 2 is not harmless by block 40.

Session 28 objected that a dot product favours long vectors. Session 29 answered half: dk divides by the expected scale. It explicitly did not answer one key actually being longer than another.

Layer norm is the other half. Every vector entering an attention sublayer has been rescaled to mean zero and standard deviation one first, so the vectors being dotted arrive at comparable lengths. Not cosine similarity, and it does not claim to be — but the failure mode session 28 named is what this controls.

One line of arithmetic: instead of a component's output replacing its input, the output is added back to it.

A plain stack computes x→f(x)→g(f(x)). A residual stack computes x→x+f(x)→x+f(x)+g(…).

Think of one d-dimensional residual stream running vertically through the whole model at each token position. It starts as that token's input embedding.

Every component reads from the stream, computes something, and adds its result back in. Nothing ever overwrites the stream.

Why gradients survive a deep stack: the stream is an uninterrupted addition path from the output back to the input embedding, with no chain of matrix multiplications on it — session 24's problem answered by construction rather than mitigation.

And which component does what: "the only component that takes as input information from other tokens is multi-head attention". Attention is the token-mixing component; the feedforward layer works within a single stream.

The residual-stream framing is a modern reframing. Alammar's Illustrated Transformer — the assigned second read — draws the older picture, with "Add & Norm" boxes between sublayers.

They are the same equations. If the two readings look different, that is a difference of drawing, not of model.

Normalise, attend, add back; normalise, transform, add back

A transformer block is not six unrelated steps. It is the same three-step figure performed twice, once with attention in the middle and once with the feedforward network.

In (8.27) attention takes ti1 and t11…tN1 — query from position i, keys and values from all positions. That is the only line where other tokens appear.

And (8.28) adds back xi, the block's input, while (8.31) adds back ti3. Each residual reaches back to just before its own sublayer, not to the start. Input and output are both [1×d], which is what makes stacking possible.

(8.26) puts LayerNorm on the input of each sublayer. Vaswani §3.1 puts it on the output: LayerNorm(x+Sublayer(x)).

Not a notational variant — the two train differently, and post-norm typically needs a learning-rate warmup that pre-norm does not. We teach pre-norm, because that is the reading. A diagram drawn from the 2017 paper will show "Add & Norm" after the box.

One block is not a transformer. The original stacks N=6 in the encoder and six in the decoder; language models run from 12 layers to 96 and beyond.

Identical in architecture, not in parameters — every block has its own weights. And one small asymmetry: after the last block there is one further layer norm, run on each token's final hi.

The component the architecture is named for — the one every diagram is drawn around — is the minority of the parameters, by a factor of two.

Because dff=4d: each feedforward matrix is four times the size of one of attention's full-width projections, and there is no equivalent widening in attention. Layer norm is free — 2,048 against three million. And when sessions 32 and 33 quote a parameter count, most of it is feedforward weight.
Question 1 of 2

In a standard transformer block, which part holds most of the parameters?

Correct: the feedforward layer — 2,097,152 against attention's 1,048,576, outnumbered two to one.

The first is the answer nearly everyone gives, and it is not unreasonable: attention really does have more matrices. What it misses is that the heads partition the width. The third is off by three orders of magnitude. The fourth confuses parameters with activations — the N×N matrix is computed at run time and is not stored weight.

Sessions 29 and 30 both deferred the mask. Computing QK𝖳 produces a score for every query against every key — including keys at positions after the query.

For a model trained to predict the next token that is fatal, and SLP3 puts it bluntly: "guessing the next word is pretty simple if you already know it".

Remove the future by adding a mask matrix

Mij=−∞∀j>iMij=0otherwise

Adding −∞ and then taking a softmax gives exactly zero weight. Nothing is deleted from the input and no separate machinery is needed — one addition between the scores and the softmax.

Which is why session 29's softmax(mask(QK𝖳/dk))V could carry it as a single function name. Note what it does not cost: the masked scores are still computed and thrown away. Masking buys correctness, not speed.

An encoder is not predicting the next token. It represents an input that is already, entirely, present — so there is no future to hide.

"The multi-head attention in the encoder, however, is allowed to look ahead at the entire source language text, so it is not masked."

Encoder-only models are for understanding; decoder-only models are for generation.

An encoder can use the right-hand context of a word to represent it, which is what you want when deciding what the word means. A decoder must not, because at generation time the right-hand context does not exist yet.

The only genuinely new mechanism in this session

"Cross-attention has the same form as the multi-head attention in a normal transformer block, except that while the queries as usual come from the previous layer of the decoder, the keys and values come from the output of the encoder."

Decoder supplies Q; the encoder's output supplies K and V

What changed is not the mechanism but its inputs.

A decoder state querying a set of encoder states, producing weights over source positions, returning a weighted sum — that is exactly session 28's Bahdanau attention.

The transformer did not invent decoder-attends-to-encoder. It replaced Bahdanau's small feedforward scoring network with a scaled dot product, ran it in several heads, and put it inside a block. Sessions 27, 28 and 31 describe the same idea at three levels of machinery.

Question 2 of 2

What distinguishes a decoder block from an encoder block?

Correct: the mask, plus cross-attention — the only two differences. Everything else is identical, which is why SLP3 can describe the encoder as "the same as the basic transformers from Chapter 8" and the decoder as that "augmented with a special new layer".

The second is simply not so: A=8 on both sides. The third inverts the design. The fourth mixes up two unrelated things — pre-norm versus post-norm is a whole-model choice, and what lets a decoder generate one token at a time is the causal mask.

Exercise

The six equations of a block, shuffled

(a) ti5=FFN(ti4) · (b) ti3=ti2+xi · (c) ti1=LayerNorm(xi) · (d) hi=ti5+ti3 · (e) ti4=LayerNorm(ti3) · (f) ti2=MultiHeadAttention(ti1,t11…tN1)

Put them in order. Then — the part that matters — say which lines would change under the original paper's post-norm style, and how.

The order is c, f, b, e, a, d — (8.26) through (8.31). You do not have to remember it: each line's right-hand side names the variable the previous line produced, so it reconstructs from the dependencies alone.

The pattern is what the ordering is really testing: normalise, attend, add back; normalise, transform, add back. Note also that (b) adds back xi and (d) adds back ti3 — each residual reaches to the start of its own sublayer.

Under post-norm the normalisation moves to the end of each movement, so the pairs collapse. The attention half becomes one line, ti3=LayerNorm(MultiHeadAttention(xi,x1…xN)+xi), replacing (c), (f) and (b); the feedforward half becomes hi=LayerNorm(FFN(ti3)+ti3). Attention now consumes the raw xi, and the residual addition happens inside the normalisation.

That second change is the substantive one. Under post-norm the residual stream is normalised at every block, so it is no longer a clean addition path from output back to input — the usual explanation for why post-norm needs a warmup and pre-norm does not.

That is an entire transformer: input from token and positional embeddings, blocks of attention and feedforward wired with residuals and layer norms, six stacked, and two kinds of block depending on whether the future may be seen.

What each kind is used for follows directly from the mask.

Three models, one architecture

  • Encoder alone, no mask anywhere — reads a whole input at once and represents it. Good for understanding, useless for generating, since it was never trained to guess what comes next. That is BERT, session 32
  • Decoder alone — a language model
  • Both, wired by cross-attention — the machine translation architecture of session 34

Summary

A block is attention plus a feedforward layer four times the model width, layer normalisation, and residual connections into a stream that is never overwritten — equations (8.26)–(8.31): normalise, attend, add back; normalise, transform, add back. SLP3 uses pre-norm, Vaswani post-norm.

Two thirds of a block's parameters are feedforward. Encoder and decoder blocks differ in exactly two ways: the decoder's self-attention is masked, and it carries cross-attention. The same three equations, three times over, differing only in what queries what.
