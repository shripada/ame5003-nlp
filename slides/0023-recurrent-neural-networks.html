The RNN: hidden state, shared weights

A feedforward layer needs an input of one fixed size, and sentences are not all one size. An RNN runs the same small network once per word instead, carrying a running summary — the hidden state — forward from one word to the next.

Session 20, restated and not re-derived

y=f(∑iwixi+b)

Stack several neurons and it is a matrix multiply, z=Wx, one row of W per neuron.

The weights are not counted the way session 16's were. They start arbitrary and get fitted, nudged by gradient descent until the whole thing predicts well. That is everything this session needs.

A feedforward layer needs a fixed-size input

  • W has a fixed number of columns, and that cannot change from one input to the next
  • CBOW (session 21) averaged the context words down to one vector, whatever the window size
  • Lab 8 did the same to build a document vector from GloVe and Word2Vec — average every word, get one fixed vector back

Both dodge the wall the same way, and lab 8 measured the price: TF-IDF outperformed both averaged-embedding representations.

Two distinct problems

Fixed size. A network built for a 10-word input cannot take a 50-word input without redesign.

Order-blindness. Averaging is commutative — avg(a,b,c)=avg(c,b,a), exactly, not approximately. Whatever order the words carried is gone before the network sees the vector.

The same GloVe vectors lab 8 used

cos⁡(avg(GloVe[dog],GloVe[bites],GloVe[man]), avg(GloVe[man],GloVe[bites],GloVe[dog]))=0.9999999999999998

Floating-point addition is not perfectly order-invariant, so a+b+c and c+b+a can differ in the last bit. The rounding noise in the seventeenth digit is not evidence that order mattered even a little.

The same test on "the movie was good, not bad" against "the movie was bad, not good" gives 0.9999999999999999. Averaging does not do a poor job of keeping order — it cannot keep order, by construction.

Feed the network one word at a time, and give it a hidden state — a vector it carries from step to step — so word 50 is processed with a summary of words 1–49 already folded in.

Nothing about the network's size depends on sentence length, because at every step it looks at one word plus one hidden state.

Fixed size stops being a constraint: the input at every step is always one word vector plus one hidden-state vector, three words or three hundred.

Order-blindness stops being automatic: ht is built from ht−1, which was built from the one before — a specific, order-dependent chain, not a symmetric sum.

Three matrices, same idea as session 20

ht=g(Uht−1+Wxt)the hidden state, updatedyt=f(Vht)an output, if this step produces one

xt is the current word's vector; ht−1 is everything carried forward so far. W reads the new word, U reads the running memory, V turns memory into output.

g is conventionally tanh⁡ rather than session 20's sigmoid — it squashes into [−1,1], and the zero-centred range keeps a value fed back into itself over and over from drifting all one direction.

If the hidden state is 300-dimensional and each word vector is 100-dimensional: U is 300×300, W is 300×100, and V is whatever the output needs — one row per class, for example.

The same three matrices at every step

Not three hundred sets of weights for a three-hundred-word document and three for a three-word sentence — one set, applied again and again.

A thousand-word document and a three-word sentence use the identical parameter count. This is what session 20's feedforward layer could not do.

The same network, drawn once per timestep

h0 is the starting hidden state, usually all zeros. Every U arrow is the identical matrix, every W arrow the identical matrix, every V arrow the identical matrix.

The figure draws an output at every step, which is the sequence-labelling shape. The classification setup later keeps only the last step and drops y1 and y2 entirely.
Question 1 of 2

What makes an RNN handle a 3-word sentence and a 300-word document with the same network, without redesigning anything?

Correct: the same three matrices are reused at every step.

Nothing about U, W or V's shape mentions sequence length — they map "one word plus one hidden state" to "one new hidden state", applied once per word. A three-word sentence runs the loop three times; a three-hundred-word document runs it three hundred times; the network is identical both times.

One-dimensional hidden state, no activation, checkable by hand

U=0.5W=1h0=0x1=2x2=3

Two steps of the recurrence

h1=Uh0+Wx1=0.5⋅0+1⋅2=2h2=Uh1+Wx2=0.5⋅2+1⋅3=4

Real RNNs squash every step with tanh; it is omitted here so the arithmetic can be checked by hand. The structure matters more than the values.

h2's formula contains h1, which contained h0. Nothing prevents h100 from depending on h0 through an unbroken chain. Whether it does in practice is session 24's question.

Exercise

Same toy RNN

h0=0, U=0.5, W=1, h1=2, next input x2=3. Compute h2. Then: does h2's formula mention h0 anywhere?

h2=Uh1+Wx2=0.5⋅2+1⋅3=4.

No — it mentions only h1 and x2. h0 enters only through h1, one step removed.

Every hidden state reaches back one step at a time, chained — exactly the shape of thing that can either carry information a long way or lose it a long way. Which one happens is session 24's question.

The same architecture, two output shapes

  • Sequence labelling — an output at every step: a tag for every word, the way session 6's POS tagging assigns one label per token
  • Sequence classification — one output at the very end, the direct continuation of lab 8. This is our running example

Take the final hidden state, feed a separate classifier

yˆ=softmax(Wchn)

In a classifier there are no per-step outputs at all — no y1, no y2, nothing until the last word is read. So V, the figure's hidden→output matrix, is simply not used here.

The classification head is an extra, separately-sized matrix bolted onto the end, with one row per class — two, for positive/negative — not one row per whatever the RNN's per-step output was.

The loss comes from the classification decision alone, at the very last step, and backpropagates through the classifier's weights, into hn, and from there back through every U and W to the first word.

Nothing is trained to produce a good intermediate representation directly. A good representation is whatever falls out of training the final decision to be correct.

An alternative: pooling

Average all the hidden states instead of keeping only the last. At first glance this looks like reintroducing the problem we just measured.

Lab 8 averaged raw word vectors — context-free, order-blind by construction. Pooling averages hidden states, and every hi already encodes everything before position i.

The order information was built into each vector before the average, not thrown away by it. Averaging is not the problem; averaging context-free vectors was.

Both orderings through a randomly initialised RNN

h(dog bites man)≠h(man bites dog)componentwise, exactlycos⁡(h(dog bites man),h(man bites dog))=0.138

An untrained RNN has never been taught to do anything useful with the order it sees. 0.138 is not a meaningful similarity score.

The claim is narrower and does not depend on training: the architecture is capable of seeing order; averaging raw vectors is not. Compare the two cosines — 0.9999999999999998 for averaging, 0.138 for the untrained RNN.
Question 2 of 2

Why can lab 8's averaged embeddings not distinguish dog bites man from man bites dog, while even an untrained RNN's final hidden state can?

Correct: averaging cannot see order because addition is commutative; the RNN's recurrence is not.

Training does not enter into it. An untrained RNN's weights are arbitrary, but the function ht=g(Uht−1+Wxt) still depends on which word arrived at which step, because ht−1 feeds into ht and not the reverse. Averaging has no such asymmetry, trained or not.

SLP3 says the recurrent connection can let a decision "depend on information from hundreds of words in the past". It is worth being precise about what that establishes.

We have shown that the architecture allows it: the worked example makes the chain visible link by link, and nothing in the formula breaks it. Whether the dependence survives training is a separate question, and session 24 takes it up.

Summary

Every trick this course used to get a fixed-size input cannot see word order, because addition is commutative. An RNN reads one word at a time, carrying ht=g(Uht−1+Wxt) forward, with the same three matrices for a three-word sentence and a three-hundred-word document.

For classification the final hidden state feeds a softmax, trained end-to-end. What this session did not show is whether "everything before it" really reaches back hundreds of words — only that the architecture does not forbid it.
