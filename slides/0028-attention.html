The bottleneck, and attention as the fix

Session 27 ended on a problem: one fixed-size vector carrying an entire source sentence. The fix is a single change of subscript, and the three operations it needs are all operations this course already taught.

SLP3 §13.8 opens on exactly where we stopped

"This final hidden state is thus acting as a bottleneck: it must represent absolutely everything about the meaning of the source text, since the only thing the decoder knows about the source text is what's in this context vector."

Bahdanau puts it as relieving the encoder "from the burden of having to encode all information in the source sentence into a fixed-length vector".

Note what both sentences locate the fault in. Not that c is a bad summary — that the decoder has no other route to the source. The encoder computed a hidden state for every word, and the architecture threw all of them away except the last. The fix is, more or less literally, stop doing that.

c became ci. That is the entire architectural change — a different context vector at every decoder step, computed fresh each time.

Same encoder, same decoder, same unit inside both boxes, same cross-entropy loss, same teacher forcing, same end-of-sequence token.

Everything from session 27 carries over. The only new content is how ci is computed.

Session 27's c was hne, fixed before the decoder started. A c that carries an i can depend on the decoder's current state — so it can be about the word being produced right now.

The decoder about to emit the verb can be given a context assembled around the verb. That capability is not available at any price when the context is computed once.

Score every source position for relevance to where I am now, turn the scores into a distribution, take the weighted average of the source representations under it.

There is no new mathematics here, only a new arrangement of arithmetic the course has had for weeks. SLP3 calls (13.35) dot-product attention, and describes it as treating "relevance as similarity" — session 19's sentence almost word for word.

Session 19 established that a raw dot product favours long vectors, which is why cosine divides by both lengths. Equation (13.35) divides by nothing — an encoder state with a large norm scores highly against everything.

That is a real weakness, not an oversight. It is fixed in session 29, where the same dot product is divided by dk before the softmax.

The assigned paper computes the score with a small feedforward network: a(si−1,hj)=va𝖳tanh⁡(Wasi−1+Uahj).

So the formula in the reading is not the one used above. The role is identical — decoder state and encoder state in, one number out — and the three-step structure is unchanged. What differs is whether the score has learned parameters.

Nobody told the model that Spanish position 1 corresponds to English position 4. Session 27's alignment fell out of a dot product and a softmax.

c1 is not he(arrived); it is near it, pulled slightly by the at weight 0.119. No mechanism here selects a source word.

This is why it is called soft attention, and it is what makes it differentiable — a mechanism that picked a word could not be trained by gradient descent, because there is no derivative of a choice.

Suppose the weights were uniform, 0.25 each

c=0.25⋅([2,1]+[1,2]+[−1,2]+[2,−1])=[1.000,1.000]

Nothing like [2,−1]. It does not point at any source word in particular, which is precisely what an average is for — and it is exactly session 23's pooling.

Attention is not "look at all the states": session 27 could have averaged the states. It is "look at all the states in proportions that depend on where you are".

Question 1 of 2

What is the difference between the plain encoder-decoder of session 27 and the attention-based one?

Correct: the context is recomputed per step from all the encoder states — the move from c in (13.32) to ci in (13.34).

The first needs care, because it is true of Bahdanau's paper and of lab 10's code — but it is not the mechanism. Attention works fine over a unidirectional encoder, and 13.35–13.37 never mention direction. The fourth is session 27: that is what (13.32) already did.

The right-hand column is the left-hand column of session 27's table — the numbers that entered the encoder in the first place. The 50 : 1 compression is gone, because there is no longer a stage that performs it.

ci is still a single fixed-size vector — still 300 numbers, still consumed one at a time. Nothing about the decoder's input width changed.

What changed is where those 300 numbers come from: computed afresh at each step from all of h1:ne, so every source position stays reachable for the entire decode. The bottleneck was never the size of c; it was that one c had to serve every target word.

Dot-product attention has no parameters at all — a fixed arithmetic operation with nothing for training to adjust.

That is economical, and also a limitation: the model cannot learn what kind of similarity should count as relevance. It gets whatever similarity the representations happen to express.

SLP3's second scoring function

score(hi−1d,hje)=hi−1dWshje(13.38)

Ws is trained end-to-end and "gives the network the ability to learn which aspects of similarity between the decoder and encoder states are important". Steps two and three are unchanged.

There is also a practical reason implementations use it: a plain dot product needs hd and he to have the same dimensionality. Ws is rectangular, so encoder and decoder may be sized independently.

Question 2 of 2

What are the attention weights αij?

Correct: they are computed, by a softmax over the scores, forming a distribution over source positions — the four in the worked example summed to 1.0000.

The first is the commonest misunderstanding and the one to rule out hardest. Nothing about the α is stored: they are recomputed from scratch at every decoder step of every sentence, and they must be, since learned per-position weights could not handle an unseen length. Ws is learned, but the α are the softmax of the score's output, not the score's parameters.

Attention as taught here is a decoder attending to an encoder: two sequences, one asking and one answering.

The modification is to point the same three operations at one sequence attending to itself, so each position gathers from every other position in the same sentence. That is self-attention.

Sessions 25 and 26 both closed on a limitation neither the LSTM nor the GRU could fix: a sequence must be processed one step at a time, so it cannot be parallelised, and distant positions are still distant.

Session 29 removes both, using the machinery this session introduced.

Summary

Attention changes one subscript, and the context is recomputed at every decoder step by three previously taught operations: score, softmax, weighted average. The worked example put weight 0.876 on arrived, recovering session 27's alignment by arithmetic rather than stipulation — and uniform weights collapse the whole thing into session 23's pooling.

The weights are computed, never stored. All n encoder states stay reachable for the whole decode, though ci is itself still one fixed-size vector. The dot product is unnormalised, which session 29 fixes.
