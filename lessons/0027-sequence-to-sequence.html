Sequence-to-sequence: the encoder-decoder shape

Four sessions built a recurrent unit. This one does not touch it. It is the first session in Unit III about what you build out of two of them, and about a task that no amount of improving the unit could have solved.

What changes, and what does not

Sessions 23 to 26 built a unit: the recurrence, then the LSTM, then the GRU. This session does not touch it. SLP3 writes g throughout §13.7 as "a stand-in for some flavor of RNN", and that is the right posture — the unit is a black box from here on, and what changes is what gets built out of two of them.

This is the first session in Unit III that is about an architecture rather than about a cell. If you are still tracking gate equations, put them down; nothing below depends on which of the three units is inside the box.

A task the previous shape cannot do

Everything in Unit III so far has been sequence labelling — one output per input, as in session 6's POS tagger — or sequence classification, one output at the end. SLP3 draws the contrast directly: in sequence labelling "we have two sequences, but they are the same length… each input is associated with a specific output."

Translation is not that shape. Here is SLP3's own pair:

source (English) :  the    green   witch   arrived
target (Spanish) :  llegó  la      bruja   verde
glossed          :  arrived the    witch   green

Read the alignment off the gloss. The first Spanish word comes from the fourth English word, the second from the first, the third from the third, the fourth from the second: 4, 1, 3, 2. It is not monotonic, so no scheme that emits one output per input as it goes can produce it. And this example is unusually kind — in general the two sentences need not even be the same length, so there is no one-to-one correspondence to align in the first place.

Exercise

Session 6's POS tagger reads a sentence and emits one tag per word. Suppose you point it at this problem and ask it to emit one Spanish word per English word instead. Give two separate reasons it cannot produce llegó la bruja verde.

One: the alignment is 4, 1, 3, 2. At the first position the model would have to emit llegó, which comes from arrived — a word it has not read yet. A one-output-per-input model commits to an output before the evidence for it has arrived.

Two: the lengths are equal here by luck. the green witch arrived has four words and so does the Spanish, but "I don't know" is three words and "no sé" is two. A one-tag-per-token model emits exactly as many outputs as it read, so it cannot produce a shorter or longer sentence at all.

The second reason is the more fundamental one. The first could in principle be patched by reading the whole sentence first; the second cannot be patched, because it is a property of the shape.

The three components

SLP3 gives the architecture as three parts:

  1. An encoder that accepts the input sequence x_{1:n} and produces contextualised representations h_{1:n}.
  2. A context vector c, a function of h_{1:n}, which "conveys the essence of the input to the decoder."
  3. A decoder that accepts c and generates an arbitrary-length sequence of hidden states, and from them the outputs.

The phrase to hold on to in component 3 is arbitrary-length. That is the direct answer to the second reason above: the decoder stops when it decides to stop, not when the input runs out.

This is a shape, not a model

SLP3 is explicit that "LSTMs, convolutional networks, and transformers can all be employed as encoders," and the same for decoders. Nothing above says what is inside the boxes. That is why this session survives session 31: when the transformer arrives it goes into this shape rather than replacing it, and session 34's machine translation reuses the same three components with a different unit inside them.

The one slight change

Here is the part worth slowing down for. SLP3 does not build this architecture from scratch. It builds it out of the language model this course has had since session 11, and describes the modification as slight:

SLP3 §13.7

"We only have to make one slight change to turn this language model with autoregressive generation into an encoder-decoder model… add a sentence separation marker at the end of the source text, and then simply concatenate the target text."

So the training example is one string:

the green witch arrived <s> llegó la bruja verde
└────────── source ─────────┘   └────── target ──────┘

Train an ordinary RNN language model on that. Everything before <s> is read; everything after it is generated. That is the whole idea. A model that predicts the next word, given a string that happens to contain a separator, is a translation model — because predicting the words after the separator, given the words before it, is translating.

And the object being maximised is not new either. SLP3 starts §13.7 from the chain rule, its equation (13.28):

p(y)=p(y1)p(y2|y1)p(y3|y1,y2)⋯p(ym|y1,…,ym−1)(13.28)

That is session 12's equation, unchanged. The n-gram models of Unit II factored a sentence's probability exactly this way, and made a Markov assumption to make the conditionals tractable. Here the conditioning context is a hidden state instead, so no truncation is needed — but the factorisation is the one the course has been using for fifteen sessions.

The equations

The recurrent language model, per step, is SLP3's (13.29) and (13.30):

ht=g(ht−1,xt)(13.29)
yˆt=softmax(ht)(13.30)

Remember that g is a stand-in for whichever unit you chose. Now the two halves. The encoder runs over the source and the context vector is its final hidden state:

c=hne

The decoder is initialised from it, h0d=c, and then runs:

htd=g(yˆt−1,ht−1d,c)(13.32)

Look at what is in that equation. The decoder's state at step t depends on the word it just produced, its own previous state, and c again. The context vector is not only used to start the decoder — it is supplied at every single decoding step.

Why c appears twice

The obvious design would use c once, to initialise h0d, and let the recurrence carry it from there. SLP3 does not do that, and says why: passing c to every step ensures "that the influence of the context vector, c, doesn't wane as the output sequence is generated." Left to the recurrence alone, the source would fade as the translation got longer — which is sessions 24 and 25's problem, appearing for a third time in a new place.

Question 1 of 2

What is the context vector c in this architecture?

Correct answer: the encoder's final hidden state, a single fixed-size vector. Earlier source words reach the decoder only through what survived the encoder's chain into that last state.

The first option is a productive error and worth remembering, because it is nearly what session 28 will do — a weighted combination of all the encoder states rather than the last one. It is simply not what this architecture does. The fourth is closer still to where the course is going and equally not this: keeping all n states is exactly what the fixed-size c refuses to do, and the refusal is the point. The second describes nothing in the model; no word is selected.

Training, and the gap inside it

Training is end-to-end on paired strings, and the loss is the average cross-entropy per target word — session 20's loss, unchanged. There is nothing new to learn about the optimisation.

There is something new about the procedure, and it is a genuine oddity. Consider what the decoder takes as input at step t. Equation (13.32) says ŷ_{t-1}: the word it produced at the previous step. That is what happens at inference, and SLP3 notes the consequence — "the decoder will tend to deviate more and more from the gold target sentence as it keeps generating more tokens." One wrong word early, and everything after it is conditioned on a mistake.

Training does not do that. Training uses teacher forcing: at each step the model is fed the gold target word as its input, not its own possibly-wrong output.

input to decoder step tconsequence
trainingthe gold word y_{t-1} every step is conditioned on a correct prefix
inferencethe model's own ŷ_{t-1} errors compound as generation continues

Which leaves an honest gap: the model is trained in a condition it never encounters when used. It has only ever seen correct prefixes, and at inference it will routinely be standing on its own errors.

Scheduled sampling

One response is to narrow the gap during training: feed the gold word most of the time, and the model's own output some of the time, so it gets practice at recovering. That is scheduled sampling. You will meet it in lab 10, where the decoder takes a sample_probability argument controlling exactly this mixture.

Question 2 of 2

What is teacher forcing?

Correct answer: the gold word is used as the decoder's input during training. It keeps every training step conditioned on a correct prefix instead of on the model's own mistakes.

The second is the one to rule out firmly. At inference there is no gold target — that is the thing being produced. If you had it, you would not need the model. The third describes a bidirectional encoder, a real technique and not this one. The fourth describes nothing used here; the loss is a plain average over target words.

What has to fit through c

The architecture works, and it has one property worth measuring rather than describing. c=hne is a vector of fixed size. Choose d=300 — the dimensionality session 21 used — and it is 300 numbers. It is 300 numbers for a four-word sentence and 300 numbers for a fifty-word one, because the size is a property of the model and not of the input.

source lengthnumbers entering the encodersize of c compression
4 words1,2003004 : 1
10 words3,00030010 : 1
25 words7,50030025 : 1
50 words15,00030050 : 1

A fifty-word sentence is compressed more than twelve times harder than a four-word one, and nothing in the architecture notices that this is happening. There is no mechanism that allocates more room to a longer sentence, or that reports having run out. The decoder receives 300 numbers either way and generates from them.

Where this leaves the architecture

Every word of the source must reach every word of the target through one fixed-size vector. Whatever did not survive the encoder's chain into h^e_n is not available to the decoder at all — not attenuated, not harder to reach, simply absent. The longer the source, the more that is.

That is where this session stops. The problem is real, it is a consequence of the shape rather than of the unit inside it, and it has a fix — which is session 28, and which begins by quoting the paragraph of SLP3 that starts exactly here.

The main points

Sequence labelling emits one output per input, which cannot translate: the alignment need not be monotonic — SLP3's English-to-Spanish example reorders 4, 1, 3, 2 — and the two sentences need not be the same length. The encoder-decoder is a different shape with three parts: an encoder producing hidden states from the source, a context vector c summarising them, and a decoder generating an arbitrary-length output from c. It is a shape rather than a model — RNNs, CNNs and transformers all fit inside it. The construction is a small change to a language model the course already had: put a separator after the source, concatenate the target, and train an ordinary next-word model on the result, factorised by session 12's chain rule. The context vector is the encoder's final hidden state, and SLP3 supplies it at every decoder step rather than only the first, so its influence does not wane. Training uses teacher forcing — the gold word as the next input — while inference feeds the model its own output, so the model is trained in a condition it never meets in use. And c is one fixed-size vector however long the source: at d=300, a fifty-word sentence is squeezed 50 : 1 where a four-word sentence is squeezed 4 : 1, and nothing in the architecture notices.

Reading

Speech and Language Processing, §13.7 and §13.7.1 — equations 13.28 to 13.32, with the same numbering used above. Stop at the end of §13.7.1. §13.8 is session 28 and it opens on the problem this session closed with; reading it now hands you the answer before you have felt the question.

Sutskever et al. 2014, the paper that made this architecture work at scale, is worth reading — with two differences from §13.7 flagged in advance, so they do not read as contradictions:

  • It reverses the source sentence before feeding it to the encoder. This is not an implementation detail; the paper calls it "one of the key technical contributions of this work", because reversing "introduced many short term dependencies between the source and the target sentence which made the optimization problem easier". §13.7 never mentions it.
  • It passes the context only as the initial hidden state. Sutskever takes "the fixed-dimensional representation v … given by the last hidden state" and runs an LSTM "whose initial hidden state is set to v". That is the simpler design SLP3 deliberately improves on with equation (13.32). The lecture follows SLP3; the paper is one step behind it here, and both are correct descriptions of things people built.
