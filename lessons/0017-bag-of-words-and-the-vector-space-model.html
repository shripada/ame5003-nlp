Bag of Words and the vector space model

You built this table in session 8 and used it as a lookup. Change the 0s and 1s to counts, read the columns instead of the rows, and it becomes a map with documents as places on it.

The thing we have been using without naming

Last session we classified a film review, and to do it we threw away the word order and kept a count for each word. We never gave that a name. It has one:

Bag of words

Represent a document by which words it contains and how often, discarding the order entirely. A bag, not a list — you can see what is in it, but not what came first.

The name is doing honest work. A bag really does lose something, and it is worth being blunt about how much:

"the film was good, not bad"      →   the·1  film·1  was·1  good·1  not·1  bad·1
"the film was bad, not good"      →   the·1  film·1  was·1  good·1  not·1  bad·1

Opposite meanings, identical representations. No amount of cleverness later can recover a distinction that was destroyed here. We accept it anyway, for the reason session 15 gave: word identity carries most of the signal, word order costs far more to model than it repays. But know what you traded.

The move: a column is a vector

Session 8 read this table in rows — each row a string of bits saying which plays contain a word, which is what Boolean queries need.

Read it in columns instead. Take As You Like It:

As You Like It   =   [ 1, 114, 36, 20 ]
                       ↑   ↑    ↑   ↑
                    battle good fool wit

That is a list of four numbers. A list of numbers is a vector. And a vector of length four is a point in four-dimensional space — one axis per word, and the document's position along each axis is how often it uses that word.

This is the whole idea of the hour

Every document becomes a point in a space with one dimension per vocabulary word. The collection becomes a cloud of points.

And once documents are points, documents that are close together use words in similar proportions — which is to say, they are about similar things. Meaning has become position.

This is called the vector space model, and everything in the rest of this course lives inside it.

Session 8's matrix could answer one kind of question: does this document contain these words? Useful, and limited. The vector space model answers a different kind: which of these documents resemble each other? Nothing in Unit I could do that.

Seeing it

That picture is the payoff. As You Like It and Twelfth Night are comedies; Julius Caesar and Henry V are histories. The grouping was not put there by anyone — it fell out of counting two words.

Real vectors have tens of thousands of dimensions rather than two, so we cannot draw them. But the closeness is still there, and it can still be measured. How to measure it is session 19.

The rows are vectors too

We turned the columns into document vectors. The rows work the same way: fool is [36, 58, 1, 4] — a word represented by the documents it appears in.

That is a smaller idea here and an enormous one shortly. If a word can be a vector, then words have positions, and words with similar positions are used in similar contexts — which is most of the way to what a word means. That is where sessions 21 and 22 go, and it starts here.

The price: almost everything is zero

Our table had four words. A real vocabulary has 50,000, so every document vector has 50,000 numbers in it — and a 200-word review can be non-zero in at most 200 of them. Over 99% of every vector is zero.

Such a vector is called sparse, and storing it literally would be absurd: a million documents by 50,000 words is fifty billion cells, almost all of them 0.

Which is exactly why session 9 built the inverted index — a structure that stores only the non-zero entries. The vector space model is how we think about documents; the inverted index is how we store them. Same information, and the storage question was solved before we needed it.

Think about this before reading on

Look at the table again. good has the largest counts by far — 114, 80, 62, 89 — in every single play. If you had to drop one of the four words from the representation, which should go, and why?

Drop good, despite it having the biggest numbers by a wide margin.

It appears a lot in all four plays, so it never helps you tell them apart. On the plot it would push every play far along the same axis and separate nothing. Meanwhile battle — whose counts are tiny — cleanly splits the histories from the comedies.

A word is useful in proportion to how well it distinguishes documents, not how often it occurs. Raw counts get this backwards, and they get it worst for exactly the words that are most common.

Question 1 of 2

In the vector space model, what does a single column of the term-document matrix represent?

Correct answer: one document, placed by how often it uses each word.

Columns are documents, rows are words — so a column is a document vector with one dimension per vocabulary word. The first option describes a row, which is also a useful vector (it represents a word) and is where word embeddings come from in sessions 21–22.

Question 2 of 2

Why can bag of words not tell "dog bites man" from "man bites dog"?

Correct answer: it records only which words occur and how often, not their order.

Both sentences contain the same three words once each, so both produce exactly the same vector. The information was destroyed at representation time and nothing downstream can recover it. That is the cost of the model, accepted deliberately — not a bug to be fixed later.

The one thing to remember

The whole lesson in two sentences

Bag of words represents a document by its word counts with the order thrown away, which turns each document into a vector — a point in a space with one dimension per vocabulary word. Once documents are points, documents that sit close together use words in similar proportions and are therefore about similar things, and that single idea is what makes search, similarity and every embedding in this course possible.

One problem is already visible, and the recall box above is it. good has the biggest counts in the table and is the least informative word in it. Raw counts reward words for being common, when what we actually want is words that are distinctive.

You have met the fix already — session 10 used TF-IDF to rank search results. Next session puts it inside the vector instead of inside a score, and then re-draws the picture above to show what changes.
