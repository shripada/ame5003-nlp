BERT and masked language modelling

Session 31 left a sentence on the table: an encoder sees the whole sequence, so it is for understanding. This session is that model — and the training objective it is forced to use, because seeing ahead makes the old objective trivial. Along the way it pays a debt from sessions 21 and 22: one word, two meanings, two vectors.

The sentence from last session

Session 31 closed on a distinction that was smaller than the two names suggested. An encoder block and a decoder block run the same three equations; they differ only in whether the future is allowed to be seen. An encoder has no mask, because it is not predicting the next token — it is producing a representation of an input that is already, entirely, present. A decoder must have a mask, because at generation time the right-hand context does not exist yet.

That single difference is why encoder-only models are for understanding, and decoder-only models are for generation. This session is the encoder-only model. Its name is BERT — Bidirectional Encoder Representations from Transformers — and the paper is Devlin et al., NAACL 2019.

SLP3 states the same contrast more sharply than the architecture diagram does:

SLP3 §10.1

"The causal models of Chapter 8 are generative models, designed to easily generate the next token in a sequence. But the focus of bidirectional encoders is instead on computing contextualized representations of the input tokens."

And it names the reason you would want to peek ahead, on a task this room already knows:

SLP3 §10.1

"there are tasks for which it would be useful, when processing a token, to be able to peek at future tokens. This is especially true for sequence labeling tasks in which we want to tag each token with a label, such as the named entity tagging task…"

That is session 7. Deciding whether Washington is a PERSON or a GPE may depend on words that come after it — Washington was born in 1732 against Washington raised the federal funds rate — and a left-to-right model has not read them yet. The course set that problem up twenty-five sessions ago. An encoder that sees the whole sequence is the architecture that problem was waiting for.

Bidirectionality, though, is not free. The next section is the bill.

Why the old objective collapses

Sessions 11–14 trained language models by predicting the next word. That works precisely because the model cannot see ahead: the answer is hidden, so the only way to drive the loss down is to learn something about English. Session 31's causal mask is the same idea in a transformer — "guessing the next word is pretty simple if you already know it".

Remove the mask, and the objective collapses. A bidirectional model asked to predict the word at position i can simply read position i. The loss can be driven to zero without the weights learning anything about language at all. The task has become copying, and copying teaches nothing.

So bidirectionality costs the training objective that Unit II ran on. Buying the ability to see the whole sequence means next-word prediction is no longer a question with a hidden answer. A replacement is needed, and that replacement is the subject of the next section. Masked language modelling is an answer to this problem, not a definition that happens to have a name.

Session 21 already ran a cousin of this idea: delete a word, ask the model to name it, keep the weights. CBOW predicted the centre word from an average of nearby context vectors, and what came out was one static vector per word type. The same fill-in-the-blank shape, pointed at a bidirectional transformer, is what produces a different vector for every occurrence of the word. Hold that; it returns when we reach contextual embeddings.

Masked language modelling

BERT selects 15% of the tokens in the input and manipulates them. The model is then asked to predict the original token at each of those positions, from both sides, using the rest of the sequence. SLP3's own example is lunch was delicious, with delicious chosen. That chosen token is not always replaced with [MASK]. It is treated in one of three ways:

treatmentexample
80%replace with [MASK] lunch was [MASK]
10%replace with a random token, sampled by unigram probabilitylunch was gasp
10%leave unchanged lunch was delicious

The loss is computed only at the chosen positions, and the target is always the original token — even in the 10% of cases where the input was left alone, and even in the 10% where it was replaced with something random. The model is being asked, at those positions, what actually belonged here?

The 80/10/10 split looks arbitrary, and it is the thing students memorise. The reason for it is the thing to take away. SLP3:

SLP3 §10.2.1

"Adding the [MASK] token creates a mismatch between pretraining and downstream finetuning or inference, since when we employ the MLM model to perform a downstream task, we don't use any [MASK] tokens. If we just replaced tokens with the [MASK], the model might only predict tokens when it sees a [MASK], but we want the model to try to always predict the input token."

At fine-tuning time there are no [MASK] tokens at all. A model that has only ever been asked to produce a prediction where it sees [MASK] will have learned a trick that does not fire when the model is actually used. The 10% random and 10% unchanged cases force it to hold an opinion about every position, not only the ones wearing a mask.

The same shape as session 27

Teacher forcing trained the decoder on gold prefixes it would never have at inference; scheduled sampling was the patch. Here, pretraining puts [MASK] in the input and fine-tuning never does; the 80/10/10 split is the patch. Two sessions apart, same diagnosis: a model trained in a condition it never meets at deployment will underperform.

Question 1 of 2

Why does MLM replace only 80% of the chosen tokens with [MASK], rather than all of them?

Correct answer: the pretrain / fine-tune mismatch. Downstream, the input contains no [MASK] tokens. If the model has only ever been asked to fill a [MASK], that is the only place it will bother to represent the token well. The 10% random and 10% unchanged cases are there so it has to have an opinion about ordinary tokens too.

The second is the answer nearly everyone gives, and it is not the reason. Difficulty is a side-effect, not the design. The third confuses two objectives: NSP is a sentence-pair decision carried by [CLS], not by the masked positions. The fourth confuses the 15% with the 80%. The softmax is already only at the chosen 15% of positions; changing how those 15% are corrupted does not change how many positions the loss is computed at.

Next sentence prediction — and what followed

BERT is trained on a second objective at the same time. Given two sentences packed into one input, predict whether the second actually followed the first in the original text. Half the time it did; half the time the second sentence is sampled at random from the corpus.

The input is built with two special tokens the room has not needed until now. [CLS] is placed at the start, and [SEP] is placed between the two sentences (and at the end):

[CLS] lunch was delicious [SEP] I ordered seconds  [SEP]     →  IsNext
[CLS] lunch was delicious [SEP] the stock market fell [SEP]  →  NotNext

The final-layer vector at [CLS] is the one that carries the prediction — a classifier sits on that single position and outputs IsNext or NotNext. That is why [CLS] exists: it is a dedicated place for a sequence-level decision, trained to summarise the pair. It will earn a second job in session 33, when a different classifier sits on the same position for a downstream task. For this session it is enough to know that BERT has a place to put a yes/no about the whole input, and that NSP is what trains it.

The original paper argued that this helps on paraphrase, entailment, and discourse-coherence tasks — anything where the relationship between two sentences is the thing being classified. That argument did not survive later work, and SLP3 records the fact itself:

SLP3 §10.2.2

"Some models, like the RoBERTa model, drop the next sentence prediction objective, and therefore change the training regime a bit."

NSP belongs in the original model: it is why [CLS] and [SEP] are in the input, and it is how BERT was actually trained. Later work found it dispensable. RoBERTa kept masked language modelling, dropped next sentence prediction, trained on more data for longer, and did better. The second objective was not load-bearing.

One word, two vectors

This is the thing sessions 21 and 22 promised, and it is the centre of the hour.

Session 21 closed on a concrete failure. The nearest neighbours of bank in Word2Vec were:

bank  →  banks 0.744, banking 0.690, Bank 0.670, lender 0.634, banker 0.609, depositors 0.603

Every one of them is the financial sense. The river sense is not ranked low. It is absent, because there is a single vector and the more frequent sense has taken all of it. Session 21 named the failure in one line — one word, one vector, no matter how many things the word means — and said that fixing it is what contextual embeddings do. Session 22 repeated the same three limits and pointed at Unit III again.

§10.3.1 opens on the same word:

SLP3 §10.3.1

"The word 'bank' can mean: (1) a financial institution or (2) a sloping mound."

And the two sentences the chapter uses are:

a bank can hold the investments
agriculture burgeons on the east bank

A bidirectional encoder maps the sequence (x1…xn) to a sequence of hidden states (h1…hn), where each hi has been contextualised by the entire sequence — left and right. The vector for bank in the first sentence has been mixed with investments; the vector for bank in the second has been mixed with east and agriculture. They are different vectors, because the surrounding tokens differ. Word2Vec could not do this even in principle: its table has one row per word type, and a row cannot be two places at once.

This closes the loop. The course promised this fix twice and named the unit it would arrive in. A bidirectional encoder does not add a second row to Word2Vec's table. It stops having a table of word types at all, at the output: the vector for a token is a function of the whole sentence it sits in. The input still begins with a static embedding — session 30's token embedding, looked up from a table of 30,000 WordPiece rows — and the stack of unmasked encoder blocks is what contextualises it.

SLP3's Figure 10.6 is the same argument run on more sentences. It takes BERT embeddings of the word die across many contexts, projects them to two dimensions, and the points separate into three clusters: the English noun (singular of dice), the English verb, and the German article. Three clusters, one spelling, no sense labels supplied. The model was never told that die has three readings. The surrounding tokens were enough.

Question 2 of 2

What does a contextual embedding give that Word2Vec cannot?

Correct answer: a different vector for the same word in different contexts. That is the entire content of §10.3, and it is the failure session 21 measured on bank. Word2Vec has one row per word type; a bidirectional encoder produces one vector per occurrence.

The second is true and irrelevant, which is why it is a good distractor: d=768 against 300 is a real difference and has nothing to do with contextualisation. A 768-dimensional Word2Vec would still be one vector per word. The third describes WordPiece, which BERT does use — session 3, and the next section — but subword tokenisation still produces one embedding per subword type; it does not split senses. The fourth describes positional embeddings from session 30, which tell the model where a token sits, not which sense it is being used in. bank as the second word of both sentences above would still need two different vectors.

BERT's actual size

SLP3 §10.1.1 gives the configuration of BERT-base. The parameter split below is computed from it, not copied from a blog post.

settingBERT-base
vocabulary30,000 WordPiece subwords
context window N512 tokens
model dimension d768
layers L12
heads A12
SLP3's stated total"about 100M parameters"

Head width is the same as Vaswani's: dk=d/A=768/12=64. The feedforward hidden layer is the same factor of four as session 31: dff=4d=3072. One block's attention is three projections plus WO; its feedforward is two matrices, [768×3072] and [3072×768]:

componentparameters
token embeddings, 30,000×76823,040,000
position embeddings, 512×768393,216
attention in one block2,359,296
feedforward in one block4,718,592
one block (attention + FFN)7,077,888
12 blocks84,934,656
total (ignoring norms and biases) 108,367,872

108M against SLP3's "about 100M" — close enough to confirm the arithmetic and the config together. Two things to take from the split, both of which the room has the machinery to see without being told.

The embedding table alone is 21% of the model — 23 million parameters sitting in a lookup, before any transformer block has run. The vocabulary is not a rounding error. And session 31's finding holds here too: in each block the feedforward layer is twice the attention (4.7M against 2.4M), in a model whose fame is entirely about attention. Most of "BERT has 100 million parameters" is feedforward weight, plus a vocabulary table a fifth the size of the whole network.

One sentence, while the vocabulary is on the board, to close a loop from session 3. That session taught WordPiece as "a close cousin of BPE", showed doomscrolling → ["doom", "##scroll", "##ing"], and promised that BERT uses it. Here is that vocabulary: 30,000 WordPiece tokens. The input still begins as a lookup in a static table. What has changed is what happens after the lookup.

Exercise

Suppose someone trains a bidirectional transformer — no causal mask, every position may attend to every other — with the next-word-prediction objective from sessions 11–14. At each position i the model is asked to predict token i+1.

First: why would training fail to teach the model anything useful about language?

Second: what does masked language modelling change, such that the same bidirectional model now has something to learn?

Why next-word prediction fails. The model can see the token it is being asked to predict. Position i's query is allowed to attend to position i+1's key and value, which is the answer. The loss can be driven to zero by copying, and copying does not require any knowledge of English. The causal mask was what made next-word prediction a question with a hidden answer; remove it and the question disappears.

What MLM changes. The answer is hidden again, but not by masking the future — by corrupting the present. A subset of positions is replaced (usually with [MASK], sometimes with a random token, sometimes not at all) and the model must recover the originals from the surviving context on both sides. The targets are no longer sitting in the input in plain sight, so the only way to drive the loss down is to learn how tokens relate to their bidirectional context. That is the representation the encoder was for.

The 80/10/10 split is a further refinement of the same idea, not a different one: even after the answer is hidden, the cue that it was hidden ([MASK]) must not become the only place the model bothers to think, because that cue will be absent when the model is used.

Where this leaves us

T3.8 is complete. The room now has a pretrained bidirectional encoder: 12 unmasked transformer blocks, a 30,000-token WordPiece vocabulary, trained to fill in blanks from both sides, producing a different vector for bank in each of the two sentences that Word2Vec had to give one vector to.

That is what BERT is. Session 33 is what it is for. The expensive part — pretraining on unlabelled text — is already done. What remains is to sit a small head on top of these representations and train it on a labelled task, which is fine-tuning, and then to ask whether a smaller copy of the same model can be made to behave like this one, which is DistilBERT.

The main points

An encoder-only model sees the whole sequence, so it is for understanding; a decoder-only model cannot, so it is for generation. Bidirectionality makes next-word prediction trivial — the model can read the answer — and masked language modelling is the replacement: 15% of tokens are chosen, of which 80% become [MASK], 10% a random token, and 10% are left unchanged, and the model predicts the originals from both sides. The 80/10/10 split exists because [MASK] is absent at fine-tuning time, and a model trained only on it would learn to predict only where it sees one — the same train/deploy mismatch as session 27's teacher forcing. A second objective, next sentence prediction, asks whether sentence B followed sentence A and puts the answer on [CLS]; RoBERTa dropped it and did better. The output of the stack is a contextual embedding: bank in a bank can hold the investments and bank in agriculture burgeons on the east bank are different vectors, which is the failure sessions 21 and 22 named and could not fix. BERT-base is 12 layers, 12 heads, d=768, 30,000 WordPiece tokens, about 108M parameters — 21% of them the embedding table, and twice as much feedforward as attention in every block.
