The transformer: encoder blocks, decoder blocks, the whole picture

Sessions 29 and 30 built the attention layer. This session builds the box that contains it, stacks the box six times, and then asks what separates an encoder from a decoder. The answer is smaller than it sounds: the same three equations, run three times, differing only in what is querying what.

What is already in hand

Two sessions have gone into one layer. It is worth listing what that produced before adding anything, because from here on this session is assembly rather than new theory.

  • Multi-head scaled dot-product self-attention. Each head projects the input three ways, Q=XWQ, K=XWK, V=XWV; scores are qi⋅kj divided by dk; a softmax turns scores into weights; the output is a weighted sum of values. A heads run in parallel and WO mixes their outputs back into one d-wide vector.
  • Positional embeddings. The input matrix X is built by adding a learned positional vector to each token's embedding, before the first layer.

SLP3 §8.2 is precise about what is still missing, and it is a list of exactly three items: the transformer block is that attention layer plus "(1) a feedforward layer, (2) residual connections, and (3) normalizing layers". All three arrive in the next few paragraphs, and only one of them is genuinely unfamiliar.

The three missing pieces

The feedforward layer

Nothing new at all. It is session 20's two-layer network — one hidden layer, two weight matrices,

FFN(xi)=ReLU(xiW1+b1)W2+b2(8.21)

Two things about how it is used. First, it is applied to each position independently: the same W1 and W2 are used at every token position in the sequence, and no position's feedforward computation looks at any other position's vector. Whatever mixing between tokens happens in a transformer, it happens in the attention layer and nowhere else. Second, the hidden layer is wider than the model. SLP3: "It is common to make the dimensionality dff of the hidden layer of the feedforward network be larger than the model dimensionality d. (For example in the original transformer model, d=512 and dff=2048.)" Remember that factor of four; it is the whole story of the parameter count below.

Layer normalisation

This one is new, and SLP3 introduces it in a way that makes it much less intimidating than the name: it is "a variation of the z-score from statistics, applied to a single vector in a hidden layer". Not applied to a layer, despite being called layer norm — applied to one token's vector at one position. In goes a vector of dimensionality d; out comes a vector of dimensionality d.

Take the mean and the standard deviation over the d components of the vector:

μ=1d∑ixi(8.22)
σ=1d∑i(xi−μ)2(8.23)

Subtract the mean from every component and divide by the standard deviation. The result has mean zero and standard deviation one:

xˆ=(x−μ)/σ(8.24)

Then two learned parameters are put back — γ, a gain, and β, an offset, each a vector of d numbers, trained like everything else:

LayerNorm(x)=γ(x−μ)/σ+β(8.25)

Why do it at all? The purpose is training stability rather than expressiveness: it keeps the values flowing through a deep stack inside a range where gradient-based training works, which matters when the stack is six or twelve or ninety-six blocks deep and each block's output is the next one's input. Without it, the scale of the vectors is free to drift as they pass through the stack, and a drift that is harmless at block 2 is not harmless by block 40.

Where session 28's objection finally lands

Session 28 objected that Bahdanau's score was an unnormalised dot product, and that a dot product favours long vectors. Session 29 answered half of it: dk divides by the expected scale of a score at that dimensionality. It explicitly did not answer the other half — one key vector actually being longer than another.

Layer norm is the other half. Every vector entering an attention sublayer has been rescaled to mean zero and standard deviation one first, up to the learned γ and β, so the vectors being dotted together arrive at comparable lengths. It is not cosine similarity and it does not claim to be — but the failure mode session 28 named, one vector dominating every score because it happens to be long, is what this controls.

Residual connections, and the residual stream

A residual connection is one line of arithmetic: instead of a component's output replacing its input, the output is added back to the input. Where a plain stack computes x→f(x)→g(f(x)), a residual stack computes x→x+f(x)→x+f(x)+g(…).

SLP3 gives this a framing worth adopting, from Elhage et al. (2021): think of a single d-dimensional residual stream running vertically through the whole model at each token position. The stream starts as that token's input embedding. Every component reads from the stream, computes something, and adds its result back in. Nothing ever overwrites the stream.

That picture explains two things at once. It explains why gradients survive a deep stack — the stream is an uninterrupted addition path from the output back to the input embedding, with no chain of matrix multiplications on it, which is session 24's vanishing-gradient problem answered by construction rather than by mitigation. And it explains SLP3's remark about which component does what: "the only component that takes as input information from other tokens (other residual streams) is multi-head attention". Attention is the token-mixing component — it moves information from a neighbouring token's stream into this one. The feedforward layer works within a single stream.

Two pictures of the same architecture

The residual-stream framing is a modern reframing, and Alammar's Illustrated Transformer — the assigned second read — draws the older picture, with "Add & Norm" boxes sitting between sublayers. They are the same equations. If the two readings look different, that is a difference of drawing, not of model.

The block, assembled

Six lines, one per component, with t standing for transformer and the superscripts numbering the steps inside the block. Everything here has now been introduced:

equationSLP3 eq.
ti1=LayerNorm(xi)(8.26)
ti2=MultiHeadAttention(ti1,t11…tN1)(8.27)
residual ti3=ti2+xi(8.28)
ti4=LayerNorm(ti3)(8.29)
ti5=FFN(ti4)(8.30)
residual hi=ti5+ti3(8.31)

Read it aloud as two identical movements: normalise, attend, add back; normalise, transform, add back. The pattern is the point. A transformer block is not six unrelated steps, it is the same three-step figure performed twice, once with attention in the middle and once with the feedforward network in the middle.

Two details in the notation are worth pointing at. In (8.27), attention takes ti1 and t11…tN1 — the query comes from position i, the keys and values from all positions. That is the only line where other tokens appear. And in (8.28) the thing added back is xi, the block's input, while in (8.31) it is ti3, the state of the stream after the attention sublayer. Each residual reaches back to just before its own sublayer, not all the way to the start.

Because xi and hi are both [1×d], the block's output is the same shape as its input, which is what makes stacking possible at all.

Pre-norm and post-norm: the reading and the paper disagree

Equation (8.26) puts LayerNorm on the input of each sublayer. Vaswani et al. 2017, §3.1, puts it on the output: "the output of each sub-layer is LayerNorm(x+Sublayer(x))". SLP3's arrangement is called pre-norm and the original paper's is post-norm, and SLP3 states its choice outright — "throughout the chapter, we use the prenorm version of the architecture".

This is not a notational variant; the two train differently, and post-norm typically needs a learning-rate warmup schedule that pre-norm does not. We teach the pre-norm form, because that is the reading. Note only that the 2017 paper puts the norm after each sublayer, that a diagram drawn from that paper will therefore show "Add & Norm" after the box, and that practice has largely moved to pre-norm since.

Stacking, and where the parameters actually are

One block is not a transformer. The original model stacks N=6 identical blocks in the encoder and six more in the decoder; SLP3 notes that language models run from 12 layers (T5, GPT-3-small) to 96 (GPT-3 large) and beyond. Identical in architecture, not in parameters — every block has its own weights.

One small extra, easy to miss and worth stating because it is the only asymmetry in the stack: after the last block there is one further layer norm, run on each token's final hi before whatever head sits on top.

Now the arithmetic. Take Vaswani's base configuration — d=512, A=8 heads, dk=dv=64, dff=2048 — and count the parameters of one block. Session 30 already counted the attention layer: three projections at 8×512×64 each, plus WO at 512×512. The feedforward layer is two matrices, [512×2048] and [2048×512]:

componentshapesparametersshare of the block
multi-head attention3×(8×512×64) + 512×512 1,048,57633.3%
feedforward512×2048 + 2048×512 2,097,15266.7%

Two thirds of a transformer block is the feedforward layer, not the attention. The component the architecture is named for, the one every diagram is drawn around and every explainer spends its length on, is the minority of the parameters — by a factor of two. The reason is the one detail flagged earlier: dff=4d, so each of the feedforward's two matrices is four times the size of one of attention's full-width projections, and there is no equivalent widening anywhere in the attention layer.

Two consequences worth carrying forward. Layer norm is free — 2,048 numbers against three million, small enough that it never appears in a parameter budget. And when sessions 32 and 33 describe a model as having some number of parameters, most of that number is feedforward weight.

Question 1 of 2

In a standard transformer block, which part holds most of the parameters?

Correct answer: the feedforward layer. With d=512 and dff=2048 its two matrices come to 2,097,152 parameters against attention's 1,048,576 — 66.7% against 33.3%. Attention is outnumbered two to one.

The first option is the answer nearly everyone gives, and it is not unreasonable: attention really does have more matrices. What it misses is that the heads partition the width (session 30), so the three projections together cost only 3×512×512 — while the feedforward layer is deliberately wider than the model. The third is off by three orders of magnitude: γ and β at two points is 2,048 numbers, 0.07% of the block. The fourth confuses parameters with activations. The N×N attention matrix is computed at run time and is not stored weight; the parameter count of a transformer does not depend on the length of its input.

Encoder blocks and decoder blocks

Everything so far describes a block. The architecture has two kinds, and the difference between them is smaller than the two names suggest.

The mask, at last

Sessions 29 and 30 both deferred this. Session 29's packed equation (8.33) carried a mask function with one sentence of explanation; here is the rest of it.

Computing QK𝖳 produces a score for every query against every key — including keys at positions that come after the query. For a model being trained to predict the next token that is fatal, and SLP3 puts it bluntly: "guessing the next word is pretty simple if you already know it". So the scores from the future are removed, before the softmax, by adding a mask matrix:

Mij=−∞∀j>iMij=0otherwise

Adding −∞ to a score and then taking a softmax gives exactly zero weight, so those positions contribute nothing to the weighted sum. Nothing is deleted from the input and no separate machinery is needed — the mask is one addition inserted between the scores and the softmax, which is why session 29's softmax(mask(QK𝖳/dk))V was able to carry it as a single function name. The result is the lower-triangular attention matrix drawn in session 29.

Note what this does not cost. The masked scores are still computed; they are thrown away afterwards. Masking buys correctness, not speed.

Why an encoder has no mask

An encoder is not predicting the next token. It is producing a representation of an input that is already, entirely, present — so there is no future to hide, and every position may see every other. SLP3 §12.3 says it in one line: "The multi-head attention in the encoder, however, is allowed to look ahead at the entire source language text, so it is not masked."

That single difference is the origin of a distinction the next two sessions run on: encoder-only models are for understanding, decoder-only models are for generation. An encoder can use the right-hand context of a word to represent it, which is what you want when deciding what the word means; a decoder must not, because at generation time the right-hand context does not exist yet.

Cross-attention

The third case, and the only genuinely new mechanism in this session. When there is an encoder to attend to, each decoder block gets an extra sublayer between its self-attention and its feedforward layer.

SLP3 §12.3

"the encoder-decoder architecture is made up of two transformers: an encoder, which is the same as the basic transformers from Chapter 8, and a decoder, which is augmented with a special new layer called the cross-attention layer. […] Cross-attention has the same form as the multi-head attention in a normal transformer block, except that while the queries as usual come from the previous layer of the decoder, the keys and values come from the output of the encoder."

The equations are session 29's, with one substitution. Where self-attention projected the same matrix three ways, cross-attention projects the decoder's state to get Q and the encoder's final output Henc to get K and V:

Q=Hdec[ℓ−1]WQK=HencWKV=HencWV(12.11)
CrossAttention(Q,K,V)=softmax(QK𝖳/dk)V(12.12)

Compare (12.12) with session 29's (8.33). It is the same equation with the mask removed — there is nothing to hide, because the entire source sentence is available from the start. What changed is not the mechanism but its inputs.

Which is the observation the whole session is built toward. One mechanism, three uses:

And cross-attention has a name from three sessions ago. A decoder state querying a set of encoder states, producing weights over source positions, and returning a weighted sum — that is exactly session 28's Bahdanau attention. The transformer did not invent decoder-attends-to-encoder; it replaced Bahdanau's small feedforward scoring network with a scaled dot product, ran it in several heads, and put it inside a block. Sessions 27, 28 and 31 are describing the same idea at three levels of machinery.

Question 2 of 2

What distinguishes a decoder block from an encoder block?

Correct answer: the mask, plus cross-attention. Those are the only two differences. Everything else — the feedforward layer, the residual connections, the layer norms, the shapes, the stacking — is identical, which is why SLP3 can describe the encoder as "the same as the basic transformers from Chapter 8" and the decoder as that "augmented with a special new layer".

The second option sounds plausible and is simply not so: A=8 on both sides in the original model, and nothing in the architecture ties the head count to the side. The third inverts the design — every block on both sides has a feedforward layer, and it is two thirds of the parameters. The fourth mixes up two unrelated things: pre-norm versus post-norm is a whole-model design choice (SLP3 uses pre-norm throughout, Vaswani post-norm throughout), and what lets a decoder generate one token at a time is the causal mask, not the placement of a normalisation.

Exercise

Here are the six equations of a transformer block, shuffled. The names have been kept but the order has not:

(a)  ti5=FFN(ti4)
(b)  ti3=ti2+xi
(c)  ti1=LayerNorm(xi)
(d)  hi=ti5+ti3
(e)  ti4=LayerNorm(ti3)
(f)  ti2=MultiHeadAttention(ti1,t11…tN1)

First, put them in order. Second — the part that matters — say which lines would have to change if the block were written in the original paper's post-norm style instead, and how.

The order is c, f, b, e, a, d — equations (8.26) through (8.31). You do not have to remember it. Each line's right-hand side names the variable the previous line produced, so the sequence can be reconstructed from the dependencies alone: t1 is used by (f), t2 by (b), and so on.

The pattern is what the ordering is really testing: normalise, attend, add back, then normalise, transform, add back. Two identical movements, different middles. Notice also that (b) adds back xi — the block's input, from before the first normalisation — and (d) adds back ti3, the state just before the second. Each residual reaches back to the start of its own sublayer.

Under post-norm, LayerNorm(x+Sublayer(x)), the normalisation moves from the front of each movement to the end, so the two pairs collapse. The attention half becomes a single line, ti3=LayerNorm(MultiHeadAttention(xi,x1…xN)+xi), replacing (c), (f) and (b); the feedforward half becomes hi=LayerNorm(FFN(ti3)+ti3), replacing (e), (a) and (d). Attention now consumes the raw xi rather than a normalised copy of it, and the residual addition happens inside the normalisation rather than after it.

That second change is the substantive one. Under post-norm the residual stream is normalised at every block, so it is no longer a clean addition path from output back to input — which is the usual explanation for why post-norm needs a learning-rate warmup and pre-norm does not.

Where this leaves us

T3.7 is complete. The room now has an entire transformer: an input built from token and positional embeddings, blocks of multi-head attention and feedforward layers wired with residual connections and layer norms, six of those blocks stacked, and two kinds of block depending on whether the future is allowed to be seen.

The next question is what you do with each kind, and the answer follows directly from the mask. Take the encoder alone, with no mask anywhere, and you have a model that reads a whole input at once and produces a representation of it — good for understanding, useless for generating, since it has never been trained to guess what comes next. That model is BERT, and it is session 32. Take the decoder alone and you have a language model. Take both, wired by cross-attention, and you have the machine translation architecture of session 34.

The main points

A transformer block is a multi-head self-attention layer plus three things: a feedforward layer (8.21), applied at each position independently, with a hidden layer four times the model width; layer normalisation (8.22–8.25), a z-score over the d components of one token's vector, with learned gain γ and offset β; and residual connections, which add each component's output back into a d-dimensional residual stream that is never overwritten. Assembled, that is equations (8.26)–(8.31): normalise, attend, add back; normalise, transform, add back. SLP3 normalises before each sublayer (pre-norm); Vaswani et al. normalise after (post-norm). Input and output are both [1×d], so blocks stack — N=6 in the original model, with one extra layer norm on top of the last block. Two thirds of a block's parameters are the feedforward layer, 2,097,152 against attention's 1,048,576; layer norm's 2,048 are negligible. An encoder block and a decoder block differ in exactly two ways: the decoder's self-attention is masked (Mij=−∞ ∀j>i, added before the softmax), and the decoder carries an extra cross-attention sublayer whose queries come from the decoder and whose keys and values come from the encoder's output Henc (12.11–12.12). The same three equations, three times over, differing only in what queries what.
