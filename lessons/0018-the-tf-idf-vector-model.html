The TF-IDF vector model

Last session's table rewarded the wrong words. Today we re-weight it — and the answer we get back is not the one anybody expects.

Term frequency and inverse document frequency, restated

Both quantities are as defined in session 10, and neither changes. This section is a restatement.

Term frequency measures how much a document uses a word, with diminishing returns, so that 100 occurrences is not a hundred times more informative than one:

tf  =  1 + log₁₀(count)     when count > 0
tf  =  0                    when count = 0

Inverse document frequency measures how rare the word is across the collection, where df is the number of documents containing it and N is the size of the collection:

idf  =  log₁₀(N / df)

One property of the second formula is used throughout this session:

Definitions

If a word appears in every document, then df = N, so idf = log₁₀(N/N) = log₁₀(1) = 0.

The value is not small or approximately zero but exactly zero, and any quantity multiplied by exactly zero is zero.

The Shakespeare corpus

Shakespeare wrote 37 plays, so N = 37. The following table gives df and idf for nine words across that collection:SLP3 3rd ed., §11.1.2, Fig. 11.5. The idf column is log₁₀(37/df) — every value here was recomputed from the df counts rather than copied.

Exercise

good occurs 114 times in As You Like It, the largest count anywhere in the table, and it appears in all 37 plays. What is its tf-idf weight?

tf = 1 + log₁₀(114) = 3.057, which is a healthy weight.

idf = log₁₀(37/37) = log₁₀(1) = 0.

tf-idf = 3.057 × 0 = 0.

It is worth asking whether a larger count would have helped. Suppose good occurred 10,000 times. Then tf = 5.0, and 5.0 × 0 is still 0.

No term frequency can compensate for an idf of zero. The exercise in session 17 concluded that good should be dropped. TF-IDF drops it automatically, and does so exactly rather than approximately.

Re-weighting the matrix

We multiply the two quantities together, cell by cell:

tf-idf  =  tf × idf  =  (1 + log₁₀ count) × log₁₀(N / df)

What else the weighting removed

The rest of the table requires attention. fool has fallen to hundredths and wit is little better. The only row retaining appreciable weight is battle.

fool and wit, however, were the words that separated the comedies. Session 17's plot worked because As You Like It and Twelfth Night sat high on the fool axis, and that axis has been reduced to almost nothing.

We can measure the effect directly. The distances between the re-weighted document vectors are:

Redrawing the scatter plot would not be informative: with only battle carrying appreciable weight, all four plays fall along a single line.

Why this happens

The obvious reading of this result is that TF-IDF has failed. That reading is incorrect, and understanding why matters more than the technique itself.

The main idea

idf is a property of the collection, not of the document.

Nothing about As You Like It has changed. What changed is that we asked how distinctive its words are among 37 Shakespeare plays, and Shakespeare uses fool in 36 of them and wit in 34. Within his collected works, those words are close to universal.

Stated another way: fool and wit are genuinely good words for distinguishing a comedy from a history in general. In a collection of all English books they would have high idf and carry real signal. In a collection consisting entirely of Shakespeare they carry none. The words did not change; the collection did.

The result can therefore be summarised as follows.

What the numbers show

TF-IDF did not break the example. It measured it, and the measurement shows that these four words cannot distinguish Shakespeare's plays, because Shakespeare uses them in nearly all of them. That is a fact about the collection which we did not have before.

Choosing better dimensions

The idf table already contains the answer. If the task is to distinguish Shakespeare's plays, we should choose words whose idf is high in this collection:

  • Romeo, idf 1.57, occurring in exactly one play. It identifies that play alone.
  • Falstaff, idf 0.966, occurring in four. It groups the Henry plays and nothing else.
  • forest, idf 0.489, occurring in twelve, largely the pastoral comedies.

These words would separate the plays cleanly, because they are rare in this collection. battle, good, fool, and wit were chosen in session 17 because they produced a clear picture under raw counts, and raw counts overstated their value.

This leaves us better informed than before. We have not merely weighted a matrix; we have established that our features were poorly chosen, and established it from the numbers rather than by judgement. A method that reports that the chosen features are poor for a collection is working correctly, not failing.

Question 1 of 2

To tell Shakespeare's 37 plays apart, which of these four words is the best feature, and why?

Correct answer: Falstaff, idf 0.966.

Appearing in only 4 plays is precisely what makes it useful, since observing it eliminates 33 of the 37 immediately. The other three options all reason from coverage, which is the opposite of what a discriminating feature requires. fool, in 36 plays, and sweet, in all 37, are of little use here for that reason, and sweet's weight is exactly zero.

Question 2 of 2

You take As You Like It, unchanged, and score it as part of a collection of ten thousand modern novels instead of Shakespeare's 37 plays. What happens to its tf-idf vector?

Correct answer: every weight changes.

The tf values do not change, since those are counts within the document and the document is unaltered. Every idf does change, because df and N both derive from the collection. fool and wit are rare among modern novels and would move from near-zero to genuinely informative, and good would cease to be zero as soon as one novel omitted it.

This is why the last option is wrong too: idf does not scale up uniformly with N, it depends on each word's own df. A tf-idf vector is not a description of a document. It is a description of a document relative to a collection.

A remaining problem

There is a second problem with measuring distance between document vectors, unrelated to weighting.

Take Julius Caesar's column from the raw table, [7, 62, 1, 2], and consider a document consisting of the same text repeated twice. Every count doubles:

d   =  [ 7,  62, 1, 2]     vector length  62.43
2d  =  [14, 124, 2, 4]     vector length 124.87

Euclidean distance between them:  62.43

The distance is 62.43, where the largest distance in the entire weighted matrix was 0.521. By this measure the two documents are extremely different. They are the same play, printed twice.

The problem is that doubling a vector does not move it but lengthens it. Both vectors point in exactly the same direction and one is simply longer. Length here reflects nothing but document length, which is not the quantity we intended to measure.

Where session 19 starts

What we want to compare is direction, not magnitude. A long document and a short document on the same subject should be counted as similar.

There is a standard measure with exactly this property, and on the two vectors above it returns 1.0000, indicating identical direction. Session 19 derives it.

Summary

The main points

TF-IDF weights each cell of the term-document matrix by (1 + log₁₀ count) × log₁₀(N/df), so that common words are reduced and distinctive words dominate, and a word appearing in every document collapses to exactly zero. What counts as distinctive, however, is measured against a particular collection, so the same word can be highly informative in one collection and worthless in another. When our four Shakespeare words nearly all collapsed, that was not a failure of TF-IDF but a report that those words describe this collection poorly.
