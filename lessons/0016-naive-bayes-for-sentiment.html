MSIS · AME 5003 · Unit II · Session 16

Naïve Bayes for sentiment, worked through

Five short reviews, one new sentence, and every number done by hand. The training is nothing but counting — and the first honest attempt fails completely.

Where session 15 left off

Session 15 ended with the complete classifier expressed in one line, containing no numbers:

best class  =  argmax   P(c) · Π P(w | c)
                c in C          w in d

This session supplies the numbers. Two quantities must be learned from data, the prior P(c) and the likelihoods P(w | c), and both are counts. There is no training loop and nothing to tune: we count, we divide, and the classifier is complete.

The training data

We use five very short reviews, already labelled by a human: three negative and two positive.

classdocument
−just plain boring
−entirely predictable and lacks energy
−no surprises and very few laughs
+very powerful
+the most fun film of the summer

The sentence to be classified, which the model has not seen, is:

predictable with no fun

A human reader judges this negative, on the basis of predictable and no fun. Whether the arithmetic reaches the same conclusion is the test.

Training, step 1 — the prior

The prior is how common each class is before any document is read. It is computed by counting documents:

P(c)  =  number of documents in class c  /  total documents

P(−)  =  3/5  =  0.6           P(+)  =  2/5  =  0.4

That completes the step. Note that this is the only place where we count documents; everything after this point counts words.

Training, step 2 — the likelihoods

We now require P(w | c): given that a review is negative, how often is a given word boring? To compute this, we concatenate all of a class's documents into a single big document and count within it:

P(w | c)  =  count of w in class c  /  total words in class c
classbig documenttokens
−just plain boring entirely predictable and lacks energy no surprises and very few laughs14
+very powerful the most fun film of the summer9
The two denominators compared

The prior divides by 5, the number of documents. The likelihood divides by 14 or 9, the number of words in that class. These are different questions with different denominators, and confusing them is the most common source of error in this calculation.

The positive big document is worth counting directly: very powerful the most fun film of the summer contains 9 tokens, not 8, because the appears twice.

The first attempt fails

The test sentence is predictable with no fun. Setting with aside for the moment, we apply the counts we have to the other three words:

wordcount in −P(w | −)count in +P(w | +)
predictable11/1400
no11/1400
fun0011/9

Multiplying these through, the negative class is zeroed by fun and the positive class by predictable and again by no:

P(−) · P(S | −)  =  0.6 × 1/14 × 1/14 × 0   =   0
P(+) · P(S | +)  =  0.4 × 0    × 0    × 1/9 =   0
Why a zero probability is worse than a wrong answer

Both classes score exactly zero. The classifier does not choose badly; it cannot choose at all. There is nothing to compare, and the tie cannot be resolved from these numbers.

Nothing unusual has occurred. Every word in the test sentence is an ordinary English word appearing in the training data. They simply did not all appear in both classes, which is entirely expected with five short documents.

This failure has now appeared three times: session 12's zero-probability sentence, session 13's treatment of the problem, and here. The cause is the same in each case: a product is zero if any factor is zero, and estimation by counting produces zeros readily.

Add-one smoothing

The correction is the one introduced in session 13. We treat every word as having been observed once more than it was:

P(w | c)  =  ( count(w, c) + 1 )  /  ( total words in c  +  |V| )

The form is the same as before: the +1 in the numerator removes the zeros, and the denominator grows by |V| so that the probabilities continue to sum to 1.

Why add-one is appropriate here

The objection raised in session 13 concerned scale. A language model has V of roughly 50,000, so add-one transferred almost all the probability to words never observed, and a bigram seen on every opportunity was assigned 0.008%.

Here V is 20. The correction is small, the resulting values remain sensible, and add-one is the method actually used for Naïve Bayes in practice rather than a simplification for teaching. The method has not changed; the vocabulary size has.

This generalises: a technique is not good or bad in itself, but good or bad at a particular scale on a particular problem.

What goes in |V|

|V| is the number of distinct word types across the whole training set, both classes together. In this training set there are 20:

and · boring · energy · entirely · few · film · fun · just · lacks · laughs
most · no · of · plain · powerful · predictable · summer · surprises · the · very
V is not computed per class

It is tempting to use the vocabulary of the negative class when computing negative likelihoods. This is incorrect: both classes use the same |V| = 20.

The reason is that the two classes' scores are comparable only if computed over the same set of possible words. Giving each class its own V compares probabilities defined over different sets of outcomes. The resulting numbers still appear reasonable, which is what makes this error difficult to detect.

The word with

with appears nowhere in the training data, in either class. It is not in V and therefore has no probability to smooth. The rule for Naïve Bayes is simply to drop it: the word is removed from the test document and the calculation proceeds with the remaining words.

Comparison with session 13

For a language model, an unknown word was handled with <UNK>, because the model has to assign the sentence a probability and cannot simply pretend part of it is absent.

A classifier need only compare classes. An unknown word contributes nothing to every class equally, so it cannot affect which class wins. Dropping it is therefore not an approximation and changes no decision. Note that the correct treatment depends on what the model is for, not only on the problem it encounters.

The full calculation

With |V| = 20, the denominators become 14 + 20 = 34 and 9 + 20 = 29:

wordP(w | −)P(w | +)
predictable(1+1)/34 = 2/34(0+1)/29 = 1/29
no (1+1)/34 = 2/34(0+1)/29 = 1/29
fun (0+1)/34 = 1/34(1+1)/29 = 2/29

There are no zeros. Multiplying each row through, with the prior in front:

P(−) · P(S | −)  =  3/5  ×  (2 × 2 × 1) / 34³  =  6.1 × 10⁻⁵     ← larger
P(+) · P(S | +)  =  2/5  ×  (1 × 1 × 2) / 29³  =  3.2 × 10⁻⁵

The classifier returns negative, which agrees with the human judgement. It reached this result with no knowledge of English, from five documents and a few divisions.

It is worth examining where the decision came from. Each class had one word in its favour and two against, so the margin is small. However, predictable and no each appeared in negative reviews and never in positive ones, and these two words outweighed fun pointing the other way. The prior also contributed, since negative reviews were more common in the training set.

Exercise

The negative calculation above is worked in full. Carry out the positive calculation and confirm that it gives 3.2 × 10⁻⁵. The required values are the prior 2/5 and the three probabilities 1/29, 1/29, and 2/29.

2/5 × (1/29) × (1/29) × (2/29) = 2/5 × 2/24389 = 4/121945 = 3.28 × 10⁻⁵

The denominator is 29 because the positive big document contains 9 tokens and |V| is 20. A denominator of 28 indicates that the positive documents were counted as 8 tokens, missing the second the in the most fun film of the summer.

A substantially larger result indicates that a per-class vocabulary was used in place of |V| = 20.

Numerical underflow

Our test sentence contained three words. A real review contains perhaps two hundred, so the score is a product of two hundred probabilities, each small and the product very much smaller.

Computers store numbers with limited precision. Multiplying enough small values produces a result that is not merely small but exactly zero:

0.01 ^ 200   →   0.0        (not "very small" — zero, in ordinary floating point)

This is called underflow. It would again reduce every class to zero, this time for a purely arithmetic reason rather than a missing count.

Working in logarithms

Logarithms convert multiplication into addition, since log(a × b) = log a + log b. Taking the logarithm of the whole expression turns the product into a sum:

best class  =  argmax   log P(c)  +  Σ log P(w | c)
                c in C             w in d

The values being added are moderate negative numbers, around −3 rather than 10⁻¹⁴⁷, so nothing underflows.

Our example, computed in natural logarithms:

classlog prior+ log likelihoodstotal
−−0.51−2.83 − 2.83 − 3.53−9.70 ← larger
+−0.92−3.37 − 3.37 − 2.67−10.33

The negative class again scores higher, as it must.

Why logarithms preserve the ranking

The logarithm is monotonic: if a > b then log a > log b, always. So whichever class had the bigger score still has the bigger log score. The ranking is preserved exactly, and the ranking is the entire output.

What is lost is the interpretable scale: −9.70 is not a probability and cannot be reported as one. That was already given up in session 15 when P(d) was dropped, so nothing further is lost here.

Every practical implementation works in log space. This is why predict_log_proba exists in scikit-learn, which you will use in lab 6.

Question 1 of 2

In add-one smoothing for Naïve Bayes, what is the |V| added to the denominator?

Correct answer: distinct word types across all classes together.

Both classes use the same |V|, which is 20 in our example. If each class is given its own vocabulary, the two scores are computed over different sets of possible words and cannot meaningfully be compared. The resulting numbers still appear reasonable, which is why this error often goes unnoticed.

Question 2 of 2

Why does working in log space not change which class the classifier picks?

Correct answer: the log function is monotonic, so it preserves score order.

A larger number always has a larger logarithm, so the winning class cannot change. That is the entire argument: logarithms address underflow and are not a modelling decision. Note that the last option is incorrect, since the two classes are not shifted by the same amount, and they do not need to be.

Summary

The main points

Training a Naïve Bayes classifier requires two sets of counts: the prior, from document counts, and the likelihoods, from word counts within each class's combined text. Left unsmoothed, these counts produce zeros that leave both classes scoring nothing. Add-one smoothing corrects this, using the whole training vocabulary in the denominator. Unknown words are dropped, and the products are computed as sums of logarithms so that they do not underflow.

This completes sentiment analysis with Naïve Bayes and the second block of Unit II. We now have a classifier that learns from labelled examples rather than from a hand-written lexicon, which is what VADER's failure on nightmare in lab 1 called for.

One further point before moving on. Consider what was done to the documents: word order was discarded and a count was kept for each word. We have not named that operation, but it is a method for representing a document as numbers, and it is not specific to classification. Search, similarity, and recommendation all require the same thing. Session 17 names it and develops it into a vector representation.
