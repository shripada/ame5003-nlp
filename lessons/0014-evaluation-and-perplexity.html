Judging a language model: perplexity

We have built three models and have no way to say which is best. The measure that settles it is a single number, but it means something only when computed on text the model has never seen.

The problem of comparing models

Over the last three sessions we built a working n-gram language model, and in doing so accumulated several choices that we have no means of settling:

  • Bigram or trigram?
  • Add-one, backoff, or interpolation?
  • If interpolation — which λ values?

Each of these is an empirical question, and none can be resolved by argument. We need a way to compare two models and determine which is better, which is the subject of this session.

Extrinsic evaluation

A language model is rarely the final product. It is a component within a larger system, such as a speech recogniser, a translation system, or a spelling corrector. The definitive test therefore follows directly: place model A inside the system and measure the system's performance, then substitute model B and measure again. The model producing the better system is the better model.

This is called extrinsic evaluation, and it is the only kind that actually answers the question you care about.SLP3 3rd ed., §3.2: extrinsic evaluation is "the only way to know if a particular improvement in the language model … is really going to help the task at hand". It is also expensive. Running a full speech recogniser over a test corpus twice can take hours or days, and we may need to compare twenty models rather than two. Tuning λ by this method is not feasible.

We therefore also want an inexpensive measure, one that scores the language model on its own with no application attached. Such a measure is an intrinsic evaluation. The standard intrinsic measure for language models is perplexity, which is the subject of the remainder of this session.

Extrinsic and intrinsic evaluation compared

Intrinsic evaluation is inexpensive and approximate; extrinsic evaluation is expensive and definitive. Perplexity is a proxy for the quantity we actually care about. It is a good proxy, which is why it is universally used, but a model with better perplexity does not always improve the system built around it. We return to this point at the end of the session.

Splitting the data

One point must precede any measurement: a model cannot be evaluated on the text it was trained on. The purpose of a language model is to predict text it has not seen. Scored on its own training corpus, it is being asked to recall rather than to predict, and it will appear far better than it is.

The corpus is therefore divided into three parts, serving three different purposes:

setwhat it is forhow often you touch it
training setget the counts; learn the probabilitiesconstantly
development set (devset)choose between models; tune λ, k, nas often as you like
test setthe final, honest numberonce, at the very end

The training and test split is widely known. The development set is more often omitted, and the reason for it is less obvious. Even if the test set is never used for training, evaluating on it fifty times while adjusting λ allows its particular characteristics to influence those choices, and the result is a model tuned to that specific text. All such adjustment is therefore carried out on the development set, and the test set is used once.

This also explains the held-out set from session 13, from which the λ values for interpolation were obtained. A held-out set is exactly this: data withheld from training so that it can answer a question the training data cannot answer without bias.

Training on the test set

Allowing test sentences into the training corpus is a specific and named error: training on the test set, also called data contamination. It does not produce a small error but excellent numbers that mean nothing, because the model is being scored on its capacity to recall.

It occurs easily by accident, through duplicate documents in a scraped corpus or a shuffled split that places two halves of the same article on both sides. It should be checked for explicitly. When a result is reported, the first question to ask is what it was measured on.

What "better" means

Consider the test set, a body of text the model has never seen. Both models can assign it a probability, in the same way that session 12 assigned a probability to a sentence. The criterion is then straightforward.

The criterion

The better model is the one assigning higher probability to the test set. Higher probability means the model was less surprised by real text, which is precisely the ability we want a language model to have.

This is already a usable measure. It has one defect, and correcting that defect yields perplexity.

Probability decreases with sentence length

A sentence probability is a product of numbers below 1, so each additional word makes it smaller. A 10-word test set yields a value of about 0.0001, while a 1,000-word test set yields a number with hundreds of zeros after the decimal point. The magnitude of the number therefore reflects mainly the length of the text rather than the quality of the model.

The correction is to normalise by length, dividing out the effect of the token count, so that what remains is a per-word figure comparable across texts of different sizes.

Perplexity

Perplexity is the probability of the test set, inverted, and normalised per token:

PP(W)=P(w1w2…wN)−1/N=1P(W)N

Two separate operations are combined in this expression, and it is worth distinguishing them:

  • The −1 inverts the probability, so that a high probability becomes a low number. Lower perplexity is therefore better, which is the most commonly misremembered property of the measure.
  • The 1/N takes the N-th root, which removes the effect of length, converting a whole-text probability into a per-token quantity.
What N counts

N is the number of tokens the model predicted — so it includes </s> and excludes <s>. Exactly the same rule that made V=10 rather than 11 last session: <s> is only ever context, never a prediction.

Our four-sentence corpus contains 26 such tokens. If N is wrong, every perplexity computed below is wrong as well, and nothing will indicate the error.

Perplexity as a branching factor

Perplexity admits an interpretation that makes it considerably less abstract: it is approximately the number of choices the model was effectively selecting between at each step, its average branching factor.

Consider the simplest possible model over our vocabulary of V=10, one that has learned nothing and treats every next token as equally likely with probability 1/10. Its perplexity on any test text is exactly 10:

PP=((110)N)−1/N=10

The value is ten because at every position the model selects blindly among ten options. This is the standard any real model must improve on. A model with perplexity 4 over the same vocabulary has reduced ten options to roughly four, and a perplexity of 1 would mean it identified the next word exactly every time.

This is a reference point rather than an upper bound. A model can score worse than 10 by being confidently wrong, placing most of its probability on words that do not then appear. Guessing uniformly is not the worst possible performance, only the performance obtainable without effort.

This is why perplexity is described as a weighted branching factor. The raw branching factor counts the available options, whereas perplexity weights them by probability, so a model that formally permits ten words but concentrates most of its probability on one of them receives a low score.

Four perplexity values from our corpus

We use the same four sentences as sessions 11 to 13. The four measurements that follow constitute a single argument rather than four separate examples.

<s> I want to eat Indian food </s>
<s> I want to eat Chinese food </s>
<s> I want Indian food </s>
<s> she wants to eat Indian food </s>

1 · The model that knows nothing → 10

This value was established above and serves as our reference point: any real model must improve on 10.

2 · The trained bigram model, on a training sentence → 1.17

Session 12 scored I want to eat Indian food at 1/3. It has 7 predicted tokens (I want to eat Indian food </s>), so:

PP=(13)−1/7=31/7=1.17

The value is 1.17 against a reference of 10, so the model is behaving as though it identified the next word almost exactly at every step.

Why this number is not a good result

A value of 1.17 does not indicate an excellent model. It indicates that the model was scored on a sentence from its own training data and reproduced it. The model is recalling rather than predicting.

This is how data contamination presents in practice: not as an obvious error but as an implausibly good result. A perplexity that appears too good usually indicates a flawed experiment rather than a strong model.

3 · A genuine test sentence, MLE → infinite

We therefore repeat the measurement correctly, using a sentence the model has never seen that is composed entirely of words it does know: I want Chinese food. All four words are in the vocabulary.

P(I want Chinese food)=34×33×03×11×44=0

The third factor is zero because count(want Chinese)=0, and the perplexity that follows is a division by zero:

PP=0−1/5=10=∞

The perplexity is infinite. This is not a large number but an undefined one, arising from division by zero, and the sentence itself is perfectly ordinary; it merely pairs two words the corpus never placed together.

This is session 13's zero problem with its consequences made explicit. The difficulty is not only that an unsmoothed model produces implausible estimates. It cannot be evaluated at all. A single unseen pair anywhere in a test set of a million words sends the perplexity of the entire set to infinity. Smoothing is not an optional refinement; without it there is no number to report.

4 · The same sentence, add-one smoothed → 4.69

We now apply session 13's add-one estimate, (count(w1w2)+1)/(count(w1)+V), with V=10:

bigramcountsadd-one probability
<s> I 3 / 44/14 = 0.286
I want 3 / 34/13 = 0.308
want Chinese 0 / 31/13 = 0.077
Chinese food 1 / 12/11 = 0.182
food </s> 4 / 45/14 = 0.357
P=414×413×113×211×514=0.000439PP=0.000439−1/5=4.69

The result is 4.69, and this number is meaningful. Over a vocabulary of 10, the model behaves as though selecting between roughly five options at each step rather than ten. From four sentences of training text, this is a legitimate result.

Which of the four is a genuine result

Only the last row. The other three each demonstrate a condition required to obtain one: the score of a model that has learned nothing, the appearance of a score computed on training data, and the consequence of omitting smoothing.

One qualification applies throughout: perplexity is normally computed over a whole test set rather than a single sentence. The probabilities of all its sentences are multiplied together and N is the total token count. Single sentences are used here only because four training sentences are all we have. A test set of one sentence would be of no practical value, being far too small to be representative.

Perplexity values in practice

Our values are small because the vocabulary contains ten words. The same experiment at realistic scale, taken from the textbook, uses unigram, bigram, and trigram models trained on 38 million words of Wall Street Journal text and scored on a 1.5-million-word test set.SLP3 3rd ed., §3.3. Figures read from the live chapter, August 2026.

modelperplexity
unigram962
bigram170
trigram109

Read as branching factors, these values are informative. The unigram model, which ignores context entirely, selects among roughly a thousand options at each word. Knowing one previous word reduces this to 170, and knowing two reduces it to 109. This is the claim that more context helps, expressed as a measurement rather than an assertion.

The figures also show diminishing returns: the first word of context contributes far more than the second. The trend cannot continue indefinitely, since a 10-gram model would have almost no counts available, so the improvements cease. More context helps only while sufficient data remains to estimate it.

Three ways perplexity can mislead

Perplexity is a good measure, and it is also easy to misuse, in three specific ways.

1 · Two perplexities are only comparable on the same test set and the same vocabulary

Perplexity depends on both the model and the text. A model scored on easy text obtains a lower value than a better model scored on difficult text. Comparing perplexities taken from two different papers, two different test sets, or two different tokenizers is therefore uninformative.

2 · <UNK> can be gamed

This one follows directly from last session. Suppose you shrink your vocabulary so that most words get replaced by <UNK>. The model now has very few things to choose between, so it predicts confidently and perplexity drops sharply — while the model has actually become less useful, because it no longer distinguishes the words it threw away.

A perplexity figure is therefore meaningful only when reported together with its vocabulary size and its <UNK> policy. Quoted on its own, it can be made to support almost any claim.

3 · Better perplexity does not guarantee a better system

This returns us to the opening of the session. Perplexity is an inexpensive proxy for extrinsic evaluation, and a proxy is not the quantity itself. A model can predict text slightly better on average without altering a single decision made by the speech recogniser.SLP3 3rd ed., §3.3: "An (intrinsic) improvement in perplexity does not guarantee an (extrinsic) improvement in the performance of a language processing task."

The practice that follows is to use perplexity routinely, since it is fast and generally correct about large differences, and then to confirm the decision that matters with an end-to-end test.

Exercise

Session 12 scored two sentences: I want Indian food at 1/4 = 0.250 and she wants to eat Indian food at 1/6 = 0.167. By raw probability the first ranks higher. What does perplexity give? Take N as 5 and 7 respectively.

PP(I want Indian food)=(14)−1/5=41/5=1.320PP(she wants to eat Indian food)=(16)−1/7=61/7=1.292

Perplexity reverses the ranking. The longer sentence had the lower raw probability but the better per-token score, having simply two more words to account for. Raw probability was partly measuring length, and perplexity divides that effect out.

This is the −1/N term operating as intended. Note, however, what it is for: length normalisation is what permits comparison of a model's performance across test sets of different sizes. Perplexity is a measure of models, not a ranking of sentences, and it should not be understood as a method for deciding which sentence is better English.

Question 1 of 3

A model gets perplexity 1.2 on the corpus it was trained on. What does that tell you?

Correct answer: almost nothing — it was scored on text it memorised.

Perplexity computed on training data measures recall rather than prediction and is always misleadingly low. It indicates a flawed experiment rather than a good model. The only figure worth reporting comes from held-out data the model has never seen.

Question 2 of 3

Why is the perplexity of an unsmoothed model on a real test set usually infinite?

Correct answer: one unseen n-gram makes P = 0, and perplexity inverts it.

The test-set probability is a product, so a single zero anywhere reduces the whole product to zero, and perplexity raises that to a negative power, which is division by zero. Any real test set contains unseen n-grams, which is why an unsmoothed model cannot be evaluated at all.

Question 3 of 3

Model A has perplexity 140 and model B has perplexity 95. Which is the better language model?

Correct answer: model B, if both were measured on the same test set with the same vocabulary.

Lower is better, so model B, but only under that condition. Perplexity depends on the text as well as on the model, and reducing the vocabulary lowers it without any improvement to the model. Without matching conditions the two numbers do not measure the same quantity.

Summary

The main points

Perplexity is the test-set probability, inverted and normalised per token, so that lower values are better. It can be read as the average number of words the model was effectively choosing between. The value is meaningful only if computed on text the model was not trained on: measured on training data it appears excellent and means nothing, and measured without smoothing it is infinite.

This completes the n-gram language model: count, assume a short history, smooth, and measure. Every choice left open earlier — bigram or trigram, which smoothing method, which λ values — can now be settled by building both alternatives and comparing perplexity on a development set.

Session 15 changes the question. Instead of asking how likely a piece of text is, we ask what it is about: whether a given review is positive or negative. The probability machinery carries over directly, applied to a different target.
