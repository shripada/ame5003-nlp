Judging a language model: perplexity

We have built three models and cannot say which is best. The fix is one number — but it only means anything if you measure it on text the model has never seen.

Three models and no way to choose

Over the last three sessions we built a working n-gram language model, and along the way we collected a pile of choices with no way to settle any of them:

  • Bigram or trigram?
  • Add-one, backoff, or interpolation?
  • If interpolation — which λ values?

Every one of those is an empirical question, and none of them can be answered by arguing. We need a way to put two models side by side and say this one is better. That is what this hour is for.

The honest way to measure, and why we cannot afford it

A language model is almost never the product. It is a part inside something else — a speech recogniser, a translation system, a spelling corrector. So the real test is obvious: put model A inside the system, measure how well the system does; swap in model B, measure again. Better system wins.

This is called extrinsic evaluation, and it is the only kind that actually answers the question you care about.SLP3 3rd ed., §3.2: extrinsic evaluation is "the only way to know if a particular improvement in the language model … is really going to help the task at hand". It is also expensive. Running a full speech recogniser over a test corpus twice can take hours or days, and you may want to compare twenty models, not two. You cannot tune λ that way.

So we also want a cheap measure — one that scores the language model on its own, with no application attached. That is an intrinsic evaluation. The standard intrinsic measure for language models is perplexity, and it is what the rest of this hour is about.

Keep the trade in view

Intrinsic is cheap and approximate; extrinsic is expensive and true. Perplexity is a stand-in for the thing you actually want. It is a good stand-in, which is why everyone uses it — but a model with better perplexity does not always make the system around it better. We come back to this at the end, and it matters more than it sounds.

First, split the data

Before any measuring: you cannot evaluate a model on the text it was trained on. The whole point of a language model is to predict text it has not seen. Scored on its own training corpus it is being asked to remember, not to predict, and it will look far better than it is.

So the corpus is cut into three parts, used for three different jobs:

setwhat it is forhow often you touch it
training setget the counts; learn the probabilitiesconstantly
development set (devset)choose between models; tune λ, k, nas often as you like
test setthe final, honest numberonce, at the very end

The training/test split is the one everybody knows. The devset is the one people skip, and the reason it exists is subtler. Even if you never train on the test set, testing on it fifty times while you fiddle with λ lets its quirks leak into your choices. You end up tuned to that particular text. So all the fiddling happens on the devset, and the test set is opened once.

This also finally explains the held-out set from last session, where the λ values for interpolation came from. A held-out set is exactly this: data kept out of training so it can answer a question training data cannot answer honestly.

Training on the test set

Letting test sentences into the training corpus is a specific, named mistake — training on the test set, also called data contamination. It does not produce a small error. It produces beautiful numbers that mean nothing, because the model is being scored on its ability to recall.

It is easy to do by accident: duplicate documents in a scraped corpus, a shuffled split that puts two halves of the same article on both sides. Check for it. And when someone reports a result, the first question is always what was it measured on?

What "better" means

Take the test set — a lump of text the model has never seen. Both models can assign it a probability, the same way session 12 assigned a probability to a sentence. The rule is then as simple as it could be:

The whole criterion

The better model is the one that assigns higher probability to the test set. Higher probability means it was less surprised by real text — which is precisely what we wanted a language model to be good at.

That is already a usable measure. It has one flaw, and fixing the flaw gives us perplexity.

The flaw: probability shrinks with length

A sentence probability is a product of numbers below 1, so every extra word makes it smaller. Score a 10-word test set and you get something like 0.0001; score a 1,000-word test set and you get a number with hundreds of zeros after the decimal point. The size of the number is mostly telling you how long the text was, not how good the model is.

The fix is to normalise by length — divide out the effect of the token count, so what is left is a per-word figure that texts of different sizes can be compared on.

Perplexity

Perplexity is the probability of the test set, inverted, and normalised per token:

PP(W)  =  P(w₁ w₂ … w_N) ^ (−1/N)

       =  the N-th root of  1 / P(W)

Two things are happening in that one expression, and they are worth separating:

  • The −1 inverts it. High probability becomes a low number. So lower perplexity is better — this is the single most common thing to get backwards.
  • The 1/N takes the N-th root, which is what cancels out the length. It turns a whole-text probability into a per-token one.
What N counts

N is the number of tokens the model predicted — so it includes </s> and excludes <s>. Exactly the same rule that made V = 10 rather than 11 last session: <s> is only ever context, never a prediction.

Our four-sentence corpus has 26 such tokens. Get N wrong and every perplexity below is wrong, quietly.

What the number means: branching factor

Perplexity has a reading that makes it far less abstract. It is roughly the number of choices the model felt it had at each step — its average branching factor.

Take the simplest possible model over our vocabulary of V = 10: one that has learned nothing and calls every next token equally likely, probability 1/10 each. Its perplexity on any test text works out to exactly 10.

PP  =  ((1/10)^N) ^ (−1/N)  =  10

Ten, because at every position the model is choosing blindly between ten options. That is the bar any real model has to clear. A model with perplexity 4 on the same vocabulary has narrowed ten options down to about four. A perplexity of 1 would mean it knew the next word exactly, every time.

It is a bar, not a ceiling: a model can score worse than 10 here, by being confidently wrong — putting most of its probability on words that then do not appear. Guessing blindly is not the floor of performance, only the floor of effort.

This is why perplexity is described as weighted branching factor. The raw branching factor just counts the options; perplexity weights them by probability, so a model that technically allows ten words but puts most of its probability on one of them gets a low score.

Four numbers from our corpus

Same four sentences as sessions 11–13. Watch what happens across these four measurements — they are one argument, not four examples.

<s> I want to eat Indian food </s>
<s> I want to eat Chinese food </s>
<s> I want Indian food </s>
<s> she wants to eat Indian food </s>

1 · The model that knows nothing → 10

Established above. This is our reference point: any real model has to beat 10.

2 · The trained bigram model, on a training sentence → 1.17

Session 12 scored I want to eat Indian food at 1/3. It has 7 predicted tokens (I want to eat Indian food </s>), so:

PP  =  (1/3) ^ (−1/7)  =  3 ^ (1/7)  =  1.17

1.17 out of a possible 10. The model is behaving as though it knew the next word almost perfectly at every step.

That number is not good news — it is the warning

1.17 does not mean we built an excellent model. It means we scored the model on a sentence it was trained on, and it recited it back. It is not predicting; it is remembering.

This is what data contamination looks like from the inside: not an obvious error, just a suspiciously good result. A perplexity that looks too good is usually a broken experiment, not a breakthrough.

3 · A genuine test sentence, MLE → infinite

So let us do it properly. Here is a sentence the model has never seen, built entirely from words it does know — I want Chinese food. All four words are in the vocabulary.

P(I want Chinese food)
  =  3/4  ×  3/3  ×  0/3  ×  1/1  ×  4/4       ← count(want Chinese) = 0
  =  0

PP  =  0 ^ (−1/5)  =  1/0  =  ∞

Infinite perplexity. Not a large number — undefined, dividing by zero. And the sentence is perfectly ordinary; it just happens to pair two words the corpus never put together.

This is session 13's zero problem arriving with consequences attached. It is not only that an unsmoothed model gives silly answers. You cannot evaluate it at all. One unseen pair anywhere in a test set of a million words sends the perplexity of the whole thing to infinity. Smoothing is not a nicety; without it there is no number to report.

4 · The same sentence, add-one smoothed → 4.69

Now use last session's add-one estimate, (count(w₁w₂) + 1) / (count(w₁) + V) with V = 10:

bigramcountsadd-one probability
<s> I 3 / 44/14 = 0.286
I want 3 / 34/13 = 0.308
want Chinese 0 / 31/13 = 0.077
Chinese food 1 / 12/11 = 0.182
food </s> 4 / 45/14 = 0.357
P  =  4/14 × 4/13 × 1/13 × 2/11 × 5/14  =  0.000439

PP =  0.000439 ^ (−1/5)  =  4.69

4.69, and now the number is worth something. On a vocabulary of 10, the model behaves as if it were choosing between roughly five options at each step rather than ten. From four sentences of training text, that is an honest result.

The last row. The other three are each a lesson about how to get one: what a model that knows nothing scores, what scoring on training data looks like, and what happens when you skip smoothing.

One caveat on all of it: perplexity is normally computed over a whole test set, not a single sentence — you multiply the probabilities of all its sentences together and N is the token count of the lot. Single sentences are used here only because four training sentences is all we have. A test set of one sentence would be worthless in practice: far too small to be representative.

Read that as branching factor and it tells a clear story. The unigram model — which ignores context entirely — is picking between roughly a thousand options at each word. Knowing one previous word cuts that to 170. Knowing two cuts it to 109. That is what "more context helps" looks like as a measurement instead of an opinion.

It also shows the diminishing return: the first word of context buys far more than the second. And the trend cannot continue for ever — a 10-gram model would have almost no counts to work from, so the gains stop arriving. More context only helps while you still have enough data to estimate it.

Three ways perplexity misleads you

It is a good measure. It is also easy to misuse, in three specific ways.

1 · Two perplexities are only comparable on the same test set and the same vocabulary

Perplexity depends on the model and the text. A model scored on easy text gets a lower number than a better model scored on hard text. Comparing perplexities from two different papers, two different test sets, or two different tokenizers tells you nothing at all.

2 · <UNK> can be gamed

This one follows directly from last session. Suppose you shrink your vocabulary so that most words get replaced by <UNK>. The model now has very few things to choose between, so it predicts confidently and perplexity drops beautifully — while the model has actually become less useful, because it no longer distinguishes the words it threw away.

So a perplexity figure is only meaningful alongside its vocabulary size and its <UNK> policy. Quoted alone, it can be made to say almost anything.

3 · Better perplexity does not guarantee a better system

Back to where we started. Perplexity is the cheap stand-in for extrinsic evaluation, and the stand-in is not the thing. A model can predict text slightly better on average and still not change a single decision the speech recogniser makes.SLP3 3rd ed., §3.3: "An (intrinsic) improvement in perplexity does not guarantee an (extrinsic) improvement in the performance of a language processing task."

The working practice is: use perplexity constantly, because it is fast and it is usually right about the big differences; then confirm the choice that matters with a real end-to-end test.

Think about this before reading on

Session 12 scored two sentences: I want Indian food at 1/4 = 0.250 and she wants to eat Indian food at 1/6 = 0.167. By probability, the first is the clear winner. What does perplexity say? (N is 5 and 7.)

PP(I want Indian food) = (1/4)^(−1/5) = 4^(1/5) = 1.320
PP(she wants to eat Indian food) = (1/6)^(−1/7) = 6^(1/7) = 1.292

Perplexity reverses the ranking. The longer sentence had the lower raw probability but the better per-token score — it just had two more words to pay for. Raw probability was partly measuring length; perplexity divides that out.

That is the −1/N doing its job. But note what this is for: length normalisation is what lets you compare a model's performance on test sets of different sizes. Perplexity is a measure of models, not a ranking of sentences — do not walk away thinking its purpose is to decide which sentence is better English.

Question 1 of 3

A model gets perplexity 1.2 on the corpus it was trained on. What does that tell you?

Correct answer: almost nothing — it was scored on text it memorised.

Perplexity on training data measures recall, not prediction, and it is always flatteringly low. It is a broken experiment, not a good model. The only figure worth reporting comes from held-out data the model has never seen.

Question 2 of 3

Why is the perplexity of an unsmoothed model on a real test set usually infinite?

Correct answer: one unseen n-gram makes P = 0, and perplexity inverts it.

The test-set probability is a product, so a single zero anywhere collapses the whole thing to zero — and perplexity raises that to a negative power, which is division by zero. Any real test set contains unseen n-grams. That is why you cannot evaluate an unsmoothed model at all.

Question 3 of 3

Model A has perplexity 140 and model B has perplexity 95. Which is the better language model?

Correct answer: model B, if both were measured on the same test set with the same vocabulary.

Lower is better, so B — but only under that condition. Perplexity depends on the text as well as the model, and shrinking the vocabulary lowers it for free. Without matching conditions the two numbers are not measuring the same thing.

The one thing to remember

The whole lesson in two sentences

Perplexity is the test-set probability inverted and normalised per token, so lower is better, and it reads as the average number of words the model thought it was choosing between. The number is only worth anything if it came from text the model never trained on — measured on training data it looks wonderful and means nothing, and measured without smoothing it is infinite.

That completes the n-gram language model: count, assume a short history, smooth, and now measure. Every choice we left open — bigram or trigram, which smoothing, which λ — is now answerable by building both and comparing perplexity on a devset.

Next session changes the question. Instead of asking how likely a piece of text is, we ask what it is about — is this review positive or negative? The probability machinery carries straight over, pointed at a new target.
