The bottleneck, and attention as the fix

Session 27 ended on a problem: one fixed-size vector carrying an entire source sentence. The fix is a single change of subscript, and the three operations it needs are all operations this course already taught.

Where session 27 stopped

Last session closed on a table and refused to say what came next. The table said that at d=300, the decoder receives 300 numbers whether the source was four words or fifty, and that nothing in the architecture notices the difference. SLP3's §13.8 opens on exactly that:

SLP3 §13.8

"This final hidden state is thus acting as a bottleneck: it must represent absolutely everything about the meaning of the source text, since the only thing the decoder knows about the source text is what's in this context vector."

Bahdanau states the same problem in his own words, and the phrasing is worth having alongside SLP3's: attention exists to "relieve the encoder from the burden of having to encode all information in the source sentence into a fixed-length vector."

Note what both sentences locate the fault in. It is not that c is a bad summary — it is that the decoder has no other route to the source. The encoder computed a hidden state for every source word, and then the architecture threw all of them away except the last. The fix is going to be, more or less literally, stop doing that.

The whole change is one subscript

Put both decoder equations side by side. The top one is session 27's, and the bottom one is this session's:

decoder recurrenceSLP3 eq.
session 27hid=g(yˆi−1,hi−1d,c)(13.32)
session 28h^d_i = g(ŷ_{i-1}, h^d_{i-1}, c_i) (13.34)

c became c_i. That is the entire architectural change. The context is no longer one vector computed once and reused; it is a different vector at every decoder step, computed fresh each time the decoder is about to emit a word.

Everything else is untouched. Same encoder, same decoder, same unit inside both boxes, same cross-entropy loss, same teacher forcing, same end-of-sequence token. If you learned session 27, you have learned all of this session except one thing: how c_i gets computed. The rest of the hour answers that.

Why the subscript is enough

Session 27's c was h^e_n, so it could not depend on where the decoder had got to — it was fixed before the decoder started. A c that carries an i can depend on the decoder's current state, which means it can be about the word being produced right now. The decoder about to emit the verb can be given a context assembled around the verb. That capability is what the subscript buys, and it is not available at any price when the context is computed once.

How c_i is computed: three operations, none of them new

Say the name of each operation before its equation, because the names are all familiar and that is the point:

Read the three lines as one sentence: score every source position for relevance to where I am now, turn the scores into a distribution, and take the weighted average of the source representations under it. There is no new mathematics in this session. There is a new arrangement of arithmetic the course has had for weeks.

SLP3 calls (13.35) dot-product attention, and describes what it is doing as treating "relevance as similarity". That is session 19's sentence almost word for word: two vectors pointing the same way have a large dot product, and here the two vectors are a decoder state and an encoder state. The decoder asks which source positions look like what it is currently trying to say.

This dot product is not normalised, and you are right to object

Session 19 established that a raw dot product favours long vectors, which is why cosine similarity divides by both lengths. Equation (13.35) divides by nothing. An encoder state that happens to have a large norm scores highly against everything, regardless of direction.

That is a real weakness, not an oversight in the notes. It is fixed in session 29, where the same dot product is divided by dk before the softmax, and where you will see what goes wrong when it is not. Hold the objection; do not discard it.

Bahdanau does not use this scoring function

The paper assigned with this session computes the score with a small feedforward network instead: a(si−1,hj)=va𝖳tanh⁡(Wasi−1+Uahj), which he describes as "a feedforward neural network which is jointly trained with all the other components". So the formula in the reading is not the formula on the board. The role is identical — take a decoder state and an encoder state, return one number — and the three-step structure is unchanged. What differs is whether the score has learned parameters, which is the subject of the last section of this lesson.

The worked example

Use session 27's sentence, so the two sessions interlock. The source was the green witch arrived, the target llegó la bruja verde, and the alignment was 4, 1, 3, 2 — which last session simply asserted, from the gloss. This session watches the mechanism find it.

Two dimensions, so every number below can be checked by hand. The encoder has run and produced four states, and the decoder is at its first step, about to emit llegó — the Spanish for arrived:

he(the)=[2,1]he(green)=[1,2]he(witch)=[−1,2]he(arrived)=[2,−1]
h0d=[2,−1]

That last vector is the query: where the decoder is, before emitting anything.

Compare that against he(arrived)=[2,−1].

Three things to take from those numbers, in this order.

One: the alignment was computed, not supplied. The context the decoder receives before emitting llegó is, to three decimal places, the hidden state of the source word arrived. Nobody told the model that Spanish position 1 corresponds to English position 4. Session 27's alignment fell out of a dot product and a softmax.

Two: it is a blend, not a choice. c1 is not he(arrived); it is near it, pulled slightly by the at weight 0.119. No mechanism here selects a source word. Every encoder state contributes at every step, and some contribute almost nothing. This is why the mechanism is sometimes called soft attention, and it is what makes it differentiable — a mechanism that picked a word could not be trained by gradient descent, because there is no derivative of a choice.

Three: the weights are where all the work happens. Suppose the α were uniform, 0.25 each — which is exactly the average-the-states pooling session 23 used for sequence classification. Then:

c=0.25⋅([2,1]+[1,2]+[−1,2]+[2,−1])=[1.000,1.000]

That is nothing like he(arrived)=[2,−1]; it does not point at any source word in particular, which is precisely what an average is for. Strip the weights out and equation (13.37) degenerates into the pooling session 23 already showed loses the thing you wanted. Attention is not "look at all the states" — session 27 could have averaged the states. It is "look at all the states in proportions that depend on where you are."

Exercise

The same four encoder states. The decoder has now emitted llegó la bruja and is at its last step, about to emit verde — the Spanish for green. Its state is h3d=[1,2].

Compute the four scores and the four weights α4j. Then say which source position the context now sits on, and whether the mechanism is more or less confident than it was at step 1.

Scores against h3d=[1,2]: the gives 2⋅1+1⋅2=4; green gives 1⋅1+2⋅2=5; witch gives −1⋅1+2⋅2=3; arrived gives 2⋅1+(−1)⋅2=0.

Exponentiating: 54.598, 148.413, 20.086, 1.000, summing to 224.097. So

α4(the)=0.2436α4(green)=0.6623α4(witch)=0.0896α4(arrived)=0.0045

and c4=[1.069,1.743], sitting near he(green)=[1,2]. The mass has moved from source position 4 to source position 2, which is the alignment 4, 1, 3, 2 — the fourth Spanish word comes from the second English word. The mechanism was re-run, and the pattern moved.

It is less confident: 0.662 here against 0.876 at step 1. The reason is visible in the scores — the scored 4 against green's 5, because he(the)=[2,1] and he(green)=[1,2] point in fairly similar directions. When two source states look alike, the softmax cannot separate them sharply, and the context is a genuine mixture of the two. That is the mechanism behaving correctly, not failing.

Question 1 of 2

What is the difference between the plain encoder-decoder of session 27 and the attention-based one?

Correct answer: the context is recomputed per step from all the encoder states. That is the move from c in (13.32) to c_i in (13.34), and everything else in this lesson is the recipe for computing it.

The first option is worth care, because it is true of Bahdanau's paper and of lab 10's code — his §3.2 makes the encoder bidirectional deliberately, so that each annotation summarises the following words as well as the preceding ones. It is simply not the mechanism. Attention works perfectly well over a unidirectional encoder, and equations 13.35–13.37 never mention direction. The third describes something no one does: concatenation would give the decoder a variable-size input, which is exactly what fixed-size vectors exist to avoid. The fourth is session 27 — that is what equation (13.32) already did, and if you chose it, reread the callout on why c appeared twice last session.

Now be precise about what is not being claimed, because the sloppy version of this sentence causes trouble in session 29.

What is and is not fixed

c_i is still a single fixed-size vector. It is still 300 numbers, and the decoder still consumes it one vector at a time. Nothing about the decoder's input width changed.

What changed is where those 300 numbers come from. In session 27 they were computed once, from h^e_n, before the decoder ran — so whatever did not survive the encoder chain was gone. Now they are computed afresh at each step from all of h^e_{1:n}, so every source position remains reachable for the entire decode. The bottleneck was never the size of c; it was that one c had to serve every target word.

A score with parameters

One loose end. Dot-product attention, (13.35), has no parameters at all — it is a fixed arithmetic operation, and there is nothing in it for training to adjust. That is elegant, and it is also a limitation: the model cannot learn what kind of similarity should count as relevance. It gets whatever similarity the encoder and decoder representations happen to express.

So SLP3 gives a second scoring function, the bilinear form:

score(h^d_{i-1}, h^e_j) = h^d_{i-1} W_s h^e_j              (13.38)

W_s is a weight matrix, trained end-to-end with everything else, and it "gives the network the ability to learn which aspects of similarity between the decoder and encoder states are important to the current application." Steps two and three are unchanged; only the score is different.

There is also a practical reason this is the form real implementations use. A plain dot product requires h^d and h^e to have the same dimensionality — you cannot dot a 512-vector with a 300-vector. W_s is rectangular, so the encoder and the decoder may be sized independently.

Handing over to session 29

Attention as taught here is a decoder attending to an encoder: two different sequences, one asking and one answering. SLP3 closes §13.8 by pointing forward — "We'll return to the concept of attention when we define the transformer architecture, which is based on a slight modification of attention."

The modification is to point the same three operations — score, softmax, weighted average — at one sequence attending to itself, so that each position gathers from every other position in the same sentence. That is self-attention, and it turns out that once each position can reach every other position directly, the recurrence has nothing left to do. Sessions 25 and 26 both closed on a limitation neither the LSTM nor the GRU could fix: a sequence must be processed one step at a time, so it cannot be parallelised, and distant positions are still distant. Session 29 removes both, and it does it with the machinery you have just learned.

Question 2 of 2

What are the attention weights αij?

Correct answer: they are computed, by a softmax over the scores, and they form a distribution over source positions — the four in the worked example summed to 1.0000.

The first is the most common misunderstanding of attention and the one to rule out hardest. Nothing about the α is stored. They are recomputed from scratch at every decoder step of every sentence, and they must be, since a model with learned per-position weights could not handle a sentence of a length it had not seen. The fourth confuses the two: W_s is learned, and it is a parameter of the score — but the α are the softmax of the score's output, not the score's parameters. The second describes a heuristic nobody needs here; the weights depend on content, which is why they landed on arrived at step 1 and on green at step 4.

The main points

The plain encoder-decoder forces every source word to reach the decoder through one fixed vector, and SLP3 names it a bottleneck: the only thing the decoder knows about the source is what is in c. Attention changes one subscript — c becomes c_i, equation (13.32) becomes (13.34) — so the context is recomputed at every decoder step; nothing else in the architecture moves. It is computed in three steps, all previously taught: score each encoder state against the decoder's current state with a dot product (13.35), softmax the scores into weights that sum to 1 (13.36), and take the weighted average of the encoder states (13.37). In the worked example the decoder about to emit llegó put weight 0.876 on arrived, recovering session 27's alignment by arithmetic rather than stipulation; the weights are what does the work, since uniform weights collapse the whole thing into session 23's pooling. The weights are computed, never stored. The result is that all n encoder states stay reachable for the whole decode rather than 300 numbers standing in for all of them — though c_i is itself still one fixed-size vector. The dot product is unnormalised, which session 29 fixes; the bilinear score (13.38) adds a trained W_s, and Bahdanau's paper uses a third, additive, scoring function.

Reading

Speech and Language Processing, §13.8 — equations 13.34 to 13.38, with the same numbering used above. It is short, it opens on the sentence quoted at the top of this lesson, and it finishes chapter 13.

Bahdanau, Cho and Bengio 2014, the paper that introduced this mechanism, with two differences from §13.8 flagged in advance so they do not read as contradictions:

  • His scoring function is additive, not the dot product. The alignment model is a(si−1,hj)=va𝖳tanh⁡(Wasi−1+Uahj) — "a feedforward neural network which is jointly trained with all the other components". The role is the same as (13.35); the parameters are not.
  • His encoder is bidirectional, and structurally so. §3.2 is titled "Encoder: Bidirectional RNN for Annotating Sequences", and the reason given is that "we would like the annotation of each word to summarize not only the preceding words, but also the following words." The argument is worth following: attention weights a position, so that position's representation had better summarise its whole context. This course has not taught bidirectional RNNs — they are SLP3 §13.4 — and the mechanism does not require them, but lab 10's encoder is bidirectional for exactly Bahdanau's reason.

§3 is the part to read closely; §4 and §5 are the WMT'14 English-to-French experimental setup and results, which you can skim. The exception is Figure 3, the alignment heat maps — look at those properly. They are this lesson's α table computed for real sentences, and the bright diagonal breaking wherever English and French disagree about word order is the 4, 1, 3, 2 of the worked example, found by a model nobody told about alignment.
