Multi-head attention, and positional embeddings

Session 29 removed the recurrence and got parallelism. The bill for that was word order, and this session pays it. Then the same mechanism is run several times side by side — which turns out to cost almost nothing, for a reason that is worth doing the arithmetic on.

The bill from last session

Session 29 ended on a debt. Self-attention computes each output as a weighted sum over pairs of positions, and nothing in that computation refers to where in the sentence anything sits. The mechanism treats its input as a set of vectors rather than a sequence of them. The recurrence used to handle order for free — an RNN reads the words one after another, so it cannot fail to represent their order — and session 29 threw the recurrence away to get parallelism.

So the first job of this session is to put order back. The second, independent job is multi-head attention. They are in that order because the first one is the answer to a question session 29 left open.

Permuting the sentence changes nothing

The claim is easy to state and easy to check. Take four tokens, give each a distinct embedding, run equations (8.10)–(8.13) from last session, and then run them again on a shuffled version of the same four tokens. Here the sentence is session 27's the green witch arrived, shuffled to arrived the witch green, with the causal mask dropped so that every position may see every other:

tokenoutput in the original orderoutput in the shuffled order
the(−0.285,−0.457,−0.542,0.435) (−0.285,−0.457,−0.542,0.435)
green(−0.319,−0.540,−0.538,0.466) (−0.319,−0.540,−0.538,0.466)
witch(−0.141,−0.297,−0.471,0.320) (−0.141,−0.297,−0.471,0.320)
arrived(−0.218,−0.403,−0.492,0.371) (−0.218,−0.403,−0.492,0.371)

Not similar — identical, to every digit. Each token's output moved to wherever that token moved to, and otherwise nothing happened. The reason is visible in the equations: a score is qi⋅kj, which depends on the two tokens and on nothing else, and a softmax over a set of scores does not care what order they arrived in. Shuffle the inputs and you get the same scores between the same pairs, and therefore the same outputs.

Set that against session 27, which opened by arguing that translation is not word-by-word substitution: the green witch arrived becomes llegó la bruja verde, an alignment of 4, 1, 3, 2. Word order is the problem that session was about. A model built only of self-attention cannot tell the witch arrived from arrived the witch, so it cannot be the whole model.

What the causal mask does and does not fix

Chapter 8's equations carry ∀j≤i, so a fair objection is that the model does know something about order: position 5 can see position 2 and not the other way round. True, and it is why the table above had to drop the mask to make the point cleanly.

But the mask knows precedence, not distance. It tells the model that j comes somewhere before i; it does not tell it that j is three words before i rather than thirty. Every weight is still computed from a dot product that contains no reference to position. Precedence alone will not distinguish the dog bit the man from the man bit the dog — both readings are consistent with the same set of "before" facts about different tokens.

Positional embeddings

SLP3 §8.4 asks where the input matrix X comes from, and the answer is that it is built from two embeddings, not one: "The transformer does this by separately computing two embeddings: an input token embedding, and an input positional embedding."

The token embedding is the one from session 21 — a row of the embedding matrix E, which has one row per vocabulary item and therefore shape [|V|×d]. The positional embedding is new. The simplest form, which SLP3 calls absolute position, is exactly what it sounds like:

SLP3 §8.4

"The simplest method, called absolute position, is to start with randomly initialized embeddings corresponding to each possible input position up to some maximum length. For example, just as we have an embedding for the word fish, we'll have an embedding for the position 3. As with word embeddings, these positional embeddings are learned along with other parameters during training. We can store them in a matrix Epos of shape [N×d]."

So there is a vector for "position 1", a vector for "position 2", and so on up to the context length N, and they are ordinary learned parameters, trained by the same gradient descent as everything else. Nothing tells the model in advance what position 3 means. It works out for itself what is worth storing there.

Added, not concatenated

This is the part worth slowing down on, because most people guess the other one. The positional vector is added to the token vector:

xi=E[id(i)]+Epos[i]

SLP3: "we just add the word embedding for each input to its corresponding positional embedding. The individual token and position embeddings are both of size [1×d], so their sum is also [1×d]." Stack those rows and you have X, of shape [N×d], which is the matrix session 29's packed equations (8.32)–(8.34) consumed.

The instinct that position should be appended — d numbers of word plus a few numbers of position, in a longer vector — is a reasonable one and it is not what is done. Position is summed into the same d numbers. Two consequences follow, and they are worth stating because they sound like objections:

  • No dimensions are spent on position. The vector entering the first layer is d wide, exactly as it would be without positions, so every shape downstream is unchanged. Concatenation would have widened X and therefore every matrix that touches it.
  • Word and position share the space. That looks like it should be destructive — the "meaning" and the "where" are stored in the same numbers — and the answer is that the model is trained with the sum, so it learns representations that survive the sum. The two embedding matrices are learned together, so nothing forces the word part and the position part to interfere where it matters.

It also matters where in the pipeline the addition happens: before the first attention layer, and once. Add position later and it is too late, because the attention scores of the first layer have already been computed from vectors that had no idea where they were.

The alternative, and the one reason to want it

Learned positional embeddings have a specific weakness, and SLP3 names it in one sentence rather than appealing vaguely to generalisation:

SLP3 §8.4

"A potential problem with the simple position embedding approach is that there will be plenty of training examples for the initial positions in our inputs and correspondingly fewer at the outer length limits. These latter embeddings may be poorly trained and may not generalize well during testing."

The argument is a counting argument. Every training sentence has a position 1, so the embedding for position 1 receives a gradient from every example in the corpus. Very few sentences are 4,000 tokens long, so the embedding for position 4,000 is updated by almost nothing and stays close to where it was randomly initialised. The vectors at the far end of Epos are undertrained, and there is no way to fix that by training harder — the data simply is not there.

The alternative is to stop learning the positional vectors and compute them instead, from a fixed function of the position number. Vaswani et al. used a combination of sines and cosines at different frequencies. A static function has no undertrained region: position 4,000 gets the same quality of vector as position 1, whether or not any training sentence was ever that long. That is the whole argument for sinusoids, and it is enough for this course — the formula itself is not on the syllabus. SLP3 adds one more suggestion, that sinusoids "may also help in capturing the inherent relationships among the positions, like the fact that position 4 in an input is more closely related to position 5 than it is to position 17."

A third family exists and is mentioned here only so the name is not new later: relative position methods, which represent the distance between two positions rather than the absolute index of each, and which are usually implemented inside the attention computation at every layer instead of being added once at the input.

Exercise

A four-token sentence, the green witch arrived, and its permutation arrived the witch green. You are told that self-attention as defined in session 29 produces the same set of output vectors for both, which the table above demonstrates.

Answer two things. First: what has to be added to break the tie? Second, and this is the part that matters: where in the pipeline does it have to be added, and why would adding it anywhere later fail?

What. A vector that depends on the position rather than on the token — a row of Epos — added to each token's embedding. After the addition, the vector at position 1 is no longer the same object as the same word at position 3, so the two orderings no longer present the same set of vectors to the mechanism, and the outputs differ. Re-running the table's script with positional embeddings added confirms it: the two output sets are no longer permutations of each other.

Where. At the input, before the first attention layer. The reason is that the attention weights are computed from the vectors as they arrive. If xi carries no position when the first layer runs, then the first layer's scores — and therefore its whole N×N matrix — are already position-free, and the outputs of that layer are already a permuted copy of what they would have been. Adding position to those outputs afterwards labels the result but does not change it; the information about order was needed while the comparisons were being made, not after.

A useful way to say it: position must be in the vectors that get compared, because the only thing the mechanism ever looks at is dot products between vectors.

Question 1 of 2

Why do transformers need positional embeddings at all?

Correct answer: self-attention is permutation-invariant. It sees a set of vectors, and a set has no order — which is exactly what the table of identical outputs shows.

The second option describes a real problem that really does need solving, which is what makes it the tempting wrong answer. Different sentence lengths are handled by padding and masking, and that is a separate mechanism from positional embeddings; a model could pad perfectly and still not know which word came first. The third is false: the weights depend on the tokens through qi⋅kj, and they are generally not uniform — they are just order-blind. The fourth has it backwards. Epos is [N×d], so adding positions adds parameters; the count is fixed by the context length N, not by any individual sentence.

Multi-head attention

Second topic, and it is independent of the first. Everything in session 29 described one attention head. Real transformers run several in parallel, and SLP3 gives the reason:

SLP3 §8.1, Multi-head Attention

"The intuition is that each head might be attending to the context for different purposes: heads might be specialized to represent different linguistic relationships between context elements and the current token, or to look for particular kinds of patterns in the context."

Think about what one head is being asked to do. In session 29's example sentence, resolving what it refers to needs one kind of comparison. Deciding which verb a noun is the subject of needs another. Noticing that a word is inside a quotation needs a third. A single scoring function qi⋅kj has to serve all of these at once, so it must compromise between them — one similarity measure, averaging several purposes together.

Multi-head attention runs A heads side by side, each with its own WiQ, WiK and WiV. Each head runs session 29's equations independently and produces its own output vector; the outputs are then concatenated and passed through a single output projection. In SLP3's numbering, with c indexing the head:

each head has its own three projections qic=xiWcQkjc=xjWcKvjc=xjWcV (8.15)
score, within the head scorec(xi,xj)=qic⋅kjcdk(8.16)

Compare that with session 29's five equations. The first four are the same four, with a c attached — the mechanism has not changed at all. Only the last line is genuinely new: where single-head attention applied WO to one head's output, multi-head first concatenates the A outputs and then applies WO to the concatenation. Each head's output is [1×dv], the concatenation is [1×A⋅dv], and WO is [A⋅dv×d], which brings the result back to [1×d] so the layer can be stacked.

Note what WO is doing now, and why session 29 said it would start to earn its place here. It is the only part of the layer where the heads meet. Inside a head, nothing knows the other heads exist; WO is the learned recipe for mixing their answers back into one vector.

The arithmetic: heads divide the width, they do not add to it

Now the question every student should ask: if eight heads each do what one head did, does the layer cost eight times as much? The answer is no, and the reason is a dimension choice that is easy to read past. SLP3 quotes the original transformer's numbers: d=512, dk=dv=64, A=8 heads.

Look at those three numbers together:

A×dk=8×64=512=d

The heads do not each get a full-width projection. They partition the width. Each head works in a 64-dimensional space, and eight of those spaces side by side come to exactly the model dimension. So the parameters work out like this:

projection matricesparameters
one head at full width (dk=512)3×512×512 786,432
eight heads at width 648×3×512×64786,432
output projection WO512×512262,144
multi-head layer, total1,048,576

The eight heads cost exactly the same as one full-width head — not approximately, exactly, because 8×64=512. The only extra is WO, and it is present in the single-head case too, at a smaller size. Heads are close to free: they divide the width rather than adding to it.

That reframes what the technique is. Multi-head attention is not "more attention". It is the same parameter budget spent on eight narrow comparisons instead of one wide one, and the argument for spending it that way is the quotation above: eight 64-dimensional similarity functions can each specialise, where one 512-dimensional function has to average its purposes together.

It is worth being honest that the specialisation is a hope, not a guarantee. Nothing in the equations tells head 3 to learn coreference. The heads differ only because they start from different random initialisations and are free to diverge, and what they end up doing is an empirical question — in practice some heads do learn recognisable jobs and others are close to redundant.

Question 2 of 2

In the original transformer, do 8 attention heads cost roughly 8 times the parameters of 1 head?

Correct answer: they partition the width. With d=512, dk=64 and A=8, each head's WQ is [512×64] rather than [512×512]. Eight of those come to 786,432 parameters, which is exactly what a single full-width head's three matrices cost. Adding WO brings the layer to 1,048,576 — four thirds of single-head, not eight times.

The first option is the natural guess and it gets the premise right: each head really does have its own three matrices. What it misses is that those matrices are narrower. The second invents a saving that is not the explanation — WO is indeed a single shared matrix, but the projections are where the surprise is. The fourth is wrong about the mechanism: the heads are independent and are computed in parallel, which is a large part of why the design is attractive on modern hardware.

Where this leaves us

T3.6, the self-attention mechanism, is complete across sessions 29 and 30. What the room now has, in full, is the attention layer of a transformer: the input X built from token and positional embeddings, and multi-head scaled dot-product self-attention computed over it.

What is still missing is everything around that layer. SLP3 §8.2 is precise about how much is left: the transformer block is the self-attention layer plus "(1) a feedforward layer, (2) residual connections, and (3) normalizing layers". Of those three, the first is already in hand — it is session 20's feedforward network, unchanged. The other two are new, and they are session 31's, along with the distinction between an encoder block and a decoder block and therefore the proper treatment of the causal mask that sessions 29 and 30 have twice deferred.

The main points

Self-attention is permutation-invariant: it compares vectors pairwise, so shuffling the input produces the same set of outputs, verified above to every digit. Order therefore has to be supplied separately. SLP3 §8.4 builds the input X from two embeddings — a token embedding from E, of shape [|V|×d], and a positional embedding from Epos, of shape [N×d] — which are added, not concatenated, so the input to the first layer is still d wide. It must be added at the input, before any attention weight has been computed. Absolute positional embeddings are learned like any other parameters; their weakness is that the far positions get few training examples and stay undertrained, which is the one reason to prefer a static sinusoidal function instead. Multi-head attention then runs A heads in parallel, each with its own WQ, WK, WV, and concatenates their outputs before a single WO (8.15–8.19). Because A×dk=d — 8×64=512 in the original paper — the heads partition the model width instead of multiplying it, so eight heads cost the same 786,432 projection parameters as one full-width head, and the whole layer is 43 of single-head rather than eight times. Multi-head is the same budget spent on several narrow, specialised comparisons rather than one wide averaged one.
