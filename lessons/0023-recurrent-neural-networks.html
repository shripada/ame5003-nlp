The RNN: hidden state, shared weights

A feedforward layer is a fixed-size hammer; text is not a fixed-size nail. An RNN reuses the same small hammer once per word, carrying a running summary — the hidden state — forward from one word to the next.

The five minutes this session owes you

Session 20's board, back up, nothing re-derived — just the shapes put back in front of the room. A neuron is one weighted sum plus a squashing function:

y = f( Σ wᵢxᵢ + b )

Stack several neurons and it becomes a matrix multiply, z = Wx, one row of W per neuron. Weights are not counted, the way session 16's Naïve Bayes weights were — they start as arbitrary numbers and get fitted, nudged by gradient descent until the whole thing predicts well. That is everything session 20 built, and it is everything this session needs. Nothing else from session 20 is re-taught.

The wall every representation so far has hit

Session 20's feedforward layer needs a fixed-size input vector — the matrix W has a fixed number of columns, and that number cannot change from one input to the next. Every variable-length-text representation this course has built so far dodged that same wall, the same way:

  • CBOW (session 21) averaged the context words down to one vector, whatever the window size.
  • Lab 8, last week, did the same thing to build a document vector from GloVe and Word2Vec — average every word's vector, get one fixed-size vector back.

Both tricks paid the same price, and lab 8 measured it: TF-IDF beat both averaged-embedding representations, decisively. That price is not one problem — it is two:

Two separate problems, not one

Fixed size. A network built for a 10-word input cannot take a 50-word input without redesign.

Order-blindness. Averaging is commutative — avg(a, b, c) = avg(c, b, a), exactly, not approximately. Whatever order the words carried, it is gone before the network ever sees the vector.

The second claim is worth not taking on faith. Real vectors, glove-wiki-gigaword-100 (the same cached file lab 8 used):

avg(GloVe[dog], GloVe[bites], GloVe[man])
avg(GloVe[man], GloVe[bites], GloVe[dog])

cos( · , · )  =  0.9999999999999998
⚠️ Not "close to 1" — mathematically incapable of being anything else

That is not a clean 1.0 — floating-point addition is not perfectly order-invariant, so a+b+c and c+b+a can differ in the last bit. The rounding noise in the seventeenth digit is not evidence that order mattered even a little — it is exactly the precision floating-point arithmetic has to give. The same computation on "the movie was good, not bad" against "the movie was bad, not good" — six identical words, two orders — gives 0.9999999999999999. Averaging does not merely do a poor job of keeping order. It cannot keep order, by construction: it is a sum divided by a count, and addition does not care what order you add in.

The fix: stop trying to see the whole sentence at once

Feed the network one word at a time instead. Give it a hidden state — a vector it carries from step to step — so that word 50 is processed with a summary of words 1–49 already folded in. Nothing about the network's size depends on how long the sentence is, because at every step the network only ever looks at one word plus one hidden state.

One move, both problems

Fixed size stops being a constraint, because the network's input at every step is always "one word vector plus one hidden-state vector" — the same shape whether the sentence is three words or three hundred. Order-blindness stops being automatic, because the hidden state at step t is built from the hidden state at step t−1, which was built from the one before that — a specific, order-dependent chain of updates, not a symmetric sum.

This is the promise session 22 closed on: "the third [problem, blindness to order] is the reason Unit III opens with a model built to process a sequence as a sequence, one step at a time." This is that promise, kept.

The recurrence, stated plainly

Three matrices, new names, same idea as session 20 — a matrix times a vector, added, squashed:

h_t = g( U h_{t-1}  +  W x_t )        the hidden state, updated
y_t = f( V h_t )                       an output, if this step produces one

x_t is the current word's vector. h_{t-1} is everything the network has carried forward so far. W reads the new word; U reads the running memory; V turns the memory into an output, when there is one to produce. g is conventionally tanh here rather than session 20's sigmoid — it squashes into [-1, 1] instead of [0, 1], and the zero-centred range keeps a value that gets fed back into itself, over and over, from drifting all one direction.

Walk the shapes the way session 20 walked Wx + b: if the hidden state is 300-dimensional and each word vector is 100-dimensional, U is 300×300, W is 300×100, and V is whatever the output needs — one row per class, for example.

The session's real payload: the weights do not change

U, W, V are the same three matrices, reused at every timestep. Not three-hundred sets of weights for a three-hundred-word document and three for a three-word sentence — one set, applied again and again. A thousand-word document and a three-word sentence use the identical parameter count. This is the thing session 20's feedforward layer could not do at all — its weight matrix is sized to one fixed input, full stop.

Question 1 of 2

What makes an RNN handle a 3-word sentence and a 300-word document with the same network, without redesigning anything?

Correct answer: the same three matrices are reused at every step.

Nothing about U, W, or V's shape mentions sequence length — they map "one word plus one hidden state" to "one new hidden state," and that mapping is applied once per word, however many words there are. A three-word sentence runs the loop three times; a three-hundred-word document runs it three hundred times; the network being run is identical both times.

By hand, with numbers small enough to track

A tiny synthetic RNN — one-dimensional hidden state, clean integers, no activation function. Real RNNs squash every step with tanh; this toy skips it purely so the arithmetic stays inspectable on the page:

U = 0.5     W = 1     h₀ = 0     x₁ = 2     x₂ = 3

h₁ = U·h₀ + W·x₁ = 0.5·0 + 1·2 = 2
h₂ = U·h₁ + W·x₂ = 0.5·2 + 1·3 = 4

The numbers themselves are forgettable — the structure is the point. Look at h₂'s formula: it contains h₁, which already contained h₀. The chain reaches back indefinitely, in principle — nothing in the formula stops h₁₀₀ from depending, through an unbroken chain, on h₀. Whether it reaches back indefinitely in practice is a different question, and this session is not going to answer it.

Work this out before revealing

Same toy RNN. You are told h₀ = 0, U = 0.5, W = 1, h₁ = 2, and the next input is x₂ = 3. Compute h₂ yourself. Then answer: does h₂'s formula mention h₀ anywhere?

h₂ = U·h₁ + W·x₂ = 0.5·2 + 1·3 = 4.

No — h₂'s formula mentions only h₁ and x₂. h₀ only enters through h₁, one step removed. Every hidden state reaches back only one step at a time, chained — which is exactly the shape of thing that can, in principle, either carry information a long way or lose it a long way. Which one happens is session 24's question.

What comes out the other end

The same architecture supports two different shapes of output, and this session commits to one of them as the running example.

Sequence labeling produces an output at every step — a tag for every word, the way session 6's POS tagging assigns one label per token. One line, no worked example here.

Sequence classification — the direct continuation of lab 8 — produces one output at the very end. Run the whole sequence through, take the final hidden state h_n, and feed it to a separate small feedforward classifier with its own weight matrix, which softmaxes into however many classes the task has:

h_n  =  the hidden state after the last word
ŷ    =  softmax( W_c h_n )        W_c belongs to the classifier, not to the RNN
⚠️ W_c is not V — this is where the diagram stops applying

In a classifier there are no per-step outputs at all: no y₁, no y₂, nothing until the last word has been read. So V — the RNN's hidden→output matrix from the figure above — is simply not used here. The classification head is an extra, separately-sized matrix bolted onto the end, and it has one row per class (two, for positive/negative sentiment), not one row per whatever the RNN's per-step output was. SLP3 draws exactly this in Fig 13.8: an RNN, then a feedforward network hanging off h_n.

SLP3 calls this end-to-end training: the loss comes from the classification decision alone, at the very last step, and backpropagates first through the classifier's own weights, then into h_n, and from there back through the whole chain — every U, every W, all the way to the first word. Nothing is trained to produce a good intermediate representation directly; a good representation is whatever falls out of training the final decision to be correct.

The contrast lab 8 earns

SLP3 §13.3.2 itself offers an alternative to using just h_n: pooling — averaging all the hidden states instead of keeping only the last one. That deserves one careful paragraph, because it sounds like it walks straight back into beat 2's trap.

Pooling RNN hidden states is not lab 8's mistake, wearing a disguise

Lab 8 averaged raw word vectors — context-free, order-blind by construction, exactly the problem beat 2 computed. Pooling RNN hidden states averages h_1, h_2, …, h_n — and every single h_i already encodes everything that came before position i, folded in by the recurrence one step at a time. The order information was built into each vector before the average, not thrown away by it. Averaging is not inherently the enemy. Averaging context-free vectors was lab 8's problem, specifically — and an RNN's hidden states are not context-free.

The same point, computed rather than argued. Push both token orderings from beat 2's example through a hand-rolled, randomly-initialised RNN — untrained, on purpose, because session 24 has not happened yet:

h(dog bites man)  ≠  h(man bites dog)         componentwise, exactly
cos( h(dog bites man), h(man bites dog) )  =  0.138
⚠️ Don't oversell this

An untrained RNN's final hidden state has never been taught to do anything useful with the order it sees — 0.138 is not a meaningful similarity score in any sense a trained model's output would be. The claim here is narrower and does not depend on training at all: the architecture is capable of seeing order; averaging raw vectors is not, a fact about the two functions themselves, independent of what either has been trained to accomplish with that capability. Compare the two cosines side by side — averaging's 0.9999999999999998 against the untrained RNN's 0.138 — and the gap is the whole argument.

Question 2 of 2

Why can lab 8's averaged embeddings not distinguish dog bites man from man bites dog, while even an untrained RNN's final hidden state can?

Correct answer: averaging cannot see order because addition is commutative; the RNN's recurrence is not.

Nothing about training enters into it — an untrained RNN's weights are arbitrary, but the function h_t = g(Uh_{t-1} + Wx_t) still depends on which word arrived at which step, because h_{t-1} feeds into h_t and not the reverse. Averaging has no such asymmetry at all, trained or not — it is mathematically incapable of telling two reorderings apart, which is what beat 2's cosine of 0.9999999999999998 demonstrated directly.

The honest cliffhanger

SLP3 itself claims the recurrent connection can let a decision "depend on information from hundreds of words in the past." State the claim, then question it, then stop:

⚠️ The architecture allows it. Whether it happens is a different question.

This session showed you the architecture allows a decision to depend on information from hundreds of words back — beat 5's toy made the chain visible, link by link, with nothing in the formula that breaks it. Whether that actually happens once you try to train one is next session's entire hour — and the honest answer is not the one the architecture's name promises.

Unit II ended on "blind to order," and this session is the fix. Unit III's first real complication is that the fix has a limit nobody in this room has stated yet.

The whole lesson in four sentences

A feedforward layer needs a fixed-size input, and every trick this course has used to get one — averaging context words, averaging a whole document — is mathematically incapable of seeing word order, because addition is commutative. An RNN instead processes one word at a time, carrying a hidden state h_t = g(Uh_{t-1} + Wx_t) forward, so the same three matrices U, W, V handle a three-word sentence and a three-hundred-word document identically, and the hidden state at any step is a specific, order-dependent function of everything before it. For classification, the final hidden state h_n feeds a softmax, trained end-to-end; pooling all the hidden states is a legitimate alternative precisely because each one already encodes what came before it, unlike lab 8's raw-vector averaging. What this session did not show is whether that "everything before it" reaches back hundreds of words in practice, only that the architecture does not forbid it — that question is session 24's.
