The RNN: hidden state, shared weights

A feedforward layer needs an input of one fixed size, and sentences are not all one size. An RNN runs the same small network once per word instead, carrying a running summary — the hidden state — forward from one word to the next.

Recap: what session 20 established

We begin by restating two results from session 20. Nothing here is re-derived. A neuron computes one weighted sum followed by a squashing function:

y=f(∑iwixi+b)

Stack several neurons and it becomes a matrix multiply, z=Wx, one row of W per neuron. Weights are not counted, the way session 16's Naïve Bayes weights were — they start as arbitrary numbers and get fitted, nudged by gradient descent until the whole thing predicts well. That is everything session 20 built, and it is everything this session needs. Nothing else from session 20 is re-taught.

Why fixed-size input is a problem for text

Session 20's feedforward layer needs a fixed-size input vector — the matrix W has a fixed number of columns, and that number cannot change from one input to the next. Every variable-length-text representation this course has built so far dodged that same wall, the same way:

  • CBOW (session 21) averaged the context words down to one vector, whatever the window size.
  • Lab 8, last week, did the same thing to build a document vector from GloVe and Word2Vec — average every word's vector, get one fixed-size vector back.

Both approaches pay the same price, and lab 8 measured it: TF-IDF outperformed both averaged-embedding representations. That price consists of two separate problems:

Two distinct problems

Fixed size. A network built for a 10-word input cannot take a 50-word input without redesign.

Order-blindness. Averaging is commutative — avg(a,b,c)=avg(c,b,a), exactly, not approximately. Whatever order the words carried, it is gone before the network ever sees the vector.

We can check the second claim directly, using the same glove-wiki-gigaword-100 vectors lab 8 used:

cos⁡(avg(GloVe[dog],GloVe[bites],GloVe[man]), avg(GloVe[man],GloVe[bites],GloVe[dog]))=0.9999999999999998
Why the cosine is not exactly 1.0

That is not a clean 1.0 — floating-point addition is not perfectly order-invariant, so a+b+c and c+b+a can differ in the last bit. The rounding noise in the seventeenth digit is not evidence that order mattered even a little — it is exactly the precision floating-point arithmetic has to give. The same computation on "the movie was good, not bad" against "the movie was bad, not good" — six identical words, two orders — gives 0.9999999999999999. Averaging does not merely do a poor job of keeping order. It cannot keep order, by construction: it is a sum divided by a count, and addition does not care what order you add in.

Processing one word at a time

Feed the network one word at a time instead. Give it a hidden state — a vector it carries from step to step — so that word 50 is processed with a summary of words 1–49 already folded in. Nothing about the network's size depends on how long the sentence is, because at every step the network only ever looks at one word plus one hidden state.

How this addresses both problems

Fixed size stops being a constraint, because the network's input at every step is always "one word vector plus one hidden-state vector" — the same shape whether the sentence is three words or three hundred. Order-blindness stops being automatic, because the hidden state at step t is built from the hidden state at step t−1, which was built from the one before that — a specific, order-dependent chain of updates, not a symmetric sum.

This is the model session 22 pointed forward to, when it noted that blindness to order is the reason Unit III opens with a model built to process a sequence as a sequence, one step at a time.

The recurrence

Three matrices, new names, same idea as session 20 — a matrix times a vector, added, squashed:

ht=g(Uht−1+Wxt)the hidden state, updatedyt=f(Vht)an output, if this step produces one

xt is the current word's vector. ht−1 is everything the network has carried forward so far. W reads the new word; U reads the running memory; V turns the memory into an output, when there is one to produce. g is conventionally tanh⁡ here rather than session 20's sigmoid — it squashes into [−1,1] instead of [0,1], and the zero-centred range keeps a value that gets fed back into itself, over and over, from drifting all one direction.

Walk the shapes the way session 20 walked Wx+b: if the hidden state is 300-dimensional and each word vector is 100-dimensional, U is 300×300, W is 300×100, and V is whatever the output needs — one row per class, for example.

Shared weights: the same matrices at every step

U, W, V are the same three matrices, reused at every timestep. Not three-hundred sets of weights for a three-hundred-word document and three for a three-word sentence — one set, applied again and again. A thousand-word document and a three-word sentence use the identical parameter count. This is the thing session 20's feedforward layer could not do at all — its weight matrix is sized to one fixed input, full stop.

Question 1 of 2

What makes an RNN handle a 3-word sentence and a 300-word document with the same network, without redesigning anything?

Correct answer: the same three matrices are reused at every step.

Nothing about U, W, or V's shape mentions sequence length — they map "one word plus one hidden state" to "one new hidden state," and that mapping is applied once per word, however many words there are. A three-word sentence runs the loop three times; a three-hundred-word document runs it three hundred times; the network being run is identical both times.

A worked example

Consider a very small RNN: a one-dimensional hidden state, integer weights, and no activation function. Real RNNs squash every step with tanh; we omit it here so that the arithmetic can be checked by hand:

U=0.5W=1h0=0x1=2x2=3
h1=Uh0+Wx1=0.5⋅0+1⋅2=2h2=Uh1+Wx2=0.5⋅2+1⋅3=4

The particular values matter less than the structure. Note that h2's formula contains h1, which in turn contained h0. In principle the chain reaches back indefinitely: nothing in the formula prevents h100 from depending on h0 through an unbroken chain of such updates. Whether it does so in practice is a separate question, which we take up in session 24.

Exercise

Same toy RNN. You are told h0=0, U=0.5, W=1, h1=2, and the next input is x2=3. Compute h2 yourself. Then answer: does h2's formula mention h0 anywhere?

h2=Uh1+Wx2=0.5⋅2+1⋅3=4.

No — h2's formula mentions only h1 and x2. h0 only enters through h1, one step removed. Every hidden state reaches back only one step at a time, chained — which is exactly the shape of thing that can, in principle, either carry information a long way or lose it a long way. Which one happens is session 24's question.

Two output shapes: labeling and classification

The same architecture supports two different shapes of output, and this session commits to one of them as the running example.

Sequence labeling produces an output at every step — a tag for every word, the way session 6's POS tagging assigns one label per token. One line, no worked example here.

Sequence classification — the direct continuation of lab 8 — produces one output at the very end. Run the whole sequence through, take the final hidden state hn, and feed it to a separate small feedforward classifier with its own weight matrix, which softmaxes into however many classes the task has:

yˆ=softmax(Wchn)

Here hn is the hidden state after the last word, and Wc belongs to the classifier rather than to the RNN.

Wc is not V: where the figure stops applying

In a classifier there are no per-step outputs at all: no y1, no y2, nothing until the last word has been read. So V — the RNN's hidden→output matrix from the figure above — is simply not used here. The classification head is an extra, separately-sized matrix bolted onto the end, and it has one row per class (two, for positive/negative sentiment), not one row per whatever the RNN's per-step output was. SLP3 draws exactly this in Fig 13.8: an RNN, then a feedforward network hanging off hn.

SLP3 calls this end-to-end training: the loss comes from the classification decision alone, at the very last step, and backpropagates first through the classifier's own weights, then into hn, and from there back through the whole chain — every U, every W, all the way to the first word. Nothing is trained to produce a good intermediate representation directly; a good representation is whatever falls out of training the final decision to be correct.

Pooling the hidden states

SLP3 §13.3.2 itself offers an alternative to using just hn: pooling — averaging all the hidden states instead of keeping only the last one. This deserves care, since at first glance it appears to reintroduce the problem we measured earlier.

Why this differs from averaging raw word vectors

Lab 8 averaged raw word vectors — context-free, order-blind by construction, exactly the problem measured earlier. Pooling RNN hidden states averages h_1, h_2, …, h_n — and every single h_i already encodes everything that came before position i, folded in by the recurrence one step at a time. The order information was built into each vector before the average, not thrown away by it. Averaging is not the problem in itself. Averaging context-free vectors was lab 8's problem, specifically — and an RNN's hidden states are not context-free.

We can verify this by computation rather than argument. Passing both orderings of dog bites man through a randomly initialised RNN — untrained, since we have not yet covered training — gives:

h(dog bites man)≠h(man bites dog)componentwise, exactlycos⁡(h(dog bites man),h(man bites dog))=0.138
What this result does and does not show

An untrained RNN's final hidden state has never been taught to do anything useful with the order it sees — 0.138 is not a meaningful similarity score in any sense a trained model's output would be. The claim here is narrower and does not depend on training at all: the architecture is capable of seeing order; averaging raw vectors is not. That is a fact about the two functions, and holds whether or not either has been trained. The comparison to make is between the two cosines: 0.9999999999999998 for averaging, 0.138 for the untrained RNN.

Question 2 of 2

Why can lab 8's averaged embeddings not distinguish dog bites man from man bites dog, while even an untrained RNN's final hidden state can?

Correct answer: averaging cannot see order because addition is commutative; the RNN's recurrence is not.

Nothing about training enters into it — an untrained RNN's weights are arbitrary, but the function ht=g(Uht−1+Wxt) still depends on which word arrived at which step, because ht−1 feeds into ht and not the reverse. Averaging has no such asymmetry at all, trained or not — it is mathematically incapable of telling two reorderings apart, which is what the cosine of 0.9999999999999998 above demonstrated directly.

An open question: how far back does it reach?

SLP3 states that the recurrent connection can let a decision "depend on information from hundreds of words in the past." We should be careful about what this claim establishes.

What the architecture allows, and what training delivers

What we have shown is that the architecture allows a decision to depend on information from hundreds of words back. The worked example above makes the chain visible link by link, and nothing in the formula breaks it. Whether this dependence survives training is a separate question, and session 24 is devoted to it. The answer is not the one the architecture suggests.

Unit II ended with the problem of order-blindness, and the RNN addresses it. The first complication in Unit III is that this solution has a limit, which we have not yet stated.

Summary

A feedforward layer needs a fixed-size input. Every trick this course has used to get one — averaging context words, averaging a whole document — cannot see word order, because addition is commutative. An RNN reads one word at a time instead, carrying a hidden state ht=g(Uht−1+Wxt) forward. The same three matrices handle a three-word sentence and a three-hundred-word document. At any step, the hidden state depends on everything before it, in order.

For classification, the final hidden state hn feeds a softmax, trained end-to-end. Pooling all the hidden states works too, for a reason lab 8's averaging could not claim: each hidden state already encodes what came before it.

What this session did not show is whether "everything before it" really reaches back hundreds of words. Only that the architecture does not forbid it. That is session 24's question.
