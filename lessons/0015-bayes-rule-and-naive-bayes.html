Bayes' rule and the Naïve Bayes classifier

The question we want to ask cannot be counted. So we turn it into two questions that can — and then tell two deliberate lies to make the second one countable too.

Where lab 1 left off

In lab 1 we applied VADER, a sentiment analyser built from a hand-written lexicon, to several sentences. It handled the difficult cases well, classifying brilliant and terrible correctly and scoring "not bad at all" as mildly positive. It then produced the following:

"this course is going to be a nightmare"   →   0.0   (neutral)

The failure is not subtle, and the reason is straightforward: nightmare does not appear in VADER's 7,502-word lexicon, because nobody added it.

It could be added, but shambles is also missing, as is whatever word comes into use next year. A hand-written list is permanently incomplete, and a human must notice each gap.

What this session adds

Rather than writing the rules, we supply a program with a collection of documents that people have already labelled, marking each review as positive or negative, and let the program determine for itself which words matter.

This is supervised machine learning. It is the first point in this course at which we ask a model to learn a task rather than to compute a definition. The method used here is Naïve Bayes.

The task

Classification is the task of choosing one label from a fixed set, given a document. Our concern here is sentiment analysis, determining whether a review is positive or negative, but the machinery is not specific to sentiment. The same classifier performs spam detection, language identification, and topic labelling without modification.

In practice, "supervised" means that labelled training data is required: a set of documents each marked with the correct answer. This is the cost of not writing rules, and it is a genuine cost, since the documents had to be labelled by someone.

Why we cannot count the answer directly

Written out, the objective is direct: of all the classes, return the one that is most probable given the document.

best class  =  argmax  P(c | d)
                c in C

argmax denotes the argument that maximises the expression, so what we obtain is the class itself rather than the probability. The line reads as: of all the classes, return the one most likely for this document.

We now attempt to estimate this quantity in the way we have estimated everything so far, by counting:

P(positive | "predictable with no fun")

   =   count(that exact document, labelled positive)
       ─────────────────────────────────────────────
       count(that exact document)

The denominator is 1 if that document happens to appear in the training set and 0 otherwise. It will not appear, because it is a new document, which is the entire purpose of a classifier.

The same problem as in session 12

In session 12 the chain rule gave the exact probability of a sentence and was unusable, because the long histories it required almost never recur. The situation here has the same structure. The quantity we want is well defined and cannot be counted, because the thing we would count is unique.

In session 12 the solution was to ask a question with less context. Here the solution is different: we keep the question and change the quantity used to answer it.

Probability: a short refresher

Three terms are needed, since the remainder of the session uses them constantly.

A conditional probability P(A | B) is the probability of A given that B is known to be true. The vertical bar denotes "given".

namewrittenin our problem
priorP(c)how common this class is, before looking at the document
likelihoodP(d | c)how likely this document is, if the class were c
posteriorP(c | d)how likely this class is, now that we have read the document

Prior and posterior mean before and after seeing the evidence. The posterior is the quantity we want and cannot count.

Bayes' rule

Bayes' rule relates the two conditional probabilities that point in opposite directions. In general form:

P(x | y)  =  P(y | x) · P(x)  /  P(y)

Applied to our problem, it turns the posterior into the other three:

                          P(d | c) · P(c)
best class  =  argmax     ───────────────
                c in C          P(d)

Consider what has changed. We wanted P(c | d), the probability of a class given a unique document that has not been seen before. We now require P(d | c) and P(c) instead.

P(c) is easy to estimate: of the labelled documents, what fraction were positive? This is a count over documents, and documents are plentiful. P(d | c) remains difficult, and we address it below. The exchange is nonetheless favourable: one impossible question has been replaced by one easy question and one difficult one.

Why reversing the conditional helps

The reason this works is that the two directions are not equally difficult to count.

The question "how often is this exact document positive?" has no data behind it, since the document is unique. The question "how often does a positive review use the word fun?" has a great deal of data behind it, since thousands of positive reviews exist and many of them contain fun. Bayes' rule allows the first question to be answered using the second.

Dropping the denominator

P(d) is the remaining awkward term, and it can be removed at no cost. We are comparing classes for one fixed document, so whatever P(d) is, it takes the same value in every class being compared and cannot affect which class is largest.

We also do not require an actual probability, only the identity of the winning class. We therefore drop the term:

best class  =  argmax   P(d | c) · P(c)
                c in C

                        likelihood   prior
Reading the formula

This expression has a natural interpretation: to produce a document, first select a class, then produce words appropriate to that class. Classification reverses the process, asking which class most likely produced the observed words.

Because it describes how a document could be generated, Naïve Bayes is called a generative model, and it can in fact be used to generate text, though poorly. The alternative family, discriminative models, omits the generative account and learns only what distinguishes the classes.

Two simplifying assumptions

P(d | c), the probability of a whole document given a class, remains unresolved. A document is a specific sequence of specific words in a specific order, so counting it encounters the same uniqueness problem as before. The difficulty has been relocated rather than solved.

Naïve Bayes proceeds by making two assumptions, both of which are false. This should be stated plainly, since their falseness is what makes them worth examining.

Assumption 1 — bag of words

Position does not matter. Keep which words appeared and how often; throw away the order. The document becomes an unordered bag:

"the film was fun, not boring"      →   {the, film, was, fun, not, boring}
"the film was boring, not fun"      →   {the, film, was, boring, not, fun}

These two reviews have opposite meanings, and the model cannot distinguish them. This is a genuine loss of information, accepted because word identity carries most of the signal for sentiment while word order is expensive to model. We return to bag of words in session 17, where it becomes a method for representing a document as a vector.

Assumption 2 — the naïve assumption

This is the assumption the method is named after. Given the class, the words are independent, so that knowing one word gives no information about the others. This permits the individual probabilities to be multiplied:

P(d | c)  =  P(w₁ | c) · P(w₂ | c) · … · P(wₙ | c)

This is plainly untrue. In a positive review, the presence of special makes effects far more likely than it would otherwise be, and San is almost always followed by Francisco. Words co-occur systematically, and the assumption denies that they do.

The same trade-off, a third time

The pattern is now clear enough to state explicitly:

  • Session 12 — the Markov assumption: only the last word or two matters. False.
  • Now — bag of words: order does not matter. False.
  • Now — the naïve assumption: words are independent. False.

Each of these replaces a quantity we cannot estimate with one we can, and each is adopted knowingly. The test of such an assumption is not whether it is true but whether the model built on it performs well. Naïve Bayes is obviously wrong about language and classifies text effectively. Both statements hold simultaneously, and much of applied machine learning consists of working with assumptions of this kind.

The classifier

Combining the pieces, the entire method is a single expression:

best class  =  argmax   P(c) · Π P(w | c)
                c in C          w in d

Stated in words: for each class, multiply how common that class is by how typical each of the document's words is for that class, and select the class with the highest result.

Two quantities are required, and both are counts over labelled data:

quantitywhat it asks
P(c)what fraction of the training documents are in class c?
P(w | c)of all the words in class c's documents, what fraction are this word?

There is no optimisation, no iteration, and no training loop: we count and divide. This is why Naïve Bayes remains worth studying alongside much larger models. It is the least expensive method that works.

Exercise

We removed P(d) from the formula, although it is a real quantity, namely the probability of that document. Why can it be discarded safely, and what is lost by doing so?

It can be discarded safely because it is identical for every class. We compare P(d|+)P(+)/P(d) against P(d|−)P(−)/P(d) for the same document d, and dividing both by the same number cannot change which is larger. The ranking is unaffected.

What is lost is the scale. The resulting values are no longer probabilities and do not sum to 1; they are scores. We can therefore state that positive outranks negative, but not that the classifier is 70% confident, without restoring the denominator.

The general principle is worth retaining: when only an ordering is required, any factor shared by every item being ranked can be discarded. This situation arises frequently and usually provides the cheapest available simplification.

Question 1 of 2

Why can we not just count P(c | d) from the training data directly?

Correct answer: the exact document is unique, so its count is 0 or 1.

This would require counting how often that precise document appeared with each label, and a new document has never appeared at all. This is the same obstacle as in session 12: the quantity is well defined and has no data behind it. Bayes' rule converts it into questions about individual words, which do have data behind them.

Question 2 of 2

What exactly does the "naïve" assumption claim?

Correct answer: given the class, each word is independent of the others.

This is what permits the individual P(w|c) values to be multiplied together rather than estimating the probability of the whole word combination. It is plainly false, since special and effects are not independent, and the classifier performs well regardless. Note that the separate bag-of-words assumption is the one concerning order.

Summary

The main points

We want the most likely class given the document, a quantity that cannot be counted because the document is unique. Bayes' rule converts it into the likelihood of the document given the class, multiplied by the prior probability of the class, and the denominator drops out because only a ranking is required. That likelihood is still not countable, so two knowingly false assumptions reduce it further: order does not matter, and words are independent. What remains is a classifier consisting only of counting and multiplication.

We now have the formula with no numbers in it. Session 16 trains it on real labelled reviews and uses it to classify one.

One difficulty is already visible. The formula multiplies one P(w | c) for every word in the document, so consider what happens when a word in a new review never appeared in the training documents of that class. The count is zero, the product is zero, and the class is excluded entirely on the evidence of a single word. This is the zero problem from session 13, in a new setting.
