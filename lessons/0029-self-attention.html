Self-attention: query, key, value, and the dk

Session 28's three operations, pointed at one sequence instead of two. The arithmetic barely changes. What changes is that the recurrence is left with nothing to do — and that a set of vectors compared pairwise has no notion of word order at all.

The same mechanism, pointed at one sequence

Session 28 built attention out of three operations: score every encoder state against the decoder's current state, softmax the scores into weights, take the weighted average of the encoder states. Those two sequences were different sequences. A decoder state asked the question and the encoder states answered it.

This session points the identical machinery at one sequence. In self-attention, each position of a sequence attends to the positions of that same sequence, so the thing asking and the thing answering are drawn from the same sentence. SLP3 describes the result as "a way to compute a vector representation for a token at a particular layer of a transformer, by selectively attending to and integrating information from prior tokens at the previous layer."

Nothing in score–softmax–weighted-average changes. What changes is what is being compared to what, and the chapter's opening example shows why that is worth doing:

SLP3 §8.1, on Figure 8.3

The current token is it, in the sentence The chicken didn't cross the road because it was too tired. "The tokens chicken and road both have a high attention weight, meaning that as we are computing the representation for it, we will draw most heavily on the representation for chicken and road. This will be useful in building the final representation for it, since it will end up coreferring with either chicken or road."

This is the same job session 23's recurrence was doing — build a representation of a word that depends on its context — reached a different way. The RNN carried context forward one step at a time through ht. Self-attention fetches it directly, in one operation, from wherever in the sentence it happens to be.

Query, key, value

Three names appear here that session 28 did not need, and SLP3 introduces them as three roles that a single input vector plays during the computation:

SLP3 §8.1.1

"As the current element being compared to the preceding inputs. We'll refer to this role as a query. In its role as a preceding input that is being compared to the current element to determine a similarity weight. We'll refer to this role as a key. And finally, as a value of a preceding element that gets weighted and summed up to compute the output for the current element."

So a query is what a position uses to ask, a key is what a position offers to be matched against, and a value is what a position contributes once it has been matched. Every position plays all three roles in the course of one layer: it is the query when its own output is being computed, and a key and a value when everybody else's is.

Rather than use the raw xi for all three jobs, transformers give each role its own projection. Three weight matrices, learned like any other weights:

qi=xiWQki=xiWKvi=xiWV(8.9)

The shapes are worth having, because they are the first place the three roles visibly differ. WQ and WK are both [d×dk], since a query and a key have to be dot-producted together and therefore must have the same dimensionality. WV is [d×dv], and dv is free — nothing dots a value against anything.

One vector asked to do more than one job — session 25 again

This diagnosis has appeared before in Unit III. Session 25 opened on it: a plain RNN asks ht to be the memory, the output and the input to the next step all at once, and those jobs want different things. The LSTM's answer was to split the vector into a cell state and a hidden state.

Self-attention reaches the same diagnosis about xi and answers it differently: project the vector three ways instead of splitting it. The projections are learned, so the model can decide what a position should advertise as a key and what it should hand over as a value, and these need not be the same thing. Same diagnosis, different repair.

Put the middle three beside session 28's (13.35), (13.36) and (13.37). They are the same three lines, in the same order, doing the same three things. Two differences and no others:

  • The score compares projections instead of raw states. Session 28 dotted hi−1d with hje directly. Here the dot product is between qi and kj, which are xi and xj seen through two different learned matrices. Note what this buys: it is a parameterised score, so it belongs with the bilinear (13.38) rather than with the plain dot product — and in fact qi⋅kj=xiWQ(WK)𝖳xj𝖳, which is (13.38)'s bilinear form with Ws=WQ(WK)𝖳. The three-scoring-functions table at the end of session 28 already had a row for this.
  • The score is divided by dk. That is the next section.

Equation (8.14) is new rather than different: WO reshapes the head's output back to the model dimensionality d, so that xi and ai have the same width and the layer can be stacked on top of another one. It does no attending, and it will matter far more in session 30, where there are several heads whose outputs have to be recombined.

Why (8.12) says ∀j≤i and not ∀j

Chapter 8 develops self-attention for a left-to-right language model, so every equation in it restricts attention to the current position and the ones before it — "when processing xi, the model has access to xi as well as the representations of all the prior tokens in the context window but no tokens after i." The reason is the obvious one: a model being trained to predict the next word must not be allowed to look at it.

That restriction is called causal masking, it is not part of the attention mechanism itself, and session 31 is where it is taught, once encoder blocks and decoder blocks have been separated. Take it for now as a fact about the equations you are reading: the sum runs over j≤i because chapter 8's model is a decoder.

Where the dk comes from

SLP3 gives a reason for the division, and it is a true one, but it is not an answer to the question this session was set. The chapter says the scaling exists because "the result of a dot product can be an arbitrarily large (positive or negative) value, and exponentiating large values can lead to numerical issues and loss of gradients during training", and that we therefore "scale the dot product by a factor related to the size of the embeddings".

That explains why some division is wanted. It does not explain why the divisor is the square root of dk rather than dk, or log⁡dk, or 10. The derivation is in the paper that introduced the transformer, in a footnote, and it is two sentences long:

Vaswani et al. 2017, footnote 4

"To illustrate why the dot products get large, assume that the components of q and k are independent random variables with mean 0 and variance 1. Then their dot product, q⋅k=∑iqiki, has mean 0 and variance dk."

That is the whole argument. A dot product of two dk-dimensional vectors is a sum of dk independent terms; variances of independent terms add, so the variance of the sum grows in proportion to dk. Variance dk means a standard deviation of dk, so the typical size of a score grows like dk — and dividing by dk puts it back to about 1 whatever the dimension. The divisor is the standard deviation of the thing being divided.

The claim is easy to check, and worth checking, since the rest of the section depends on it. Drawing 20,000 pairs of vectors per row with components from a standard normal distribution:

dk=64 is the value used in the original transformer, so the middle row is the case that matters in practice: without the division, scores arriving at the softmax are typically spread over a range of about ±8 instead of ±1. Recall from session 20 what a softmax does with an input spread that wide. Exponentiating puts e8≈2981 against e−8≈0.0003, the largest score takes essentially all of the weight, and every other position is switched off. That is a saturated softmax, and its real cost is the gradient: a weight already at 0.9999 has almost no derivative, so nothing about the scores can be learned any more.

The scaling does not change what the softmax is or what it computes. It keeps its input in the range where it still distinguishes things.

Session 28's objection, settled — and only partly

Last session conceded a real weakness and promised it here. Session 19 established that a raw dot product favours long vectors, which is why cosine similarity divides by both vectors' lengths; equation (13.35) divided by nothing. So the objection was correct, and the promise was that this session would divide.

Be precise about what has actually been fixed, because the two divisions are not the same division. Cosine divides by the actual lengths of the two vectors in front of it. dk divides by the expected scale of a score at this dimensionality — a single constant, identical for every pair in the sequence. It is a fix for scores growing with dimension. It is not a fix for one key vector being longer than another, and a key with a large norm still scores highly against everything. Attention as used in practice is genuinely not normalised in cosine's sense. What keeps that from being fatal is layer normalisation, which appears in session 31 as part of the transformer block, and which acts on the vectors rather than on the scores.

Exercise

Three input vectors in two dimensions, and take all three projection matrices to be the identity — WQ=WK=WV=I — so that qi=ki=vi=xi and every number below can be done by hand:

x1=(1,0)x2=(0,1)x3=(1,1)

Compute the attention weights α2j for the query at position 2, and then the output head2. Here dk=2, so dk=1.4142, and ignore the j≤i restriction — attend over all three positions.

Then answer the part that matters: what happens to those weights if all three input vectors are multiplied by 10?

The weights that survive are 0.5 and 0.5, so all information about how much more relevant they were has been flattened too.

Scaling the inputs by 10 is not something that happens on purpose. Increasing dk is, and by footnote 4 it has the same effect on the scores for the same reason. That is the failure the dk exists to delay — and note the word delay: dividing by a constant slows the growth, it does not abolish it.

What it buys: the recurrence is gone

Sessions 25 and 26 closed on the same limitation, and neither the LSTM nor the GRU could fix it: ht cannot be computed until ht−1 exists, so a sequence must be processed one step at a time. Self-attention has no such dependency. Look again at (8.10)–(8.13): every ai depends only on the xs, and never on any other a. So all n outputs can be computed at once, and §8.3 writes the entire layer as a handful of matrix multiplications. Pack the N input embeddings into a matrix X of shape [N×d], one token per row, and:

equationSLP3 eq.
all projections at once Q=XWQK=XWKV=XWV(8.32)
the whole head head=softmax(mask(QK𝖳/dk))V(8.33)
output projectionA=headWO(8.34)

QK𝖳 is an N×N matrix, and its (i,j) entry is qi⋅kj — every score in the layer, computed in one multiplication. mask is the j≤i restriction from the callout above, now that it has to be done to a whole matrix at once: the upper triangle is set to −∞, which the softmax turns into zero, "thus eliminating any knowledge of words that follow in the sequence". Session 31 will explain when that is wanted and when it is not.

SLP3 gives N for real language models as commonly 1K to 32K tokens. That is the scale at which "one matrix multiply rather than N sequential steps" stops being an aesthetic preference. It is also, unavoidably, an N×N matrix, so the cost is quadratic in the sequence length — which is the price this design pays, and which session 28's teacher notes flagged as arriving here.

The second gain is separate from parallelism and easy to conflate with it. Session 24's subject was that gradient information from token 1 reaches token n through n−1 multiplications by the same matrix, and that Un−1 either vanishes or explodes. In self-attention there is no such product, because there is no chain:

Every position is one dot product away from every other position it is allowed to see, at any distance. Session 24's problem does not get mitigated here in the way the LSTM mitigated it; the structure that caused it is absent. This is the argument that justifies the whole back half of Unit III, and it is why the transformer displaced the recurrent network rather than supplementing it.

Question 1 of 2

What distinguishes self-attention from the attention taught in session 28?

Correct answer: one sequence attending to itself. Both the query and the keys come from the same sentence, which is what the word self is doing in the name.

The first option is worth ruling out carefully, because its conclusion is right and its reasoning is wrong. Self-attention is faster in practice, but it has more parameters, not fewer — WQ, WK, WV and WO are all new. The speed comes from parallelism, not from size: the n sequential steps of a recurrence become one matrix multiply. The third has it backwards; the softmax is still there in (8.11)–(8.12), and the scaling happens inside it. The fourth is a fair guess about a real detail — attention in a transformer does apply to the layer's inputs — but those inputs are the previous layer's outputs once layers are stacked, and nothing here removes any need to train.

What it cost: there is no order

Now the bill. Look at (8.13) again and ask what the output headi is a function of. It is a weighted sum of the values, where the weights come from dot products between pairs. Nothing in that expression refers to where in the sequence anything sits. Shuffle the input tokens, and the same set of pairs produces the same set of dot products, and every output is the same as before — attached to a different position, but otherwise untouched.

So self-attention as defined here treats its input as a set of vectors, not a sequence of them. The chicken crossed the road and the road crossed the chicken are the same object to it. The causal mask conceals this a little, since j≤i at least knows which positions come earlier — but knowing that j precedes i is a long way from knowing that j is three words before i, and the weights themselves are still computed with no reference to distance.

Set that against session 27, which opened by arguing that translation is not word-by-word substitution: the green witch arrived becomes llegó la bruja verde, an alignment of 4, 1, 3, 2, and the whole point was that word order differs between languages and has to be handled. The recurrence handled order for free — it was the one thing an RNN could not fail to represent, because it read the words in order. This session threw the recurrence away, and order went with it.

That is the largest thing self-attention gives up, it was given up in exchange for everything in the previous section, and it has to be repaired rather than tolerated. Session 30 repairs it, by adding a representation of position to the input embeddings, and then returns to the mechanism to run several attention heads in parallel rather than one.

Question 2 of 2

Why is the dot product in equation (8.11) divided by dk?

Correct answer: the variance argument — Vaswani's footnote 4. Variance dk means a typical score of size dk, and at dk=64 that is scores spread over roughly ±8, which the exercise showed is enough to collapse a softmax onto one position.

The second is the likeliest error and the one to be firm about: non-negativity and summing to 1 are the softmax's doing, and they hold whatever the scores are — divided, undivided or multiplied by a thousand. The scaling changes how sharp the distribution is, never whether it is a distribution. The fourth is the near-miss discussed in the warning box above: it describes cosine similarity, which divides by the two vectors' actual lengths, whereas dk is one constant standing for their expected scale. The third invents a problem; WQ and WK differ, but both map into the same dk-dimensional space, which is exactly why the dot product is defined at all.

The main points

Self-attention is session 28's mechanism pointed at a single sequence, so that each position of a sentence attends to positions of that same sentence. Each input vector is projected into three roles by three learned matrices — a query for asking, a key for being matched against, a value for being contributed (8.9) — which is the same "one vector, several jobs" diagnosis that motivated the LSTM in session 25, repaired by projection instead of by splitting. The layer is then five equations (8.10–8.14), of which the middle three are session 28's three unchanged: score, softmax, weighted average. The score is scaled by dk because the dot product of two dk-dimensional vectors has variance dk — Vaswani's footnote 4, verified by simulation at dk = 8, 64 and 512 — so without the division the softmax saturates as the dimension grows and the gradients disappear. This is not cosine's normalisation: it divides by the expected scale of a score, not by the actual lengths of the vectors. Because no output depends on any other output, the whole layer packs into three matrix operations (8.32–8.34), n sequential steps become one multiply, and any two positions are one dot product apart rather than n−1 — which is session 24's vanishing-gradient problem removed rather than mitigated. The cost is quadratic in sequence length, and worse, a set of vectors compared pairwise carries no word order at all. Session 30 puts order back.
