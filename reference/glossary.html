NLP Glossary

Every term used in this course, in one place. Once a word is defined here, every lesson uses it to mean exactly this.

How to use this

Keep it open while you work. NLP is full of near-synonyms that mean subtly different things — type vs token, lemma vs stem — and it is hard to ask a good question about something you cannot name.

Terms marked like this are the ones that are easy to mix up. They are also the ones examiners like asking about. If you only revise part of this page, revise those.

Text and patterns — sessions 1–3

Ambiguity
The same words having more than one valid reading — "The old man the boat." You resolve it with world knowledge, instantly and without noticing. A computer has none. Nearly every technique in this course is a way of coping with it. Session 1
Information extraction
Pulling structured facts — dates, amounts, IDs, names — out of text that was not written to be structured. The syllabus name for what sessions 1–2 and Lab 2 do. Regex is the oldest tool for it and often still the best. Session 1 · T1.1
Regular expression regex
A small language for describing the shape of text, so a program can find every piece that has that shape. Describes shape, never meaning: it cannot tell you whether a review is positive. Sessions 1–2 · SLP3 §2.6
Character class [...]
"Any one character from this set." [Cc]at matches either spelling; [0-9] is a range. A leading ^ inside the brackets inverts it: [^0-9] is "any one non-digit". Session 1
Quantifier * + ? {n,m}
How many times the thing before it may repeat: zero or more, one or more, optional, or a counted range. It attaches to the one item immediately before it — which is why colo*r does not match colour. Session 1
Escaping \
A backslash before a character that would otherwise be special, so it is treated literally: \+ for a real plus sign, \. for a real full stop. Forgetting it is the most common regex bug there is. Session 1
Greedy vs. lazy
Greedy (the default) takes as much as it can, giving characters back only if the rest of the pattern cannot otherwise match — so <.*> swallows a whole line of HTML. Lazy (*?, +?) takes as little as possible. When a match is far bigger than you expected, this is almost always why. Better still, write a pattern that cannot overshoot: <[^>]*>. Session 2
Capture group ( )
Round brackets that make the engine remember what matched inside them, so you can pull the pieces out separately. Numbered left to right by opening bracket; group 0 is the whole match. Trap: once a pattern has groups, findall returns the groups instead of the whole match. Session 2
Non-capturing group (?:...)
Brackets used only to hold a pattern together — for alternation, or to attach a quantifier — without capturing anything. Use it when you want the grouping but not the extra value in your results. Session 2
Named group (?P<name>...)
A capture group with a name, read back as m.group("date") instead of m.group(2). Worth the extra characters: it still reads correctly six months later, and it does not break when you add a field in the middle. .groupdict() returns them all at once. Session 2
Word boundary \b
A zero-width position — not a character — at the edge of a run of word characters. \bcat\b refuses to match inside concatenate but still matches cat., because a full stop is not a word character. Our first, crude answer to "where does a word end?" Session 2
Combining mark \p{M}
A character that attaches to the one before it rather than standing alone — a vowel sign, or the Kannada virama (U+0CCD) that joins two consonants. Python's built-in re excludes marks from \w, so it splits Indic words at the virama: re.findall(r"\w+", "ಕನ್ನಡ ಭಾಷೆ") finds four words where there are two, and \b inherits the same error. This course uses the regex library, which gets it right. Note that \p{L} alone is not the fix — letters only; you need [\p{L}\p{M}]+ or \w. Sessions 1–2, 4 · SLP3 §2.3

The basics — used from week 1, taught properly from week 7

Model
A program that learned its behaviour from examples rather than from rules someone wrote. Opposite of a regex, where you type the rule out yourself. Keeps a set of numbers for each word it knows, and adjusts them while learning. Built properly from session 20. Gentle intro.
Training
Showing a model examples so it can work the patterns out. Done once, in advance. Contrast inference: using the finished model on something new.
Parameters
The numbers inside a model that training adjusts. "A bigger model" means more of these.
Rules vs. learning
The spine of this whole course. Rules: a person writes down what to do — regex (weeks 1–2), VADER's word list (lab 1). Precise, fast, and someone must think of every case. Learning: show examples, the machine works it out — Naïve Bayes (week 6) onward. Handles cases nobody listed, needs data and gives no guarantees. Nearly every "why do we still teach the old way?" question is answered by this row.
Vocabulary
The fixed list of every token a model knows. Decided before training and frozen. One row of parameters per entry, so vocabulary size drives model size. Anything not in it becomes <UNK> — which is the problem subword tokenization exists to solve.

Unit I — Text processing & IR

Corpus pl. corpora
A body of text used for training or evaluation.
Type vs. Token
A token is an instance; a type is a distinct entry in the vocabulary. "the cat sat on the mat" = 6 tokens, 5 types ("the" repeats). Vocabulary size means types. expect this in the exam
Tokenization
Splitting raw text into tokens. Not a string operation — a modelling decision. See Lesson 03.
Rule-based tokenizer Penn Treebank
Word tokenization done with a hand-written set of regular expressions, patiently grown until it handles ordinary English: keeps Dr. and U.S.A. intact, splits isn't into is + n't, makes punctuation its own token. The Penn Treebank rules are the best-known set; nltk.word_tokenize and spaCy's tokenizer are the ones you call. Solves the punctuation problem, not the vocabulary problem. Session 3 · SLP3 §2.8
Normalization
Collapsing surface variants to one form: case-folding, Unicode normalization, U.S.A. → USA. Deliberately destroys information you judge irrelevant.
Stemming vs. Lemmatization
Stemming chops affixes by rule — fast, crude, output need not be a real word (studies → studi). Lemmatization maps to the dictionary headword using morphology + POS — slower, correct (studies → study, better → good). the easiest pair in Unit I to mix up
Lemma
The dictionary/citation form. run is the lemma of ran, running, runs.
Stop words
High-frequency, low-content words (the, is, of) often removed. Note: harmful for tasks where they matter — "to be or not to be" is entirely stop words.
Subword tokenization
Units smaller than words, so unseen words decompose instead of becoming <UNK>. See BPE.
BPE Byte-Pair Encoding
Learns subword units by repeatedly merging the most frequent adjacent symbol pair. Merge count k sets vocabulary size. Origin: a 1994 compression algorithm.
WordPiece
BPE variant used by BERT: merges the pair that most increases training-data likelihood, not the most frequent one. The ## prefix marks "continues previous word".
<UNK>
The out-of-vocabulary catch-all token. Its existence is the problem subword tokenization solves.
POS tagging Part-of-Speech
Labelling each token with its grammatical category (noun, verb…). A sequence-labelling task.
NER Named Entity Recognition
Finding and typing proper-name spans (PERSON, ORG, LOC). Span-based, so harder than POS: entities cover multiple tokens.
Term-document incidence matrix
Binary matrix, terms × documents: 1 if term occurs in doc. Conceptually clean, hopelessly sparse at scale — which motivates the inverted index.
Inverted index
Maps each term → postings list of documents containing it. "Inverted" because the natural direction is doc → terms. The data structure behind every search engine.
Postings list
The list of doc IDs for one term, kept sorted so queries can be answered by merging lists.

Unit II — LM, sentiment, embeddings

Language model LM
Assigns probability to a token sequence — equivalently, predicts the next token.
N-gram
A contiguous run of n tokens. An n-gram LM applies the Markov assumption: only the previous n−1 tokens matter.
Chain rule
Breaks the probability of a whole sequence into a product of next-token probabilities, each conditioned on everything before it. Exact — but the long histories it needs are almost never seen often enough to count. Still how an LLM factorises a sequence.
Markov assumption
Only the last few tokens matter; the rest of the history is discarded. Knowingly false — language has long-range dependencies — but it turns the chain rule's uncountable histories into countable ones. Compare the "naïve" assumption: both are simplifications adopted because the honest version cannot be estimated.
MLE Maximum Likelihood Estimate
For n-grams: P(w|context) = count(context,w) / count(context). Just counting and dividing — and it assigns probability zero to anything unseen, which is why smoothing exists.
Smoothing
Moving probability mass to unseen n-grams so nothing is impossible. Laplace/add-one is the teaching example; Kneser-Ney is the good one. The total stays 1, so whatever the unseen gain, the seen lose.
Backoff
When an n-gram has a zero count, drop to the (n−1)-gram and try again, repeating until something has been seen. Unlike add-one, the fallback still carries evidence — a common word gets more than a rare one.
Interpolation
Always blend trigram, bigram and unigram estimates with weights λ summing to 1, rather than waiting for a zero. The unigram term is never zero, so the mix never is either. λ is tuned on a held-out set, not on the training data.
Intrinsic vs. extrinsic evaluation
Extrinsic — put the model inside a real application and measure the application. The only evaluation that answers the question you care about, and usually too expensive to run often. Intrinsic — score the model on its own, no application attached. Perplexity is the standard intrinsic metric for LMs. A gain in one does not guarantee a gain in the other.
Training / development / test set
Three disjoint slices of the data. Training gives the counts. Development (devset) is where you compare models and tune hyperparameters such as λ or k — a held-out set is this. Test is opened once, at the end, for the number you report.
Training on the test set data contamination
Test text leaking into the training corpus. Does not produce an obvious error — it produces a flatteringly good result, so it is invisible unless you look for it. Suspiciously low perplexity is the usual symptom.
Perplexity PP
Standard intrinsic LM metric: the inverse probability of the test set, normalised by token count — PP(W) = P(W)−1/N, where N counts predicted tokens (includes </s>, excludes <s>). Equivalently 2cross-entropy, the log form the textbook uses — same quantity; logs are taught in session 16. Intuition: the model's average branching factor. Lower is better — easy to get backwards, so check yourself. Only comparable across models with identical vocabularies, on the same test set. Infinite for an unsmoothed model, since one unseen n-gram makes P(W) = 0.
Supervised classification
Learn to map a document to one label from a fixed set, using training documents a human has already labelled. The alternative to writing rules by hand — and the cost is the labelling.
Prior · likelihood · posterior
Prior P(c) — how common the class is before reading anything. Likelihood P(d|c) — how likely this document is if the class were c. Posterior P(c|d) — how likely the class is now the document is read. The posterior is what you want and cannot count; the other two are what you can. The thing before the bar is what you are asking about — read them backwards and the whole topic collapses.
Bayes' rule
P(x|y) = P(y|x)·P(x) / P(y) — flips a conditional probability round. Useful exactly when one direction has data behind it and the other does not. For classification the denominator drops out, since it is identical for every class and only the ranking is needed — which is also why the outputs are scores, not probabilities.
Generative vs. discriminative
Generative (Naïve Bayes) models how a class would produce a document, then asks which class most likely produced this one. Discriminative (logistic regression) skips the story and learns only what separates the classes. Discriminative is usually more accurate; generative is cheaper and needs less data.
Naïve Bayes
Generative classifier applying Bayes' rule with a conditional-independence assumption across features. Training is counting and dividing — no optimisation, no iteration. SLP3 Appendix B — not ch 4
The "naïve" assumption
That features (words) are conditionally independent given the class. It is false for language — and the classifier works well anyway. Being able to say why a known-false assumption still works is the whole point of the topic. Not the same as bag of words, which Naïve Bayes assumes separately: bag of words is about order, this is about dependence.
Log space underflow
Multiplying hundreds of small probabilities gives exactly zero in ordinary floating point (0.01200 is 0.0, not "very small"). So add logs instead of multiplying: log(a·b) = log a + log b. The winner never changes, because log is monotonic. Base is irrelevant — it scales everything by a constant. Costs you the readable scale: log scores are not probabilities.
Precision
Of the items the classifier labelled as class c, what fraction really were c. High precision means few false alarms for that class. Lab 6 · enrichment
Recall
Of the items that really are class c, what fraction the classifier found. High recall means few missed cases for that class. Precision and recall pull against each other — a single accuracy number can hide that trade-off. Lab 6 · enrichment
F1
The harmonic mean of precision and recall for a class: 2 · precision · recall / (precision + recall). One number when you need one; still per-class, so it does not replace looking at both. Lab 6 · enrichment
Confusion matrix
A table of true class against predicted class. The diagonal is correct; off-diagonal cells are the specific mistakes. Precision and recall are just ratios of those cells — the matrix is the primary object, the report is a summary. Lab 6 · enrichment
BoW Bag of Words
Represent a document by word counts, discarding order. "Dog bites man" = "man bites dog". The loss is permanent — nothing downstream can recover an order destroyed at representation time. Accepted because word identity carries most of the signal and order costs far more than it repays.
Vector space model
Treat each document as a point in a space with one dimension per vocabulary word. Documents close together use words in similar proportions, so they are about similar things — meaning becomes position. The move that makes similarity, search and clustering possible; a term-document matrix read as geometry rather than as a lookup table. SLP3 §11.1 — not ch 5
Document vector vs. word vector
In a term-document matrix, a column is a document (placed by the words it uses) and a row is a word (placed by the documents it appears in). Both are vectors; they are the two ways of reading one table. Word vectors are the seed of embeddings.
TF-IDF
Weight = term frequency × inverse document frequency. TF rewards words frequent in this doc; IDF (a log ratio) penalises words common across all docs. Together: words that are distinctive here. Know why there is a log in IDF: it damps the effect, so being rare helps, but less and less as a word gets rarer. A word in every document has idf log(N/N) = 0 exactly, so its weight is zero no matter how often it occurs. IDF is a property of the collection, not of the document — score the same text against a different collection and every weight changes. A word can be highly distinctive in one collection and worthless in another: fool separates comedies from histories in general, and is near-useless across Shakespeare's 37 plays because he uses it in 36 of them.
Cosine similarity
Similarity as the cosine of the angle between vectors: (a·b) / (|a||b|) — the dot product over the product of magnitudes. Easiest read: shrink both vectors to length 1 (unit vectors), then take their dot product — so it compares direction and throws length away. A document and the same document printed twice score exactly 1. For count, tf or tf-idf vectors the range is 0 to 1, because counts are never negative and such vectors can be at most 90° apart; for embeddings, which do have negative components, the formula's range is the full −1 to 1 — though measured on real Word2Vec vectors (session 21) the cosines bottom out near −0.3, sit at a median of about +0.06, and only 17% are negative at all. Read a cosine against the spread its own representation produces: 0.3 is weak for count vectors and unusually high for embeddings. It fixes a length problem, not a feature problem — uninformative features stay uninformative however you measure the angle. Session 19.
Neuron unit
A weighted sum of inputs, plus a bias, pushed through one non-linear function: y = f(Σ wᵢxᵢ + b). That is the whole object. Naïve Bayes in log space is already the same shape — log P(c) + Σ log P(w|c) — the difference being that its weights are counted while a neuron's are fitted. Stack neurons side by side and the sums become one matrix multiply, f(Wx + b), which is a layer. Session 20.
Activation function sigmoid · ReLU
The non-linear f in a neuron. Sigmoid σ(z) = 1/(1 + e−z) squashes any number into (0, 1), so it reads as a probability — Word2Vec's negative sampling scores a pair as σ(u·v). ReLU max(0, z) is the modern default from Unit III on. It is not optional if you want depth: without it, W₂(W₁x) = (W₂W₁)x and a stack of layers collapses into one. ⚠️ That argument is about depth, not about every model — Word2Vec is deliberately shallow and has no hidden non-linearity at all. Session 20.
Softmax
Turns any list of scores into a probability distribution: softmax(z)ᵢ = e^(zᵢ) / Σⱼ e^(zⱼ). Exponentiate, then divide by the total, so everything comes out positive and sums to 1 — unlike ordinary normalisation it accepts negative inputs and arbitrary scales, which is why it can sit on top of a layer. The exponential exaggerates gaps: a lead of 2 in score is always a ratio of e² ≈ 7.4 in probability. Used wherever a model must pick one item out of many — in Word2Vec, one word out of the whole vocabulary, which is expensive enough that negative sampling exists to avoid it. Session 20.
Loss function cross-entropy
The number a model is trained to make smaller. For a single prediction, cross-entropy loss is −log(probability the model gave the correct answer) — near 0 for a confident correct answer, large for a confident wrong one, infinite for a probability of 0. Not new: session 14's perplexity is the exponentiated average of exactly this, so minimising cross-entropy and minimising perplexity are the same act. Session 20.
Gradient descent learning rate · backpropagation
How weights get fitted. The gradient says which way is uphill on the loss, so step the other way and repeat: w ← w − η·gradient, where η is the learning rate — how big a step. Steps shrink automatically near a minimum, because the gradient is the steepness. Backpropagation is just the chain rule applied systematically, working backwards from the loss, to get that gradient for every weight in the network. Session 20.
Embedding matrix the vectors are the weights
The |V| × d weight matrix whose rows are the word vectors — 10,000 × 300 in a typical Word2Vec. The trap is expecting the vectors to be extracted from a trained model: there is no such step. The matrix is a layer's weights, fitted by the same gradient descent as everything else, and when training stops you throw the rest of the network away and keep it. The word vectors were the model. Sessions 20–21.
Sparse vs. Dense vectors
Sparse (BoW, TF-IDF): dimension = vocabulary size, mostly zeros, each dimension is an interpretable word. Dense (Word2Vec, GloVe): a few hundred dimensions, all non-zero, individually uninterpretable. The move from sparse to dense is the central arc of Unit II.
Distributional hypothesis
"You shall know a word by the company it keeps" (Firth, 1957). Words in similar contexts have similar meanings. The premise every embedding method rests on. Sessions up to 19 counted the company (bag-of-words, TF-IDF); Word2Vec predicts it instead and keeps the weights; GloVe counts it globally — the whole corpus's co-occurrences at once, rather than one window — and fits vectors to the counts directly. All three rest on the same premise; they differ in how they get from "company" to numbers. ⚠️ The hypothesis is honest about its limits: antonyms appear in nearly identical contexts, so good and bad come out with a high cosine in both Word2Vec (0.719, rank 2) and GloVe (0.645, present but outside the top 10 — the two released vector sets disagree at the margins, not on the underlying effect). Distribution is not meaning.
Embedding
A learned dense vector for a word/token. A lookup table — vocabulary × dimensions — trained by gradient descent, not hand-built. ⚠️ Note what it does not fix: a word absent from the training vocabulary has no vector at all, so session 3's OOV problem survives intact; and each word gets exactly one vector, so bank carries the river and the money sense blended together. Both limits hold for GloVe as much as Word2Vec — neither is fixed by switching which one counts or predicts. Unit III's contextual embeddings exist to fix the second. Sessions 20–22.
Self-supervised learning
Training on labels manufactured from the input itself, so no human labelling is needed. Word2Vec's is the plainest example: delete a word from a sentence, ask the model to name it, and the deleted word is the label. Contrast session 16's sentiment classifier, which needed 2,000 reviews a person had read and tagged. This is why the approach took over — not that it is cleverer, but that every sentence ever written becomes training data. Every large language model in Unit III is pre-trained this way. Session 21.
Word2Vec's two vectors per word
During training each word has two: an input vector v_w (row w of E), used when the word appears as context, and an output vector u_w (row w of W'), used when it is the thing being predicted. A word's score is u_w · x. When training stops, W' is thrown away and the rows of E are the word vectors everybody downloads. Trips almost everyone the first time. Session 21.
CBOW vs. Skip-gram
The two Word2Vec architectures, and they are mirror images. CBOW: context → predict the centre word. Skip-gram: centre word → predict the context. Skip-gram is slower, better on rare words. Expect this in the exam — and check yourself, because the two are very easy to flip.
The reason for the trade-off: from one window position CBOW builds one training example (average the context, predict the centre) while Skip-gram builds one per context word — four times the signal from the same text, which is what rare words need. Both throw word order away. Neither is a language model: they score one position, never a sequence. Session 21.
Negative sampling
Word2Vec's efficiency trick: rather than a softmax over the whole vocabulary, discriminate the true context word from a handful of random "negative" words. Turns an impossible normalization into cheap binary classification.
The cost it removes is the denominator: softmax must score every word you know just to normalise one prediction — 10⁶ exponentials per training example on a realistic vocabulary, about 10¹⁵ per pass over a billion tokens. Negative sampling scores the true pair as σ(u·v) and k invented pairs as σ(−u·v): six sigmoids instead of a million exponentials, roughly 167,000× less arithmetic. Negatives are drawn from the unigram distribution raised to the power 3/4. Session 21.
GloVe Global Vectors
Fits vectors so wᵢᵀw̃ⱼ + bᵢ + b̃ⱼ ≈ log Xᵢⱼ, where X is the global word-word co-occurrence matrix counted once over the whole corpus. No hidden layer, no softmax, no prediction step — closer to matrix factorisation than to Word2Vec's neural network. The log matters because a difference of two such fits recovers a ratio of co-occurrence probabilities, which the paper argues is the informative quantity (its own ice/ steam/solid/gas/water table makes the case). Like Word2Vec, trains two vectors per word and — unlike Word2Vec — sums them rather than discarding one.
⚠️ The trap: "global counts beat local prediction" is GloVe's own marketing, not a settled result. Levy & Goldberg (2014) showed Skip-gram-with-negative-sampling implicitly factorises a shifted PMI matrix — i.e. it was using global statistics all along — and Levy, Goldberg & Dagan (2015) found matched hyperparameters close most of the gap between count-based and prediction-based methods. Real vectors from both bear this out: nearest-neighbour tables for movie, terrible, battle, king agree closely between GoogleNews Word2Vec and glove-wiki-gigaword-300. Session 22.

Unit III — Deep learning

RNN Recurrent Neural Network
Processes a sequence one step at a time, carrying a hidden state: h_t = g(Uh_{t-1} + Wx_t), with g conventionally tanh. U, W and a third matrix V (hidden→output, y_t = f(Vh_t)) are the same three matrices at every timestep — a thousand-word document and a three-word sentence use identical parameter count. Fixes the fixed-size-input wall that forced CBOW and lab 8's document vectors to average, and — unlike averaging — the hidden state is a specific, order-dependent function of everything before it. For sequence classification, the final h_n feeds a softmax, trained end-to-end; for sequence labeling (POS tagging), every step produces its own output. Session 23.
Hidden state
The vector an RNN carries forward — its compressed memory of everything seen so far, updated at every step by h_t = g(Uh_{t-1} + Wx_t). Because each h_t is built from h_{t-1} rather than from a symmetric sum, pooling (averaging) a sequence's hidden states is not the same mistake as averaging raw word vectors — order was already folded into each h_t before the average, not thrown away by it. Session 23.
Vanishing gradient
Training an RNN sends one loss backward through every timestep, and each step multiplies the gradient by the same matrix U. For the linear toy h_t = Uh_{t-1} + Wx_t that is exactly ∂h_n/∂h₁ = U^(n−1): with U = 0.5, twenty steps back gives 0.0000019 — not a weak learning signal but none. With |U| > 1 the same formula explodes instead (U = 1.5, fifty steps → 4.25×10⁸), so the failure runs both ways and only |U| = 1 sits still. A real RNN's tanh′ ≤ 1 adds one more factor per step, which makes vanishing worse and never explains exploding.
⚠️ This is only half of why long-range memory fails, and the half that matters less for what comes next. SLP3 names another: one hidden state is asked to serve the current decision and carry information for future ones, with nothing separating the two jobs. The LSTM is the fix for that problem — an explicit context layer with learned control over what is kept and forgotten — and it helps the gradient as a side effect, by making the path additive rather than multiplicative. Remember it as a gradient trick and its design looks arbitrary. Sessions 23–24; the fix is session 25.
LSTM Long Short-Term Memory
RNN with a cell state and gates (forget, input, output). The cell state's additive path lets gradients survive.
GRU Gated Recurrent Unit
Simplified LSTM: two gates (reset, update), no separate cell state. Fewer parameters, usually comparable performance.
Seq2seq encoder–decoder
Encoder reads input into a representation; decoder generates output. Enables mismatched input/output lengths — hence machine translation.
Bottleneck problem
Vanilla seq2seq crushes the whole input into one fixed vector. The motivation for attention. Understand this problem first, or attention looks like it came from nowhere.
Attention
Lets the decoder look back at all encoder states, weighted by relevance, instead of one summary vector. Originally Bahdanau et al., 2014 — pre-dates transformers.
Attention vs. Self-attention
Attention (cross-): decoder attends to encoder — two sequences. Self-attention: a sequence attends to itself, each token gathering from every other — one sequence. The transformer's core is self-attention. Keep them apart in your head.
Q, K, V query, key, value
Three projections of each token. Query matches against keys to produce weights; weights pool the values. A soft, differentiable dictionary lookup.
Scaled dot-product attention
softmax(QKᵀ / √dk)V. Know what the √dk is for: without it, dot products grow with dimension, pushing softmax into saturation, where gradients vanish.
Multi-head attention
Several attention operations in parallel on split projections, concatenated. Lets different heads attend to different relation types at once.
Positional encoding
Self-attention is permutation-invariant — it cannot see order — so position must be injected explicitly. Ask the class why an RNN needs no such thing.
Transformer
Architecture built from self-attention + feed-forward blocks, no recurrence. Parallelises across the sequence, which is why it won. Vaswani et al., 2017.
Encoder-only vs. Decoder-only
Encoder-only (BERT): bidirectional, sees the whole sequence, for understanding — classification, NER. Decoder-only (GPT): causally masked, cannot see the future, for generation. If you are asked "what is the difference between BERT and GPT?", this row is the answer.
MLM Masked Language Modelling
BERT's pre-training task: mask ~15% of tokens, predict them from both sides. Bidirectional context is only possible because the task is fill-in-the-blank, not next-token.
Pre-training vs. Fine-tuning
Pre-training: expensive, once, self-supervised on unlabelled text. Fine-tuning: cheap, per-task, supervised on a small labelled set. The economics of this split is why modern NLP is accessible to your students at all.
DistilBERT
BERT compressed by knowledge distillation — a small "student" trained to imitate the large "teacher". ~40% smaller, ~60% faster, ~97% of performance. Named in your syllabus (spelled "DitilBERT" — a typo).
Transfer learning
Reusing representations learned on one task for another. The umbrella that pre-train → fine-tune sits under.
